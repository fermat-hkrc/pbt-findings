## Summary

`HexString2Byte(hex, buf, len)` decodes a hex string into a byte buffer. It takes
a length only for the **output** buffer; the source extent is implicit and
unchecked. `Hex2byte` reads `ipos[0]`/`ipos[1]` with no null check and no source
bound, so three defects follow:

1. **OOB read when `hex` is not a C string** — a mapped buffer of exactly 2 digits
   with `len=2` (needs 4) reads past the end into `PROT_NONE` → SIGSEGV
   (guard-page witness).
2. **Null `hex` → crash** — `Hex2byte` dereferences `*hex++` on null → signal 11.
3. **Null `buf` → crash** (when `len > 0`) — `*opos++ = a` on null → signal 11.

The sibling encoder `Byte2HexString` (same file) **already** null-checks both
pointers and verifies `hexstrLen >= bytesLen * 2`; the decoder is missing the
symmetric guards. Header `wifi_common_util.h:374` is a bare declaration with no
`@param` contract for null or source length.

Current production callers (4 sites in `sta_state_machine.cpp`, SIM/AKA GSM/UMTS
auth) all zero-initialize a one-past-max stack buffer and copy with `strncpy_s`,
so a truncated network challenge fails closed via `Hex2num('\0') == -1` today —
**not** a demonstrated field crash. Still worth fixing: public util, no
documented contract, used on the SIM/AKA path, and the next caller passing a
non-terminated slice / too-small buffer / null pointer gets UB.

Confirmed and fixed under `DTS2026071806709`.

## Vulnerable Code

`wifi/utils/src/wifi_common_util.cpp` (`HexString2Byte`, ~line 690):

```cpp
int HexString2Byte(const char *hex, uint8_t *buf, size_t len)
{
    size_t i;
    int a;
    const char *ipos = hex;
    uint8_t *opos = buf;

    for (i = 0; i < len; i++) {
        a = Hex2byte(ipos);   // reads ipos[0], ipos[1]; no null / length check
        if (a < 0) {
            return -1;
        }
        *opos++ = a;
        ipos += 2;
    }
    return 0;
}
```

`Hex2byte` (~677) does `Hex2num(*hex++)` twice with no null check — the null-`hex`
crash site. Header (`wifi/utils/inc/wifi_common_util.h:374`) is a bare
declaration:

```cpp
int HexString2Byte(const char *hex, uint8_t *buf, size_t len);
```

Sibling `Byte2HexString` (same file, ~708) **does** null-check both pointers and
verify `hexstrLen >= bytesLen * 2`. The decoder is missing the symmetric guards.

### Why short C strings look "fine"

For NUL-terminated input shorter than `2 * len`, the next unread byte is often
`'\0'`, `Hex2num('\0') == -1`, and the function returns `-1`. That is accidental
fail-closed behavior, not an explicit source bound. It does **not** make
non-terminated or undersized storage safe (guard-page witness proves it).

## Trigger Conditions

1. **OOB read:** `hex` points to non-NUL-terminated storage with fewer than
   `2 * len` readable bytes → `Hex2byte` reads past the end → SIGSEGV (guard
   page) or silent over-read.
2. **Null `hex`:** caller passes `nullptr` → `Hex2byte` dereferences null →
   signal 11.
3. **Null `buf`** (with `len > 0`): caller passes `nullptr` → `*opos++` writes
   null → signal 11.

## Call sites (production)

Only four call sites, all in
`wifi/services/.../wifi_sta/sta_state_machine.cpp`:

| Line | Caller | Pattern |
|------|--------|---------|
| 5990 | `GetGsmAuthResponseWithLength` | zero-init `char tmpRand[MAX_RAND_STR_LEN+1]` + `strncpy_s` + `HexString2Byte(..., sizeof(randArray))` |
| 6088 | `GetGsmAuthResponseWithoutLength` | same |
| 6170 | `FillUmtsAuthReq` (`rand`) | same |
| 6191 | `FillUmtsAuthReq` (`autn`) | same |

Every site zero-initializes a one-past-max stack buffer and copies with
`strncpy_s`, then checks `ret != 0` and aborts the auth path. So a
truncated/malformed network challenge today yields `-1` and an empty auth
request — **not** a stack OOB and **not** a null deref. Impact on current callers
is **latent**.

## Impact

- **API robustness / memory-safety footgun.** Real defect (null deref +
  unbounded source read for non-C-string storage), but no demonstrated production
  crash, no demonstrated info leak, and all in-tree callers fail closed on short
  C strings.
- **Medium:** public util on the SIM/AKA path with no documented contract; the
  next caller passing a raw digit buffer, a too-small buffer, or a null pointer
  gets UB/crash. The sibling encoder already has the guards.

## Minimal Counterexample

**OOB read** (guard-page witness, no-ASan binary):

```
hex = mapped buffer of exactly 2 hex digits, len = 2 (needs 4 readable bytes)
→ Hex2byte reads ipos[2], ipos[3] → into PROT_NONE → SIGSEGV
```

**Null `hex`** / **null `buf`:**

```
HexString2Byte(nullptr, buf, len) → Hex2byte derefs null → signal 11
HexString2Byte(hex, nullptr, 1)   → *opos++ on null      → signal 11
```

Valid path is fine: `ValidHexRoundTripsThroughByte2HexString` and
`OddLengthHexDoesNotCrash` PASS — short/odd **NUL-terminated** inputs already fail
closed via `Hex2num('\0') == -1`.

| `ValidHexRoundTripsThroughByte2HexString` | PASS |

can make gtest report `OK` even though ASan logged the crash.

## Suggested Fix

Prefer an explicit source length (matches how the function is actually used and
fixes non-C-string storage):

```cpp
int HexString2Byte(const char *hex, size_t hexLen, uint8_t *buf, size_t len)
{
    if (hex == nullptr || buf == nullptr) {
        return -1;
    }
    if (len > 0 && hexLen < len * 2) {
        return -1;
    }
    // existing loop, reading only within hexLen
    ...
}
```

Minimal same-signature hardening if an API break is unacceptable (documents a
C-string-only contract; does **not** by itself make non-terminated buffers safe):

```cpp
int HexString2Byte(const char *hex, uint8_t *buf, size_t len)
{
    if (hex == nullptr || buf == nullptr) {
        return -1;
    }
    // ponytail: C-string contract only; use hexLen API if raw buffers appear
    if (len > 0 && std::strlen(hex) < len * 2) {
        return -1;
    }
    ...
}
```

Either way: mirror `Byte2HexString`, and document the contract on the declaration
in `wifi_common_util.h`. A bare `strlen` check is fine for the in-tree C-string
callers; it is **not** a fix for the guard-page class of input — `hexLen` is the
real fix for raw digit buffers.
