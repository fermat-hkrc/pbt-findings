## Summary

`PixelConvert::IsValidRowStride` validates that a non-zero `rowStride` is at
least `width * bpp` (bytes per pixel). The multiplication is performed as
`int32`, which overflows for large dimensions: e.g., `width = INT32_MAX/8+1`
with `bpp=8` (RGBA_F16) produces a wrapped negative product, so the validator
incorrectly accepts `rowStride=1` as valid. A sibling in `pixel_map.cpp`
already computes the same threshold using `int64_t` to avoid overflow. Not
High: requires unrealistic dimensions; no proven live OOB on common decode
paths in this report. Confirmed and fixed by developers (`DTS2026073013382`).

## Vulnerable Code

`frameworks/innerkitsimpl/converter/src/pixel_convert.cpp`, lines 1848–1856:

```cpp
bool PixelConvert::IsValidRowStride(int32_t rowStride, const ImageInfo &imageInfo)
{
    if (imageInfo.pixelFormat == PixelFormat::YCBCR_P010 ||
        imageInfo.pixelFormat == PixelFormat::YCRCB_P010) {
        return rowStride == 0 ||
               rowStride >= imageInfo.size.width * YUV420_P010_BYTES;  // int32 *
    }
    return rowStride == 0 ||
           rowStride >= imageInfo.size.width *
           ImageUtils::GetPixelBytes(imageInfo.pixelFormat);  // int32 *
}
```

`imageInfo.size.width * GetPixelBytes(...)` overflows when the true bytes
needed exceeds `INT32_MAX`. The wrapped product is negative, making the
comparison `rowStride >= negative_value` trivially true for tiny strides.

Sibling (correct) — `pixel_map.cpp`, lines 435–437:

```cpp
int64_t minRowStride = static_cast<int64_t>(width) * bytesPerPixel;
if (srcRowStride <= 0 || srcRowStride < minRowStride) { /* fail */ }
```

## Trigger Conditions

1. `IsValidBufferInfo` → `IsValidRowStride` runs on a huge image.
2. `width * bpp` overflows `int32` (product > 2,147,483,647 bytes).
3. The caller passes an impossibly small non-zero `rowStride` (e.g., `1`).

Example: RGBA_F16 (`bpp=8`), `width=268,435,456` (`INT32_MAX/8+1`).

| Quantity | Value |
|----------|-------|
| `width` | `268,435,456` |
| `bpp` | `8` |
| True bytes/row | `2,147,483,648` (> INT32_MAX) |
| Wrapped `int32` product | `-2,147,483,648` (INT32_MIN) |
| `1 >= INT32_MIN` | `true` → **accepts stride 1** |

## Impact

- Validator returns `true` for impossible `(stride, width, bpp)` combinations.
- If a downstream convert operation trusts the row stride without further
  bounds checks, heap OOB is possible. Full impact trace not completed in this
  report → Medium, not security-High.
- `pixel_map.cpp` already computes this threshold safely with `int64_t`.

## Minimal Counterexample

| Input | Expected | Actual |
|-------|----------|--------|
| `stride=1`, `RGBA_F16`, `width=INT32_MAX/8+1` | `false` | `true` |
| `stride=0`, any format | `true` | `true` (unchanged) |

## How PBT Detected This

`pbt-native/is_valid_row_stride_pbt_test.cpp` — links the REAL
`pixel_convert.cpp` (**not** a model):

```cpp
RC_PRE(pixelFormat == PixelFormat::RGBA_F16);  // bpp=8, large impact
RC_PROPERTY(RejectsTinyStrideWhenOverflow,
            [&](int32_t stride, int32_t width) {
                int32_t bpp = 8;
                // Skip if product fits in int32 (no overflow)
                int64_t need = static_cast<int64_t>(width) * bpp;
                RC_PRE(need > INT32_MAX);
                // Tiny stride should be rejected
                RC_ASSERT(!sut.IsValidRowStride(stride, ...));
            });
```

Shrunk witness: `stride=1`, `width=268,435,456` (`INT32_MAX/8+1`).


## Suggested Fix

Compute the product using `int64_t` and reject if it exceeds `int32` range:

```diff
 bool PixelConvert::IsValidRowStride(int32_t rowStride, const ImageInfo &imageInfo)
 {
     if (rowStride == 0) {
         return true;
     }
+    int32_t bpp = (imageInfo.pixelFormat == PixelFormat::YCBCR_P010 ||
+                   imageInfo.pixelFormat == PixelFormat::YCRCB_P010)
+                      ? YUV420_P010_BYTES
+                      : ImageUtils::GetPixelBytes(imageInfo.pixelFormat);
+    if (imageInfo.size.width < 0 || bpp <= 0) {
+        return false;
+    }
+    int64_t need = static_cast<int64_t>(imageInfo.size.width) * bpp;
+    if (need > INT32_MAX) {
+        return false;
+    }
+    return rowStride >= static_cast<int32_t>(need);
 }
```

Matches the sibling `pixel_map.cpp` pattern: compute in `int64_t`, compare
against `int32` stride.
