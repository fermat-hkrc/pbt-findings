## Summary

Static `File::GetSpanFromId` builds a file-wide span and takes the suffix at
the entity offset via `file.Last(file.size() - id.GetOffset())` with **no**
check that `offset < fileSize`. When `offset > size`, unsigned wrap yields a
huge `length` into `Span::Last` (`ASSERT` fail-open under `NDEBUG`) → an
enormous/bad span is handed to essentially every static entity accessor.

Dynamic sibling rejects first:
`ThrowIfWithCheck(!id.IsValid() || id.GetOffset() >= file.size(), …)`.
Confirmed and fixed under `DTS2026080812034` (internal system).

## Vulnerable Code

`static_core/libarkfile/file.h`:

```cpp
Span<const uint8_t> GetSpanFromId(EntityId id) const
{
    const Header *header = GetHeader();
    Span file(GetBase(), header->fileSize);
    return file.Last(file.size() - id.GetOffset());  // no offset < size gate
}
```

## Contract

1. Invalid or past-end `EntityId` must not produce a span via unsigned wrap.
2. For `offset < fileSize`, returned span size is `fileSize - offset` starting
   at `base + offset`.
3. In-tree reference: dynamic `libpandafile` `GetSpanFromId` + `ThrowIfWithCheck`.

## Minimal Counterexample

```cpp
// file image length N = 16, EntityId offset = 20
Span file(base, 16);
size_t length = file.size() - 20;   // size_t wrap → very large
file.Last(length);
// Expected: reject (sibling ThrowIfWithCheck)
// Actual (NDEBUG): huge/poisoned Span returned to callers
```

## How PBT Detected This

Harness: `pbt-native/get_span_from_id_offset_underflow_pbt_test.cpp`.

| Property | Result (unfixed SUT) |
|---|---|
| `off < N` suffix length `N-off` | PASS |
| `off >= N` must not wrap / huge Last | FAIL |

## Impact

| Axis | Rating |
|------|--------|
| Impact when hit | Huge/bad span → OOB / corrupt decode across all `GetSpanFromId` clients |
| Likelihood on well-formed abc | Low — entity offsets in range |
| Likelihood on corrupt EntityId / truncated file | Medium |
| Overall | **Medium** |

Blast radius is large when hit: class/method/field/code/debug/literal/file_reader
accessors all go through this helper.

## Suggested Fix

Match libpandafile: reject invalid / `offset >= file.size()` **before** `Last`.

```cpp
ThrowIfWithCheck(!id.IsValid() || id.GetOffset() >= file.size(),
                 File::INVALID_FILE_OFFSET, ...);
return file.Last(file.size() - id.GetOffset());
```
