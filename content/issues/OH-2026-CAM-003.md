## Summary

`HCaptureSession::UpdateBasicInfoForStream` gates each non-string plugin code with
`isIntegerRegex(pair.second)` and then feeds that same string to `std::stoi`. But
`isIntegerRegex` only checks the shape `^-?[0-9]+$` with **no magnitude bound** — a
15-digit value passes the regex yet far exceeds `INT32_MAX` (2,147,483,647, 10
digits). `std::stoi` then throws `std::out_of_range` ("stoi"), and the throw is
**not caught** anywhere in `UpdateBasicInfoForStream` or its caller
`UpdateHookBasicInfo`. On rotate-plugin-enabled products this can abort the
capture-session / `UpdateSettingOnce` path.

The defect class is wider than one function: `isIntegerRegex` + `std::stoi` is a
mismatch anywhere it appears (`IsUint8Regex`, `camera_rotate_plugin.cpp`, XML
config parsing). This issue covers `UpdateBasicInfoForStream` + `DealPluginCode`;
sibling call-sites share the same root cause and fix.

## Vulnerable Code

`services/camera_service/src/hcapture_session.cpp` (~3006) — the gate and its call sites:

```cpp
CHECK_CONTINUE(code != PLUGIN_SURFACE_APP_FWK_TYPE && !isIntegerRegex(pair.second));
switch (code) {
    case PLUGIN_PREVIEW_FORMAT:
        CHECK_EXECUTE(previewProducer != nullptr,
            previewProducer->SetTransform(static_cast<OHOS::GraphicTransformType>(std::stoi(pair.second))));
        break;
    case PLUGIN_SURFACE_FRAME_GRAVITY:
        CHECK_EXECUTE(previewProducer != nullptr, previewProducer->SetFrameGravity(std::stoi(pair.second)));
        break;
    case PLUGIN_SURFACE_FIXED_ROTATION:
        CHECK_EXECUTE(previewProducer != nullptr, previewProducer->SetFixedRotation(std::stoi(pair.second)));
        break;
    case PLUGIN_VIDEO_SURFACE_TRANSFORM:
        CHECK_EXECUTE(videoProducer != nullptr,
            videoProducer->SetTransform(static_cast<OHOS::GraphicTransformType>(std::stoi(pair.second))));
        break;
    default:
        DealPluginCode(ParameterMap, settings, code, std::stoi(pair.second));
        break;
}
```

`services/camera_service/src/camera_util.cpp:548` — the over-permissive guard:

```cpp
bool isIntegerRegex(const std::string& input)
{
    static std::regex intRegex("^-?[0-9]+$");
    return std::regex_match(input, intRegex);   // no magnitude bound
}
```

`isIntegerRegex` ⇒ `safe to std::stoi` is the false implication: any all-digit
string passes, so values like `"100000000000000"` reach `std::stoi` and throw.

## When the Bug Triggers

The code path is **optional and runtime-gated**, but when enabled the bug is reachable:

| Condition | Notes |
|-----------|-------|
| Build flag | `camera_framework_feature_camera_rotate_plugin` (default **false** in `multimedia_camera_framework.gni`) — `HOOK_CAMERA_OPERATOR` + this code compile in only when the product turns it on. |
| Runtime gate | system param `const.camera.compatible_policy_camera.enable` + `dlopen libcompatible_policy_camera.z.so` + successful plugin init. |
| Entry | `CameraRotatePlugin::OnParameterChange` → `UpdateHookBasicInfo` → `UpdateBasicInfoForStream`. |
| Producer | the matching branch needs a **non-null** preview/video producer; a null producer short-circuits `CHECK_EXECUTE` so `std::stoi` is never evaluated. |
| Input | a `ParameterMap` entry with an oversized all-digit value on an integer plugin code. |

On **default** builds the defect is latent (code absent). On **rotate-plugin**
SKUs the path is live; likelihood stays low because normal plugin traffic uses
small `to_string` metadata values, but an abnormal oversized integer string
reaches the throw.

## Minimal Counterexample

| code | value | preview producer | result |
|------|-------|------------------|--------|
| `PLUGIN_PREVIEW_FORMAT` (5) | `"100000000000000"` (15 digits) | non-null | **throws `std::out_of_range` ("stoi"), uncaught** |

```cpp
ParameterMap m = { {5, "100000000000000"} };   // PLUGIN_PREVIEW_FORMAT
// isIntegerRegex("100000000000000") == true  → passes gate
// previewProducer != nullptr                  → CHECK_EXECUTE evaluates the call
// std::stoi("100000000000000") → throws std::out_of_range (15 digits >> INT32_MAX)
```

The same throw fires for `PLUGIN_SURFACE_FRAME_GRAVITY`,
`PLUGIN_SURFACE_FIXED_ROTATION`, and `PLUGIN_VIDEO_SURFACE_TRANSFORM` whenever
their producer is non-null, plus the `default` branch's `DealPluginCode`.

## How PBT Detected This

A RapidCheck property (`UpdateBasicInfo.StoiSafeForAnyAcceptedInteger`) encoded
the negative/safety contract: for any value the production helper
`isIntegerRegex` accepts, passing it through `UpdateBasicInfoForStream` must be
safe (not throw). The SUT implicitly asserts "isIntegerRegex ⇒ safe to
`std::stoi`" — the property proved that implication false. RapidCheck shrank the
input to `code=PLUGIN_PREVIEW_FORMAT`, `value="100000000000000"`,
non-null preview producer. Confirmed directly against the real extracted closure:

```
$ probe2   # PLUGIN_PREVIEW_FORMAT="100000000000000", non-null preview producer
RESULT THREW: stoi
```

No gtest/PBT existed at introduction (commit `69a219121`, 2025-05-10); the first
systematic check is the `pbt-native` property tests.

## Impact

On rotate-plugin-enabled products, when `OnParameterChange` delivers a map with an
oversized all-digit value on an integer plugin code and the matching stream
producer is non-null, the service hits an uncaught `std::out_of_range` (process /
session failure). On default builds without the hook, the defect is latent. Impact
is a throw / abort, not silent wrong metadata.

## Suggested Fix

Parse the value **once** with a non-throwing, magnitude-bounded helper and reuse
the validated `int32_t` at every call site. This fixes the
`isIntegerRegex ⇒ safe to std::stoi` implication at the root: every value that
survives the gate is provably inside the `int32_t` range. `std::from_chars` is
stdlib (no new dependency) and sets `errc::result_out_of_range` on overflow
instead of throwing.

A `try/catch` around each `stoi` was rejected: the 4+1 call sites would each need
their own wrapper; one shared non-throwing parse is a smaller, safer diff and also
gives `DealPluginCode` a pre-validated `int32_t`. `PLUGIN_SURFACE_APP_FWK_TYPE`
keeps taking the raw string (its case is intentionally outside the integer gate).

## Sibling defects (same root cause)

`isIntegerRegex` + `std::stoi` is a mismatch wherever it appears; these share the
root cause and the `ParseInt32Strict` / `from_chars` fix:

- `IsUint8Regex` (`camera_util.cpp:569`) — `int number = std::stoi(input)` after `isIntegerRegex`; caller `camera_parameters_config_parser.cpp:42`. One-line swap closes it.
- `camera_rotate_plugin.cpp` (~279–425) — direct sibling, more `stoi` sites.
- XML `type` config parsing (`ParseParameterNode`), applist JSON key parsing, logic-camera status parsing.

Fix once at the helper; each report is a separate call-site migration.
