## Summary

`RSUniRenderUtil::GetMatrixByDegree` builds the un-rotation applied before the
hardware-cursor `srcRect` is computed (`RSUniRenderVisitor::AfterUpdateSurfaceDirtyCalc`,
hard-cursor top surface only). All three arms pass the **other** bounds axis to
`PreTranslate`: 90° uses `-boundsWidth` where `-boundsHeight` is needed, 180°
swaps both, -90° uses `-boundsHeight` where `-boundsWidth` is needed. A
non-square cursor is shifted onto the wrong axis before `UpdateSrcRect` clamps
it; square cursors and degree 0 hide the defect. Fixed upstream in
`d1115fc36d` (2026-10-19) — line-identical to the PBT report's diff — under
`DTS2026101653039`.

## Vulnerable Code

`rs_uni_render_util.cpp` `RSUniRenderUtil::GetMatrixByDegree` (~1091–1116), all
three `PreTranslate` arms.

Witness (`bounds = RectF(0, 0, 1, 2)`, map of `(0, 0)`, pre-fix):

| Degree | Expected | Actual |
|--------|----------|--------|
| 180 | `(1, 2)` | `(2, 1)` |
| 90 | `(2, 0)` | `(1, 0)` |
| -90 | `(0, 1)` | `(0, 2)` |

Official `GetMatrixByDegree001` uses zero bounds and only checks that the
rotation degree returns to 0, so the swapped translation was invisible.

## Impact

Medium — silent wrong `srcRect` sample on a non-square hard cursor under
screen rotation 90/180/270. Not a crash. Square cursors unaffected.
