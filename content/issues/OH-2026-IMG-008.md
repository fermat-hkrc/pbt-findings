## Summary

`HalfToUint32` assembles a `uint16_t` half from two bytes, decodes via
`HalfToFloat`, and truncates to `uint32_t` for `RGBA_F16 → 8-bit` format
conversion. The LE/BE ternary arms are **exactly backwards**: for little-
endian (the only live path on production devices) it builds `(lo<<8)|hi` —
a byte-swap of the half value. Channel `1.0` (`0x3C00`, LE bytes
`{0x00,0x3C}`) becomes `0` instead of `1`; channel `255.0` (`0x5BF8`,
`{0xF8,0x5B}`) becomes a huge wrapped `uint32` (sign bit flipped → negative
float → wrap). Byte-symmetric values including zero hide the bug. The sibling
`HalfTranslate` in `pixel_map.cpp` already loads LE half bytes correctly.
Not High: silent wrong channel integer, no crash/OOB. Confirmed and fixed by
developers (`DTS2026081413702`).

## Vulnerable Code

`frameworks/innerkitsimpl/converter/include/pixel_convert.h` — `HalfToUint32`
(~178):

```cpp
static inline uint16_t U8ToU16(uint8_t val1, uint8_t val2)
{
    uint16_t ret = val1;
    return ((ret << SHIFT_8_BIT) | val2);   // (val1<<8)|val2 — val1 is HIGH byte
}

static inline uint32_t HalfToUint32(const uint8_t* ui, bool isLittleEndian)
{
    // BUG: LE and BE arms are inverted vs HalfTranslate / natural LE layout.
    uint16_t val = isLittleEndian ? U8ToU16(*ui, *(ui + 1))       // (lo<<8)|hi  ← WRONG for LE
                                  : U8ToU16(*(ui + 1), *ui);      // (hi<<8)|lo  ← WRONG for BE
    float fRet = HalfToFloat(val);
    return static_cast<uint32_t>(fRet);
}
```

Sibling (correct) — `pixel_map.cpp` `HalfTranslate` (~4017):

```cpp
constexpr uint8_t HALF_LOW_BYTE = 0;
constexpr uint8_t HALF_HIGH_BYTE = 1;
static float HalfTranslate(const uint8_t* ui)
{
    return HalfToFloat(U8ToU16(ui[HALF_HIGH_BYTE], ui[HALF_LOW_BYTE])); // (hi<<8)|lo
}
```

`U8ToU16(a,b)` treats `a` as high byte. `HalfTranslate` correctly passes
`(ui+1, ui)` for LE (high byte is second byte), but `HalfToUint32` passes
`(*ui, *(ui+1))` — exactly backwards.

Callers: `RGBAF16Convert*` template in `pixel_convert.cpp` (~937) — every
live `RGBA_F16 → ARGB_8888 / RGBA_8888 / BGRA_8888 / ABGR_8888 / RGB_565`
path, always with `IS_LITTLE_ENDIAN`.

## Trigger Conditions

1. `RGBA_F16 → 8-bit` format conversion runs (live path).
2. `isLittleEndian == true` — the only flag passed on production devices.
3. The half value is not byte-symmetric (`b0 != b1`).

Byte-symmetric values (`0x0000`, `0xFFFF`, etc.) hide the bug because the
swap produces the same bit pattern.

## Impact

- Every non-byte-symmetric half channel is decoded from the **byte-swapped**
  bit pattern.
- Half `1.0` → `0`; half `255.0` → huge garbage `4294931616`.
- Round-trip `* → RGBA_F16 → RGBA_8888` silently destroys channel values.
- `pixel_map.cpp` float reads via `HalfTranslate` are **not** affected — same
  buffer yields different channels depending on which API unpacks it.
- Medium: silent wrong channel integer on every live `RGBA_F16 → 8-bit`
  convert; no crash / OOB.

## Minimal Counterexample

| Input half | Bytes (LE) | Flag | Expected `uint32` | Actual `uint32` | Assembled half |
|-----------:|-----------:|-----:|------------------:|----------------:|---------------:|
| `0x3C00` (1.0) | `{0x00,0x3C}` | `true` | **`1`** | **`0`** | **`0x003C`** |
| `0x5BF8` (255.0) | `{0xF8,0x5B}` | `true` | **`255`** | **`4294931616`** | **`0xF85B`** |
| `0x3C00` (1.0) | `{0x3C,0x00}` | `false` | **`1`** | **`0`** | **`0x003C`** |
| `0x0000` (+0) | `{0x00,0x00}` | `true` | `0` | `0` (hides) | `0x0000` |

## How PBT Detected This

`pbt-native/half_to_uint32_pbt_test.cpp` — includes the REAL `pixel_convert.h`
(**not** a model):

| Check | Result |
|-------|--------|
| `LeMatchesSiblingAssemblePlusHalfToFloat` vs oracle | **FAIL** (shrunk to `0x3C00`: `sut=0`, `ref=1`) |
| `BeMatchesAssemblePlusHalfToFloat` vs oracle | **FAIL** (same witness on BE path) |
| `ConcreteWitness_LeOnePointZero` / `LeTwoFiftyFive` / `BeOnePointZero` | **FAIL** |

Happy-path properties that don't pin absolute endian semantics still pass
(endian dual agreement, byte-swap+flip-flag identity) — both arms are
consistently inverted, so relative LE↔BE transforms hold.

```bash
cmake -S pbt-native -B pbt-native/build -DCMAKE_BUILD_TYPE=Release
cmake --build pbt-native/build -j --target half_to_uint32_pbt_test
./pbt-native/build/half_to_uint32_pbt_test
```

## Suggested Fix

Swap the two arms so LE matches the sibling `HalfTranslate`:

```diff
 static inline uint32_t HalfToUint32(const uint8_t* ui, bool isLittleEndian)
 {
-    uint16_t val = isLittleEndian ? U8ToU16(*ui, *(ui + 1)) : U8ToU16(*(ui + 1), *ui);
+    // LE: high byte at ui+1 (same as pixel_map.cpp HalfTranslate).
+    // BE: high byte at ui+0.
+    uint16_t val = isLittleEndian ? U8ToU16(*(ui + 1), *ui) : U8ToU16(*ui, *(ui + 1));
     float fRet = HalfToFloat(val);
     return static_cast<uint32_t>(fRet);
 }
```

No caller changes. After fix: LE half `0x3C00` → `1u`, `0x5BF8` → `255u`.
