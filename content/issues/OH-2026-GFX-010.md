## Summary

NDK `DrawPixelMapMeshBuilderProcess` swaps `meshWidth` (columns) and
`meshHeight` (rows). Non-square meshes get a transposed UV lattice and wrong
triangle connectivity. Header `drawing_canvas.h` pins width = columns. JS/ANI
`DrawingPixelMapMesh` walks row then column and is correct, so NDK and JS
disagree on the same API. Square meshes hide it. Confirmed and fixed under
`DTS2026090527401`.

## Vulnerable Code

`drawing_canvas_utils.cpp` anonymous `DrawPixelMapMeshBuilderProcess` (~61–99),
called from `DrawingCanvasUtils::DrawPixelMapMeshInternal` →
`OH_Drawing_CanvasDrawPixelMapMesh`.

## Impact

High — public NDK mesh draw is wrong whenever `meshWidth != meshHeight`. Not
a crash.
