## Summary

On the `spaceUpdated_` path, `adjustOffset_.start` is set to the **entire**
body delta when `endIndex_ >= 0`. `ShiftLayoutWindow(start)` then slides the
cached window. Packed-from-zero content keeps item 0 at `startPos = 0` — the
top did not move — so `start` must be 0 and growth belongs on `end`.

**Confirmed** under `DTS2026091437627` (accepted; **not fixed yet**).

## Contract

`start` is how far the top edge moved. When item 0’s `startPos` is unchanged,
`start = 0` and the body delta goes to `end`.

## Vulnerable Code

```cpp
adjustOffset_.start = endIndex_ < 0 ? 0.0f : totalMainSize_ - prevTotalMainSize_;
```

## Minimal Counterexample

8×200, gap 0→20, covering: `start=140, end=0` (expected `start=0, end=140`).

## How PBT Detected This

`SpaceUpdatedUnmovedTopHasZeroStartAdjust` FAIL.

## Suggested Fix

On `spaceUpdated_`: `adjustOffset_.start = 0.0f;` (leave `end = total - prev - start`).
