## Summary

`CaptureSession::GetZoomRatioRange` walks `OHOS_ABILITY_SCENE_ZOOM_CAP` as
fixed `(mode, min, max)` triples (`step = 3`) but bounds only `i < item.count`,
then always reads `i32[i+1]` / `[i+2]` — including the debug log. Short or
non-multiple-of-3 count → heap **OOB read**.

Same file, same offsets: `GetRAWZoomRatioRange` already
`CHECK_BREAK_ELOG(i + maxOffset >= item.count, …)` before those reads.
Not High: well-formed triples OK. Orthogonal to moon FOV look-ahead and
pair-walk tickets.

Confirmed and fixed by developers (`DTS2026080813622`).

## Vulnerable Code

`frameworks/native/camera/base/src/session/capture_session.cpp` —
`GetZoomRatioRange` (~3853–3864) vs `GetRAWZoomRatioRange` (~3793–3800):

```cpp
// GetZoomRatioRange — BUG
for (uint32_t i = 0; i < item.count; i += step) {
    MEDIA_INFO_LOG("… min: %{public}d, max: %{public}d",
        item.data.i32[i],
        item.data.i32[i + minOffset],
        item.data.i32[i + maxOffset]);  // no i+2 < count
    if (GetFeaturesMode().GetFeaturedMode() == item.data.i32[i]) {
        minZoom = item.data.i32[i + minOffset] / factor;
        maxZoom = item.data.i32[i + maxOffset] / factor;
        break;
    }
}

// GetRAWZoomRatioRange — OK (same file)
for (uint32_t i = 0; i < item.count; i += step) {
    CHECK_BREAK_ELOG(i + maxOffset >= item.count,
        "… invalid data format, i + maxOffset >= item.count");
    …
}
```

Root cause: scene-zoom path never copied the RAW sibling guard. Log evaluates
the same unbound indices even when the mode does not match.

## Trigger Conditions

1. HAL ability `OHOS_ABILITY_SCENE_ZOOM_CAP` has count 1, 2, 4, 5, …
   (truncated / non-multiple-of-3).
2. Session zoom path calls `GetZoomRatioRange`.
3. Last partial triple reads `i+1` / `i+2` past the blob.

## Impact

- Heap OOB read while resolving zoom min/max for the current feature mode.
- Medium: well-formed triple tables (normal devices) unaffected; field hit
  needs truncated HAL metadata. FW bound still wrong vs its own RAW twin.
- One sibling guard covers log + body.

## Minimal Counterexample

| `item.count` | `GetZoomRatioRange` | `GetRAWZoomRatioRange` |
|--------------|---------------------|-------------------------|
| 0 / 3 / 6 | OK | OK |
| 1 (`{mode}`) | **OOB** `[1]`,`[2]` | break |
| 2 (`{mode,min}`) | **OOB** `[2]` | break |
| 4 (`{…,m1}`) | last `i=3` **OOB** | break at `i=3` |

## Suggested Fix

Copy the RAW sibling guard before indexed reads (including the log):

```cpp
for (uint32_t i = 0; i < item.count; i += step) {
    CHECK_BREAK_ELOG(i + maxOffset >= item.count,
        "CaptureSession::GetZoomRatioRange: invalid data format, "
        "i + maxOffset >= item.count");
    MEDIA_INFO_LOG(… item.data.i32[i], item.data.i32[i + minOffset],
                   item.data.i32[i + maxOffset]);
    …
}
```

After fix: short-count props PASS; full-triple props stay PASS.
