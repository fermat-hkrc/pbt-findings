## Summary

`CalculateMaxAmplitudeForPCM24Bit` assembles little-endian 24-bit PCM with
`*(curPos + j) << (BIT_8 * j)` on `char *`. On hosts where `char` is signed,
bytes ≥ `0x80` promote to a negative `int` **before** the shift, so the
value is not unsigned LE24 + sign-extend. Peak amplitude is wrong for most
samples with `byte0` or `byte1` ≥ `0x80`; the curve is non-monotonic vs true
`|s24|`. Sibling `MixS24Volume` already unpacks LE24 as unsigned bytes then
arithmetic sign-extend. Confirmed and fixed by developers
(`DTS2026072338862`). Not necessarily present on this fork.

## Vulnerable Code

`frameworks/native/audioutils/src/audio_utils.cpp`
(`CalculateMaxAmplitudeForPCM24Bit` ~1168):

```cpp
char *curPos = frame + (i * 3);
int curValue = 0;
for (int j = 0; j < 3; ++j) {
    curValue += (*(curPos + j) << (BIT_8 * j));  // char may be signed
}
```

Dispatch: `UpdateMaxAmplitude` → `SAMPLE_S24_C`.

Correct sibling (`MixS24Volume` in `format_converter.cpp`):

```cpp
uint32_t u = (srcBuffer[2] << 16) | (srcBuffer[1] << 8) | srcBuffer[0];
int32_t s24 = (static_cast<int32_t>(u) << 8) >> 8;
```

## Trigger Conditions

1. `CalculateMaxAmplitude` / `UpdateMaxAmplitude` runs on `SAMPLE_S24_C`.
2. A 24-bit sample has `byte0 ≥ 0x80` or `byte1 ≥ 0x80` (common in real PCM).
3. Signed `char` promotion subtracts 256 before the shift; `|curValue|` is
   not `|s24|`.

Non-bug regime: `byte0 < 0x80` and `byte1 < 0x80` (byte2 high bit coincides
with 24-bit sign-extend).

## Impact

| Witness | Intended s24 | Expected amp | SUT amp |
|---------|--------------|--------------|---------|
| `{0x00,0xFF,0x00}` vs `{0xFF,0xFE,0x00}` | +65280 vs +65279 | monotone `|x|≥|y|` | **inverted** |
| `{0xFF,0x00,0x00}` | +255 | `255/8388607` | `1/8388607` (255× under-report) |

Meters / silence path track a non-monotonic, under-reported curve. Medium:
wrong peak on the live amplitude helpers; not crash/UB.

## Minimal Counterexample

```
buf = {0xFF, 0x00, 0x00}  // intended s24 = +255
// SUT: char 0xFF → -1; curValue = 1; amp ≈ 1.19e-07
// expected amp = 255 / 8388607 ≈ 3.04e-05
```

## How PBT Detected This

Real-SUT harnesses `audio_max_amplitude_pcm24_pbt_test` /
`audio_amplitude_pcm24_pbt_test`. Oracle: LE24 unpack ≡ `MixS24Volume`;
amplitude monotone in `|s24|`.

| Check | Result |
|-------|--------|
| `MonotonicityInvertedBySignedChar` | **FAIL** (witness A) |
| `Byte0HighBitBreaksSpecOracle` | **FAIL** (witness B) |
| `MatchesSpecOracleOnLowBytes` (byte0/1 < 0x80) | PASS |

## Suggested Fix

Assemble as unsigned bytes, then sign-extend 24→32:

```cpp
const uint8_t *p = reinterpret_cast<const uint8_t *>(frame) + i * 3;
uint32_t u = (uint32_t)p[0] | ((uint32_t)p[1] << 8) | ((uint32_t)p[2] << 16);
int curValue = static_cast<int>(static_cast<int32_t>(u << 8) >> 8);
```

After fix: witness A ordered; witness B = `255/8388607`.
