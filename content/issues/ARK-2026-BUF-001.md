## Summary

`MemoryBufferWriter::WriteByte` / `WriteBytes` / `AppendRange` compute the
destination as `sp_.SubSpan(offset_, n)` with **no check** that
`offset_ + n <= capacity`, then `memcpy_s`. Past-capacity writes return
`true` and advance `offset_` past the buffer.

On a 4-byte writer, a 5th `WriteByte` wrote one byte past the buffer and
returned `true` with `offset_=5`. Under ASan: out-of-bounds **write**; plain
release: silent `true`. Confirmed and fixed by developers
(`DTS2026071807957`) — capacity gate on all three paths.

## Vulnerable Code

`static_core/libarkfile/file_writer.cpp`:

```cpp
bool MemoryBufferWriter::WriteByte(uint8_t byte)
{
    if (Unlikely(countChecksum_)) {
        checksum_ = adler32(checksum_, &byte, 1U);
    }
    auto subSp = sp_.SubSpan(offset_, 1U);   // (A) no offset_ < sp_.Size()
    if (memcpy_s(subSp.data(), subSp.size(), &byte, 1U) != 0) {  // (B)
        return false;
    }
    offset_++;
    return true;
}
```

Two safety nets fail open:

1. `Span::SubSpan` guards only with `ASSERT((position+length) <= size_)`
   (`span.h`). Under `NDEBUG`, `ASSERT` is a no-op → out-of-range `SubSpan`
   returns `Span(buf + offset_, n)` unchecked.
2. Returned span has `size() == n` (requested count), so `memcpy_s`'s
   `destMax` is `n`, not remaining capacity. With `srcSize == destMax == n`,
   `memcpy_s` cannot detect the overflow.

Identical missing gate on `WriteBytes` and `AppendRange`.

## Trigger Conditions

1. Caller constructs `MemoryBufferWriter` over a fixed-capacity buffer.
2. Total writes exceed capacity (layout / write-accounting divergence).
3. Past-capacity `Write*` returns `true`; `offset_` advances; OOB write
   proceeds.

Production callers size the buffer via the assembler's own layout, then write
all items — capacity is not attacker-controlled.

## Impact

| Axis | Rating |
|------|--------|
| Impact when hit | High (OOB **write** past caller buffer) |
| Likelihood | Low–Medium — capacity computed internally by assembler; needs layout / write-accounting divergence |
| Prod symptom | **heap**-buffer-overflow (`new[]`), not the stack overflow of the minimal witness |
| Path | `MemoryBufferWriter` WriteByte / WriteBytes / AppendRange |
| Overall | **Medium** |

Reachability:

- Dynamic runtime `assembler/assembly-emitter.cpp` — `ComputeLayoutForRest()`
  then `DeduplicateItems()` **after** size → accounting drift is a concrete
  overflow vector.
- Static runtime `static_core/assembler/assembly-emitter.cpp` —
  `ComputeLayout()` then `items.Write(&writer)`.

## Minimal Counterexample

```
uint8_t buf[4] = {};
MemoryBufferWriter w(buf, 4);
w.WriteByte(1); w.WriteByte(2); w.WriteByte(3); w.WriteByte(4);
w.WriteByte(5);  // returns true, offset==5, writes 1 byte past buf
```

## How PBT Detected This

`pbt-native/memory_buffer_writer_pbt_test` — real SUT
`static_core/libarkfile/file_writer.cpp`:

| Suite.Property | Result |
|----------------|--------|
| `FillExactCapacity` / `WriteBytesExactCapacity` / `SplitWritesCoverBuffer` | PASS |
| `WritePastCapacityReturnsFalse` | **FAIL** (returns true, `offset` advances) |
| `WriteBytesOverflowReturnsFalse` | **FAIL** (returns true, OOB) |
| `FifthByteOnFourCapOOB` | **FAIL** (returns true, offset=5) |
| `WriteBytesTooLargeFails` | **FAIL** (returns true; OOB) |
| `ExactFillOk` | PASS |

```bash
cmake -S pbt-native -B pbt-native/build -DCMAKE_BUILD_TYPE=Release
cmake --build pbt-native/build --target memory_buffer_writer_pbt_test -j$(nproc)
pbt-native/build/memory_buffer_writer_pbt_test --gtest_filter='MemoryBufferWriter*'
```

ASan build confirms stack-buffer-overflow WRITE via `memcpy_s` → `WriteByte`.

## Suggested Fix

Capacity guard before `SubSpan` on all three paths; leave `offset_` unchanged
on failure (as implemented):

```cpp
// HasCapacity(n): offset_ <= sp_.Size() && n <= sp_.Size() - offset_
if (!HasCapacity(n)) {
    return false;
}
```
