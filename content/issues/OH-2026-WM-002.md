## Summary

`WindowLayoutPolicyCascade::ComputeRectByAspectRatio` strips the decor frame
from the request rect (and later the last rect) with bare `uint32_t` `-=`.
When the request is smaller than the frame (`WINDOW_FRAME_WIDTH = 5`,
`WINDOW_TITLE_BAR_HEIGHT = 48`, × vpr), the subtract wraps the content size
to ~4e9 before aspect fixup, so cascade freeform geometry goes wild.

Same product already saturates this subtract in `WindowLimits::Clip`
(`safeSub`). Large windows (w,h ≫ frames) match the saturating oracle.
Confirmed and fixed by developers (`DTS2026072921166`).

## Vulnerable Code

`wmserver/src/window_layout_policy_cascade.cpp` —
`ComputeRectByAspectRatio` (~337–338; last-rect path ~365–366):

```cpp
// decor-enabled branch
newRect.width_  -= winFrameW;  // bare uint32
newRect.height_ -= winFrameH;
// … later lastRect
lastRect.width_  -= winFrameW;
lastRect.height_ -= winFrameH;
```

At `vpr ≥ 1`, `winFrameW ≥ 10`, `winFrameH ≥ 53`. A 10×10 request then
underflows **height** (and width at exact frameW).

Root cause: no saturating subtract. When `width_`/`height_` < frame, unsigned
wrap feeds multi-GB sizes into aspect clamp / drag fixup.

## Trigger Conditions

1. Main floating window has aspect ratio + decor enabled (cascade layout).
2. Request rect is smaller than the decor strip (early / min-sized / 10×10).
3. Bare `-=` wraps; aspect path sees ~4e9 content size.

Partial mask: large windows (w,h ≫ frames) never wrap and agree with
`safeSub`. Not every cascade resize hits the small-rect path.

## Impact

- Small / early / min-sized request + decor → unsigned wrap → wrong cascade
  freeform geometry.
- Large windows unaffected.
- Medium: layout numbers only; no crash / heap OOB.

## Minimal Counterexample

```
request: 10×10
vpr:     1.0
winFrameW = 10, winFrameH = 53

Production:
  W → 0              // exact frameW
  H → 4294967253     // wrap

Expected (saturating sub):
  W → 0
  H → 0
```

## How PBT Detected This

`pbt-native/cascade_decor_pbt_test`:

| Property | Result |
|----------|--------|
| `SmallRectDoesNotWrap` | **FAIL** (e.g. `4294967287 == 0`) |
| `ConstructiveHeightUnderflow` | **FAIL** (`4294967253 == 0`) |
| `LargeRectMatchesOracle` | PASS |

```bash
cmake -S pbt-native -B pbt-native/build -DCMAKE_BUILD_TYPE=Release
cmake --build pbt-native/build -j --target cascade_decor_pbt_test
./pbt-native/build/cascade_decor_pbt_test
```

## Suggested Fix

Reuse `WindowLimits::Clip`'s saturating subtract at **both** strip sites
(`newRect` and `lastRect`):

```cpp
auto safeSub = [](uint32_t base, uint32_t dec) {
    return dec >= base ? 0u : base - dec;
};
newRect.width_  = safeSub(newRect.width_,  winFrameW);
newRect.height_ = safeSub(newRect.height_, winFrameH);
// same for lastRect
```

After fix: `SmallRectDoesNotWrap` / `ConstructiveHeightUnderflow` → PASS;
large stays PASS.
