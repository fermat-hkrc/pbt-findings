## Summary

`escape_markdown_v2_preserve_formatting` has three critical bugs: (1) broken idempotence — double-escaping backslashes on every pass, causing exponential corruption on retry/edit; (2) `~` (tilde) not escaped, used for strikethrough; (3) `>` (greater-than) not escaped, used for blockquotes. Messages containing `~` or `>` are rejected by Telegram API with "Bad Request: can't parse entities".

## Vulnerable Code

```python
SPECIAL = r'([\\{}\[\]()#+\-=|.!])'

def escape_markdown_v2_preserve_formatting(text: str) -> str:
    # 1. Escape all special characters except *, _, `
    escaped = re.sub(SPECIAL, r'\\\1', text)

    # 2. Escape # only when NOT part of a hashtag
    escaped = re.sub(r'(?<!\w)#(?!\w)', r'\#', escaped)

    # 3. Escape * or _ only when they appear inside words
    escaped = re.sub(r'(?<=\w)\*(?=\w)', r'\*', escaped)
    escaped = re.sub(r'(?<=\w)_(?=\w)', r'\_', escaped)

    return escaped
```

## Bug 1: Broken Idempotence (HIGH)

```python
escape("test.file")       = "test\\.file"
escape("test\\.file")     = "test\\\\.file"   # doubles backslashes
```

Every character in `SPECIAL` triggers re-escaping of its own escaped form. Retry, edit, or forward operations cause exponential corruption.

## Bug 2: `~` Not Escaped (MEDIUM)

Telegram MarkdownV2 uses `~text~` for strikethrough. `~` is missing from `SPECIAL`.

```python
escape("~strike~") == "~strike~"  # should be "\\~strike\\~"
```

## Bug 3: `>` Not Escaped (MEDIUM)

Telegram MarkdownV2 uses `>` for blockquotes. `>` is missing from `SPECIAL`.

```python
escape("a > b") == "a > b"  # should be "a \\> b"
```

## Impact

- **Message corruption** — retry/edit/forward corrupts messages with double-escaped backslashes
- **Message rejection** — messages containing `~` or `>` rejected with "Bad Request: can't parse entities"
- **User-facing** — affects all Telegram bot adapter users in production
- **High frequency** — `>` is very common in technical discussions, code, comparisons

## Reproduction

```python
from adapters.channels.platforms.telegram.workflows.handlers._execute_and_reply import escape_markdown_v2_preserve_formatting

# Bug 1
once = escape_markdown_v2_preserve_formatting("test.file")
twice = escape_markdown_v2_preserve_formatting(once)
assert once == twice  # FAILS

# Bug 2
assert escape_markdown_v2_preserve_formatting("~") == "\\~"  # FAILS

# Bug 3
assert escape_markdown_v2_preserve_formatting(">") == "\\>"  # FAILS
```

## Proposed Fix

```python
def escape_markdown_v2_preserve_formatting(text: str) -> str:
    # 1. Escape backslashes first to prevent double-escaping
    escaped = text.replace('\\', '\\\\')

    # 2. Escape all special chars except *, _, `, #
    for char in r'{}[]()~>`+-=|.!':
        escaped = escaped.replace(char, f'\\{char}')

    # 3. Escape # only when NOT part of a hashtag
    escaped = re.sub(r'(?<!\w)#(?!\w)', r'\#', escaped)

    # 4. Escape * or _ only when inside words
    escaped = re.sub(r'(?<=\w)\*(?=\w)', r'\*', escaped)
    escaped = re.sub(r'(?<=\w)_(?=\w)', r'\_', escaped)

    return escaped
```

Key changes: escape `\\` first, add `~` and `>`, use `str.replace` for simple chars (idempotent).

## How This Was Found

Property-based testing with [Hypothesis](https://hypothesis.readthedocs.io/) via `test_idempotence`:

```python
@given(st.text(min_size=0, max_size=50))
@example("{")
@example(".")
@example("\\")
def test_idempotence(text):
    once = escape_markdown_v2_preserve_formatting(text)
    twice = escape_markdown_v2_preserve_formatting(once)
    assert twice == once  # FAILS for most inputs with SPECIAL chars
```
