## Summary

`DoMatchCondition` splits on `or(` / `,`. A true **single** clause returns
immediately. A true **AND-group** is returned only when it is the **last**
clause (`if (i + 1 == len)`). A later false single then falls through to
`return inverse`. So `(A)and(B)or(C)` can disagree with `(C)or(A)and(B)`.

**Confirmed** under `DTS2026090919800` (accepted; **not fixed yet**).

## Contract

`(A)and(B)or(C)` ≡ `(A && B) || C`. Public Syntax: `and` all features; `or`
any clause. In-tree Test013/014 pin conjunction and disjunction separately.

## Vulnerable Code

`media_queryer.cpp` `DoMatchCondition` (~312–329): true AND-group that is not
last is discarded; only `i + 1 == len` returns it.

## Minimal Counterexample

```cpp
// width=1, height=1
MatchCondition("(width>=0)and(height>=0)or(width>=2)", f);
// Expected: true   Actual: false
```

## How PBT Detected This

`OrDisjunctionIncludingAndClause` FAIL; `AndIsConjunction` PASS.

## Suggested Fix

Treat a true AND-group like a true single: `if (result) return !inverse;`.
