## Summary

`CubicResampler::Dump` formats both labeled fields from `cubicCoffB` —
copy-paste wrong operand — so the `cubicCoffC:` slot always shows B. Debug/trace
string only; no crash, no filter math. Sampling itself uses real fields
(`GetCubicCoffB/C`) and is unaffected. Confirmed and fixed by developers
(`DTS2026080530843`).

## Vulnerable Code

`rosen/modules/2d_graphics/include/utils/sampling_options.h` —
`CubicResampler::Dump` (~49):

```cpp
out += "[cubicCoffB:" + std::to_string(cubicCoffB);
out += " cubicCoffC:" + std::to_string(cubicCoffB);  // BUG: should be cubicCoffC
out += ']';
```

| Label | Written | Correct |
|-------|---------|---------|
| `cubicCoffB:` | B | B |
| `cubicCoffC:` | **B** | **C** |

Caller: `SamplingOptions::Dump` → `cubic.Dump(out)`.

Root cause: copy-paste — `cubicCoffB` written twice.

## Trigger Conditions

1. Any `CubicResampler` with `cubicCoffB != cubicCoffC` is dumped (logs/trace).
2. Output string shows B under the `cubicCoffC:` label.

Mitchell `{1/3, 1/3}` looks OK only because B == C.

## Impact

- Logs/dumps lie about C when `B != C`.
- **Sampling itself uses real fields** — unaffected.
- Low: debug/trace correctness only; no crash, no filter math.

## Minimal Counterexample

```
CubicResampler{0.f, 0.125f}.Dump → "... cubicCoffC:0.000000"  // want 0.125
CatmullRom {0, 0.5} → both fields look like 0
Mitchell {1/3, 1/3} → looks OK only because B == C
```

