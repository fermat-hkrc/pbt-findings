## Summary

`CheckIpv4InNet` computes the CIDR subnet mask with:

```cpp
uint32_t mask = (prefixLen == 32) ? 0xffffffff : ~((1 << (32 - prefixLen)) - 1);
```

When `prefixLen = 0`, this evaluates `1 << 32` — **undefined behavior** in C/C++
(shifting a 32-bit `int` by its own width; C++ [expr.shift]). On x86 the hardware
silently wraps the shift amount mod 32, so `1 << 32` becomes `1 << 0 = 1`, yielding
mask `0xFFFFFFFF` (exact-match) instead of `0x00000000` (match-all). A `/0` prefix
— which by the CIDR spec must match every address — instead matches only the exact
CIDR base address.

The developer special-cased `prefixLen == 32` but left the symmetric `prefixLen == 0`
boundary unguarded, where the formula is genuinely broken. There is no range check
on `prefixLen` anywhere between the PAC script and `CheckIpv4InNet`, so any PAC
`isInNetEx(host, "0.0.0.0/0")` catch-all rule silently never matches — **total
undetected proxy bypass** with no error signal.

## Contract

`services/netconnmanager/src/pac_functions.cpp:918`:

```cpp
static bool CheckIpv4InNet(const char *ip, const char *cidr, int prefixLen)
```

CIDR spec contract: a prefix length of 0 produces an all-zeros mask
(`0x00000000`), which matches every IPv4 address. Therefore:

> For any valid IPv4 address `ip` and any valid CIDR base `cidr`,
> `CheckIpv4InNet(ip, cidr, 0)` must return `true`.

## Vulnerable Code

`services/netconnmanager/src/pac_functions.cpp:925`:

```cpp
static bool CheckIpv4InNet(const char *ip, const char *cidr, int prefixLen)
{
    struct in_addr ip4;
    struct in_addr net4;
    if (inet_pton(AF_INET, ip, &ip4) != 1 || inet_pton(AF_INET, cidr, &net4) != 1) {
        return false;
    }
    uint32_t mask = (prefixLen == 32) ? 0xffffffff : ~((1 << (32 - prefixLen)) - 1);
    //                                                      ^^^^^^^^^
    //                                                      UB when prefixLen == 0:
    //                                                      1 << 32 is undefined behavior
    return (ip4.s_addr & htonl(mask)) == (net4.s_addr & htonl(mask));
}
```

For `prefixLen = 0`, on x86:

```
1 << (32 - 0)  =  1 << 32         ← UB; x86 hardware gives 1 << 0 = 1
~((1) - 1)     =  ~(0)            = 0xFFFFFFFF   ← exact-match mask
```

Should be `mask = 0x00000000` (match-all for `/0`). The `/32` special case was
added preemptively (the formula would work there by accident); the `/0` case —
where the formula is actually broken — was not handled.

## When the Bug Triggers

`prefixLen = 0` flows from a PAC script through to `CheckIpv4InNet` with **no guard
anywhere in the chain**:

```
PAC script:  isInNetEx(host, "0.0.0.0/0")
  → JsIsInNetEx  (pac_functions.cpp:950)
      slash = strchr(cidr, '/')          // finds '/'
      *slash = '\0'                      // splits into "0.0.0.0" + "0"
      prefixLen = atoi("0") = 0          // no range check, no clamp
  → CheckIpv4InNet(ip, "0.0.0.0", 0)    // ← UB path
      mask = 0xFFFFFFFF                  // wrong: should be 0x00000000
      returns false for every ip ≠ 0.0.0.0
```

Production entry chain:

```
NetConnService::SetGlobalHttpProxy (net_conn_service.cpp:2895)
  → InitPACScriptWithURL / InitPACScript
  → NetPACManager::FindProxyForURL
  → JerryScript evaluates PAC script
  → isInNetEx(host, "0.0.0.0/0") → JsIsInNetEx → CheckIpv4InNet(..., 0)
  → returns false  ← proxy rule never fires
```

`NetConnService` starts a local `ProxyServer` and sets it as the system-wide HTTP
proxy. Every outgoing connection on the device goes through `FindProxyForURL`.

## Minimal Counterexample

```cpp
// Any two distinct addresses with prefixLen=0 must both match — they don't.
CheckIpv4InNet("0.0.0.0", "1.0.0.0", 0)  // Expected: true   Actual: false
CheckIpv4InNet("1.2.3.4", "8.8.8.8", 0)  // Expected: true   Actual: false

// The only /0 case that accidentally passes — ip == cidr (exact match):
CheckIpv4InNet("1.0.0.0", "1.0.0.0", 0)  // Returns: true  (coincidence, not correctness)
```

## Consequence

An enterprise or VPN deploys a PAC file with the standard catch-all proxy rule —
"route all traffic through the corporate proxy":

```js
function FindProxyForURL(url, host) {
    if (isInNetEx(host, "10.0.0.0/8"))  return "PROXY internal:8080";
    if (isInNetEx(host, "0.0.0.0/0"))   return "PROXY corp-proxy:8080";
    return "DIRECT";
}
```

With the bug:

- `isInNetEx(host, "10.0.0.0/8")` — **works** (prefixLen=8, no UB)
- `isInNetEx(host, "0.0.0.0/0")` — **always `false`** (prefixLen=0, UB)
- Every host not on `10.0.0.0/8` hits `return "DIRECT"` — **total proxy bypass**

Hard to detect: no error is raised; the proxy "partially works" (specific prefixes
`/8`, `/16`, `/24` behave correctly, only the `/0` catch-all silently fails); traffic
goes direct with no log warning, no connection error, no user-visible signal. An
admin debugging this would need to specifically test the `/0` case to find it.

Existing tests did not catch this: `CheckIpv4InNet` is `static` (file-local

script strings — **never** with `prefixLen = 0` or `prefixLen = 32`, the two
boundaries where the mask formula is unsafe.

## Impact

Silent **total bypass** of a security control (PAC-based proxy enforcement) with no
error signal. The bug is narrow (only `prefixLen == 0`) but the `/0` catch-all is a
standard enterprise/VPN PAC idiom, and when it triggers the consequence is total —
the catch-all by definition covers every host the earlier rules missed. The proxy
"partially works" (specific-prefix rules fire correctly), which masks the failure.

## Suggested Fix

Guard both boundary values explicitly, and change `1` to `1u` to eliminate the
signed-shift UB for all other prefix lengths:

```cpp
static bool CheckIpv4InNet(const char *ip, const char *cidr, int prefixLen)
{
    struct in_addr ip4;
    struct in_addr net4;
    if (inet_pton(AF_INET, ip, &ip4) != 1 || inet_pton(AF_INET, cidr, &net4) != 1) {
        return false;
    }
    uint32_t mask;
    if (prefixLen == 0) {
        mask = 0x00000000;           // /0  → match all addresses
    } else if (prefixLen == 32) {
        mask = 0xffffffff;           // /32 → exact match
    } else {
        mask = ~((1u << (32 - prefixLen)) - 1);  // 1u: unsigned, no UB
    }
    return (ip4.s_addr & htonl(mask)) == (net4.s_addr & htonl(mask));
}
```

A range-clamp on `prefixLen` at the `JsIsInNetEx` call site (`atoi` result) is a
complementary defense, but the mask formula itself must not rely on UB — the
boundary guards are the root-cause fix.
