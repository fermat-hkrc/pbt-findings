## Summary

Two functions in `image_utils.cpp` carry conflicting sizing assumptions for `ALPHA_8` pixels with no shared constant resolving the ambiguity. `GetPixelBytes(ALPHA_8)` returns 1 byte/pixel (no alignment), while `GetRowDataSizeByPixelFormat(ALPHA_8)` applies 4-byte row alignment: `(w + 3) / 4 * 4`. Production NAPI code allocates buffers using the naive formula and then writes using the canonical (aligned) size, producing a heap buffer overflow for any image width not divisible by 4.

## Root Cause

| Function | ALPHA_8 behavior | Assumption |
|---|---|---|
| `GetPixelBytes(ALPHA_8)` | returns `1` byte/pixel | No alignment |
| `GetRowDataSizeByPixelFormat(ALPHA_8)` | `(w + 3) / 4 * 4` | 4-byte row alignment |

Any caller using `width * height * GetPixelBytes(format)` gets the naive (unaligned) size, while the actual memory system uses the canonical (aligned) size.

## Vulnerable Code

**`frameworks/kits/js/common/auxiliary_picture_napi.cpp:839`**
```cpp
context->arrayBufferSize = info.size.width * info.size.height * ImageUtils::GetPixelBytes(info.pixelFormat);
context->arrayBuffer = new uint8_t[context->arrayBufferSize];
context->rAuxiliaryPicture->ReadPixels(context->arrayBufferSize, context->arrayBuffer);
// ReadPixels writes canonical bytes → overflow if w % 4 != 0
```

`frameworks/innerkitsimpl/converter/src/pixel_convert.cpp` uses the same naive pattern.

## Evidence

Verified counterexamples (naive vs canonical allocation delta):

| Width | Height | Naive size | Canonical size | Overflow delta |
|---|---|---|---|---|
| 133 | 124 | 16,492 | 16,864 | **+372 bytes** |
| 7 | 188 | 1,316 | 1,504 | **+188 bytes** |
| 9 | 23 | 207 | 276 | **+69 bytes** |

The overflow is silent at small widths and grows with image dimensions.

## PBT Detection

Detected by `extracted_pbt/extracted_property_tests.cpp` → `run_imageutils_tests()` (lines 266–297).

**Property tested:** For every pixel format, `naive(w,h) == canonical(w,h)` should hold.
**Violation:** `ALPHA_8` fails whenever `w % 4 != 0`.

The test generates 1000 random `(w, h)` pairs across 10 formats and flags mismatches, printing up to 10 counterexamples with the naive vs canonical delta.

## Impact

- **Heap buffer overflow**: undersized allocation written by production NAPI path
- **No bounds check in callers**: naive formula used directly for `new[]` allocation
- **Affects JS NAPI boundary**: any app using `PixelFormat.ALPHA_8` with width not divisible by 4
- Silent at small widths, catastrophic at large widths

## Fix Options

1. Make `GetPixelBytes(ALPHA_8)` return 4 (aligned interpretation) — aligns both functions
2. Deprecate `GetPixelBytes()` for buffer sizing; require `GetByteCount()` / `GetRowDataSizeByPixelFormat()` only
3. Fix all naive callers to use the aligned path explicitly
