## Summary

`DataPanelModifier::GetPaintPath()` computes the circle-cap angle for the
progress track as:

```cpp
float sine = thickness * 0.5f / (radius - thickness * 0.5f);
float radian = asin(sine);
arcData.circleAngle = radian * 180 / PI;
```

There is no domain guard. `PaintCircle()` derives
`radius = min(w, h) * 0.5f - strokeWidth`, so a public `SetStrokeWidth` value
at or above half the content min side drives `radius <= 0`. The fallback
`thickness = radius * 0.12` still leaves `radius <= 0`, producing `0/0` or
`|sine| > 1`, and `asin` returns **NaN**. `circleAngle` then poisons the arc
geometry (broken or missing arcs).

## Vulnerable Code

`frameworks/core/components_ng/pattern/data_panel/data_panel_modifier.cpp`:

- `PaintCircle` (~152–163): `arcData.radius = min(w, h) * 0.5f - defaultThickness;`
  with fallback `arcData.thickness = arcData.radius * 0.12f` — useless once
  `radius <= 0`.
- `GetPaintPath` (~265–269): unguarded `asin` ratio shown above.

## Contract

- `circleAngle` feeds arc geometry → must be **finite**.
- Geometry requires `radius > thickness/2` (denominator > 0) and `|sine| <= 1`.
- In-tree siblings already clamp **before** the ratio:
  - Progress ring (`progress_modifier.cpp` `CalcRingProgressAdditionalAngle`
    ~647–651): clamps `strokeWidth` when `strokeWidth + shadowBlurOffset >= radius`.
  - Legacy DataPanel (`rosen_render_data_panel.cpp` ~789–793):
    `if (diameter <= thickness) thickness = diameter * 0.1;` before `asin`.

The NG DataPanel path is the only member of this ratio family with no guard.

## Minimal Counterexample

```text
minSide = 100, strokeWidth = 50
radius  = 100 * 0.5 - 50 = 0
thickness fallback: 0 * 0.12 = 0
sine    = 0 / (0 - 0) = 0/0 -> NaN
circleAngle = asin(NaN) -> NaN
```

Any `strokeWidth >= minSide/2` collapses `radius` to 0 or below.

## How PBT Detected This

Harness: `pbt-native/data_panel_sine_radius_pbt_test.cpp` (faithful excerpt of
the three production formulas).

| Safe domain | `SafeDomainFinite` / `ModestStrokeOk` | PASS |

## Impact

Circle DataPanel with stroke width >= ~half the content min side renders
broken/missing arcs (NaN-driven geometry). Modest stroke widths are unaffected.
`SetStrokeWidth` is public and accepts any Dimension; the model applies no
clamp against content size. Visual/paint corruption — not a proven crash or
security issue.

## Suggested Fix

Validate geometry **before** the ratio, matching the Progress/legacy siblings:

```cpp
float halfT = thickness * PERCENT_HALF;
float denom = radius - halfT;
if (!(radius > 0.0f) || !(denom > 0.0f)) {
    arcData.circleAngle = 0.0f;
} else {
    float sine = std::clamp(halfT / denom, -1.0f, 1.0f);
    arcData.circleAngle = std::asin(sine) * HALF_CIRCLE / ACE_PI;
}
```
