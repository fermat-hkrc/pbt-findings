## Summary

Four parse sites in `CloudDiskRdbStore` gate on
`all_of(value.begin(), value.end(), ::isdigit)` and then call bare
`std::stoi`:

- `HasTHMSetXattr` (~1010) — HAS_THM/LCD flag `0`/`1`
- `RecycleSetXattr` (~1267) — recycle/restore option
- `FavoriteSetXattr` (~1530) — favorite `0`/`1`
- `GetUserIdAndBundleName` (~2621) — `userIdStr` after `GenParams`

"All characters are digits" ≠ "value fits in `int`": `""` is vacuously
all-digits (empty range) and throws `std::invalid_argument`; a 20-digit
string throws `std::out_of_range`. All four sites are on the live
`SetXattr` / dentry path, so the exception is uncaught → `terminate` /
crash.

The correct fail-closed sibling is `LocationSetXattr` (~893): reject with
an error code, never throw.

Confirmed and fixed under `DTS2026080808589` (internal DTS system): digit
gates additionally reject empty strings and the parses use no-throw
`strtol`-style conversion.

## Vulnerable Code

```cpp
if (!all_of(value.begin(), value.end(), ::isdigit)) {   // "" passes vacuously
    return E_INVAL_ARG;
}
int32_t val = std::stoi(value);   // "" → invalid_argument; >INT_MAX digits → out_of_range
if (val != 0 && val != 1) { ... } // never reached when stoi throws
```

## Trigger Conditions

Any `CloudDiskRdbStore::SetXattr` (THM / recycle / favorite) or dentry
helper call whose `value` / `userIdStr` is empty or an all-digit string
beyond `INT_MAX`.

## Impact

Medium — uncaught-exception crash on the live xattr/userId path; intended
values are small flags, so it needs empty or deliberately long digit
input (not High).

## Minimal Counterexample

```
HasTHMSetXattr(name, parent, cloudId, "")          // stoi("") throws
HasTHMSetXattr(name, parent, cloudId, "999...9")   // 20 digits → out_of_range
```

## How PBT Detected This

Negative / error-contract property on the parse gate: for every string,
the live xattr/userId parse either returns a value or an error code —
never throws. Empty and >`INT_MAX` all-digit strings shrink out as the
minimal violators of the "digits ⇒ parseable" assumption.

## Suggested Fix

Fail closed like `LocationSetXattr`: reject empty early
(`value.empty() ||`) and parse without exceptions
(`strtol(value.c_str(), nullptr, 10)`).
