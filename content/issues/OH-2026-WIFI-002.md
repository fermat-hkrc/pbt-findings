## Summary

`StateMachineHandler::GetCurStateName` indexes `mStateVector[mStateVectorTopIndex]`
with no bounds check. The ctor leaves the stack empty and `mStateVectorTopIndex = -1`,
so the existing `curStateInfo == nullptr` / `return ""` path is never reached —
`operator[](-1)` is UB / SEGV first.

Same-file sibling `CallTreeStateExits` already guards `mStateVectorTopIndex >= 0`
before indexing the same vector. Wrapper `StateMachine::GetCurStateName` returns
`""` when there is no handler.

Confirmed and fixed under `DTS2026073028465` (upstream !5516, `multilink状态机crash`).

## Vulnerable Code

`wifi/base/state_machine/src/state_machine.cpp` — `GetCurStateName` (~725):

```cpp
std::string StateMachineHandler::GetCurStateName()
{
    StateInfo *curStateInfo = mStateVector[mStateVectorTopIndex];  // -1 → OOB
    if (curStateInfo == nullptr) {
        LOGE("StateInfo is null.");
        return "";
    }
    return curStateInfo->state->GetStateName();
}
```

Ctor (`:307`): `mStateVectorTopIndex = -1`. `CallTreeStateExits` (`:694`):

```cpp
while ((mStateVectorTopIndex >= 0) &&
       (mStateVector[mStateVectorTopIndex] != commonStateInfo)) {
```

## Trigger Conditions

Any `GetCurStateName` before `StartStateMachine` (stack still empty):

1. Fresh handler (ctor, never started).
2. `BuildTreeComplete` without `SetFirstState`.
3. Failed `InitRptManagerStates` (OOM) — `MakeRptManager` ignores `InitRptManager()`
   and still `AddManager`; later `IsRptRunning` queries the empty stack.

After a successful `Start`, the stack holds `IdleState` — that path is fine.
Unready ≠ empty stack. Field crash was on the multilink state machine (!5516).

## Impact

- SEGV on `mStateVector[-1]` (fork probe, no ASan required).
- `IsRptRunning` (`rpt_manager.cpp:74–77`) and self-cure name compares are
  live callers; empty name should mean `false`, not crash.
- High: real crash on an unready machine, confirmed by upstream as
  `multilink状态机crash`.

`ExecuteTreeStateMsg` (`:674`) still has the same unguarded index — not this DTS.

## Minimal Counterexample

```cpp
StateMachine sm;
StateMachineHandler h(&sm);
h.GetCurStateName();  // SEGV, expected ""
```

## Suggested Fix

Shipped in !5516 — same predicate as `CallTreeStateExits`:

```cpp
std::string StateMachineHandler::GetCurStateName()
{
    if (mStateVectorTopIndex < 0) {
        return "";
    }
    StateInfo *curStateInfo = mStateVector[mStateVectorTopIndex];
    if (curStateInfo == nullptr) {
        LOGE("StateInfo is null.");
        return "";
    }
    return curStateInfo->state != nullptr ? curStateInfo->state->GetStateName() : "";
}
```
