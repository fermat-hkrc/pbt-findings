## Summary

`CameraManager::ParsingCameraConcurrentLimted` walks
`OHOS_ABILITY_CAMERA_LIMITED_CAPABILITIES` as length-prefixed records
`(tag, length, payload[0..length-1])*`. It reads `originInfo[i+1]` as
`length` then payload at `i+2…` with no `i+1 < count` /
`i+2+length <= count` → heap **OOB** / huge advance. Helpers
`GetAbilityStructofConcurrentLimted*` blindly loop `for (k < length)`.
Zoom-ratio branch also look-aheads `j+1`/`j+2` inside that window.

Not High: well-formed TLVs OK. Same hygiene gap as
`QueryZoomPerformance` (different tag/layout). Confirmed and fixed by
developers (`DTS2026080813868`).

## Vulnerable Code

`frameworks/native/camera/base/src/input/camera_manager.cpp` —
`ParsingCameraConcurrentLimted` (~1958–1965) and helpers (~2033–2049):

```cpp
for (int32_t i = 0; i < static_cast<int32_t>(count);) {
    if (tag == OHOS_ABILITY_FLASH_MODES) {
        int length = static_cast<int32_t>(originInfo[i + STEP_ONE]); // need i+1 < count
        GetAbilityStructofConcurrentLimted(vec, originInfo + i + STEP_TWO, length);
        // helper: for (k = 0; k < length; k++) vec.push(originInfo[k]);
        i = i + length + STEP_TWO + STEP_ONE;
    } else if (tag == OHOS_ABILITY_ZOOM_RATIO_RANGE) {
        int length = static_cast<int32_t>(originInfo[i + STEP_ONE]);
        for (int j = i + STEP_TWO; j < i + length + STEP_TWO + STEP_ONE; j += STEP_THREE) {
            … originInfo[j], originInfo[j + 1], originInfo[j + 2];
        }
        i = i + length + STEP_TWO + STEP_ONE;
    }
    // AE / focus / stabilization: same length-prefix shape
}
```

Defects: length look-ahead, payload trust of `length`, advance
`i += length + 3` (negative `length` after cast → backward step).

## Trigger Conditions

1. Concurrent-limited HAL blob is short vs claimed `length`, or `length`
   is huge / negative after `int32` cast.
2. `GetCameraConcurrentInfos` parses limited capabilities.
3. `originInfo[i+1]` or helper payload walk reads past `count`.

## Impact

- Heap OOB / over-advance while parsing flash / exposure / AE / focus /
  stabilization / zoom-ratio limited-capability records.
- Medium: well-formed TLVs unaffected; field hit needs malformed
  concurrent-limited metadata. Not app-crafted input.
- One remaining-length helper covers every length-prefix branch.

## Minimal Counterexample

| blob / state | Production |
|--------------|------------|
| well-formed `(tag,len,payload…)` | OK |
| `count == 1` (tag only) | **OOB** on `originInfo[i+1]` |
| `len` > remaining after header | **OOB** in helper / zoom triple |
| `len` high bit set → negative | backward `i` / **OOB** |

```bash
./pbt-native/build/concurrent_limited_tlv_pbt_test
```

## Suggested Fix

Bound header + payload before every branch (prefer one helper):

```cpp
if (i + 1 >= static_cast<int32_t>(count)) break;
int length = static_cast<int32_t>(originInfo[i + STEP_ONE]);
if (length < 0 ||
    static_cast<int64_t>(i) + STEP_TWO + length > static_cast<int64_t>(count)) {
    break;
}
// then GetAbility… / zoom triple walk inside that window
i = i + length + STEP_TWO + STEP_ONE;
```

Zoom triples: `j + 2 < i + 2 + length`. After fix: short/lying-`len`
props PASS; well-formed stay PASS.
