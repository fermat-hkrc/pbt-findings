## Summary

`FloatToHalf` packs `float` channels into IEEE-754 **binary16** bits for
`RGBA_F16` format conversion. For exact ±0.0f inputs, the magnitude bits are
zero, and the rebase subtract `(magnitude >> 13) - 0x1C000` underflows as an
unsigned operation. The low 16 bits of the underflow result are `0x4000` — the
IEEE half encoding of **+2.0**, not the required `+0` (`0x0000`). Pure black
(`0.0f`) and fully transparent (`0.0f` alpha) become half `2.0`, which decodes
back to wrong elevated channel values. Normal floats (e.g. `1.0f`, `2.0f`)
with non-zero shifted magnitude are unaffected. Not High: silent wrong
channel value on every `* → RGBA_F16` encode path; no crash/OOB. Confirmed
and fixed by developers (`DTS2026081417372`).

## Vulnerable Code

`frameworks/innerkitsimpl/converter/include/pixel_convert.h`, lines 155–163:

```cpp
static inline uint16_t FloatToHalf(float f)
{
    uint32_t u32 = FloatToUint(f);
    uint16_t u16 = static_cast<uint16_t>(
        (((u32 & MAX_31_BIT_VALUE) >> SHIFT_HALF_BIT) - SHIFT_7_MASK) & MAX_16_BIT_VALUE);
    //     (magnitude >> 13) - 0x1C000
    u16 |= static_cast<uint16_t>(
        ((u32 & SHIFT_32_MASK) >> SHIFT_16_BIT) & MAX_16_BIT_VALUE);  // sign bit OR
    return u16;
}
```

For exact ±0.0f, `u32 & MAX_31_BIT_VALUE` is zero:

```text
(0 >> 13) - 0x1C000  →  0 - 114688  (unsigned underflow)
→ low 16 bits 0x4000  →  IEEE half +2.0, not +0
```

Sign bit is OR-ed afterward, so `-0.0f` becomes `0xC000` (−2.0).

Callers: `FillRGBAF16` → every `*ConvertRGBAF16` path in `pixel_convert.cpp`
(~183–188). Production inputs include channel `0` (pure black) and alpha `0`
(fully transparent). Also `pixel_map.cpp` set-pixel via `FloatToHalf`.

## Trigger Conditions

1. `* → RGBA_F16` conversion runs (live path).
2. A channel value is exactly `+0.0f` or `-0.0f`.

Floats with any non-zero shifted magnitude (including subnormals with enough
bits set) do not underflow — only exact zero triggers this bug.

## Impact

- Pure black `0.0f` channels encode as half `2.0` → decode back to `2`, not `0`.
- Fully transparent `0.0f` alpha encodes as half `2.0` → non-zero alpha bits.
- Silent wrong value on every live `* → RGBA_F16` encode path.
- Medium: wrong channel values on production path; no crash/OOB.

## Minimal Counterexample

| Input | Expected half | Actual half | Decoded value |
|------:|--------------:|------------:|---------------:|
| `+0.0f` | `0x0000` (+0) | **`0x4000`** | **`2.0`** |
| `-0.0f` | `0x8000` (−0) | **`0xC000`** | **`−2.0`** |
| `1.0f` | `0x3C00` | `0x3C00` | `1.0` (OK) |
| `2.0f` | `0x4000` | `0x4000` | `2.0` (OK, same bits as buggy zero) |

## How PBT Detected This

`pbt-native/float_to_half_pbt_test.cpp` — includes the REAL `pixel_convert.h`
(**not** a model):

```cpp
RC_PROPERTY(ZeroEncodesAsHalfZero, [&](float f) {
    RC_PRE(f == 0.0f);
    uint16_t got = sut.FloatToHalf(f);
    uint16_t expected = std::signbit(f) ? 0x8000u : 0x0000u;  // IEEE half zero
    RC_ASSERT(got == expected);
});

RC_PROPERTY(U8ChannelDomainPreservesValue, [&](uint8_t u8) {
    // Encode u8/255 as half, decode back via HalfToFloat
    float f = static_cast<float>(u8) / 255.0f;
    uint16_t half = sut.FloatToHalf(f);
    float decoded = sut.HalfToFloat(half);
    RC_ASSERT(u8 == static_cast<uint8_t>(std::round(decoded * 255.0f)));
});
```

Shrunk witness: `f = 0.0f` → `FloatToHalf` returns `0x4000` (half 2.0).

```bash
cmake -S pbt-native -B pbt-native/build -DCMAKE_BUILD_TYPE=Release
cmake --build pbt-native/build -j --target float_to_half_pbt_test
./pbt-native/build/float_to_half_pbt_test
```

## Suggested Fix

Handle IEEE ±0.0f before the rebase subtract to avoid unsigned underflow:

```diff
 static inline uint16_t FloatToHalf(float f)
 {
     uint32_t u32 = FloatToUint(f);
+    // ±0.0f: magnitude bits are 0 — do not run the rebase subtract (underflows to 0x4000).
+    if ((u32 & MAX_31_BIT_VALUE) == 0) {
+        return static_cast<uint16_t>((u32 >> SHIFT_16_BIT) & 0x8000u);  // +0 → 0x0000, -0 → 0x8000
+    }
     uint16_t u16 = static_cast<uint16_t>(
         (((u32 & MAX_31_BIT_VALUE) >> SHIFT_HALF_BIT) - SHIFT_7_MASK) & MAX_16_BIT_VALUE);
     u16 |= static_cast<uint16_t>(
         ((u32 & SHIFT_32_MASK) >> SHIFT_16_BIT) & MAX_16_BIT_VALUE);
     return u16;
 }
```

After fix: `FloatToHalf(0.0f) == 0x0000`, `FloatToHalf(-0.0f) == 0x8000`. Normal
float path unchanged.
