## Summary

`WindowHelper::IsAspectRatioSatisfiedWithSizeLimits` subtracts the decor frame
from size-limit mins/maxes with bare `uint32_t` arithmetic. When
`minWidth_`/`minHeight_` are below the decor frame (default mins = 1), the
subtract underflows, the achievable ratio band inverts, and **every** finite
positive ratio is rejected. Caller `WindowController::SetAspectRatio` then
returns `WM_ERROR_INVALID_PARAM`.

Same product already saturates this subtract in `WindowLimits::Clip`
(`safeSub`). Empty limits / near-zero ratio still short-circuit to `true` (by
design). Confirmed and fixed by developers (`DTS2026072347788`).

## Vulnerable Code

`utils/include/window_helper.h` — `IsAspectRatioSatisfiedWithSizeLimits` (~670):

```cpp
uint32_t winFrameW = static_cast<uint32_t>(WINDOW_FRAME_WIDTH * vpr) * 2;
uint32_t winFrameH = static_cast<uint32_t>(WINDOW_FRAME_WIDTH * vpr) +
    static_cast<uint32_t>(WINDOW_TITLE_BAR_HEIGHT * vpr);
uint32_t maxWidth  = sizeLimits.maxWidth_  - winFrameW;  // bare uint32 sub
uint32_t minWidth  = sizeLimits.minWidth_  - winFrameW;  // underflows when min < frame
uint32_t maxHeight = sizeLimits.maxHeight_ - winFrameH;
uint32_t minHeight = sizeLimits.minHeight_ - winFrameH;
float maxRatio = static_cast<float>(maxWidth)  / static_cast<float>(minHeight);
float minRatio = static_cast<float>(minWidth)  / static_cast<float>(maxHeight);
if (maxRatio < ratio || ratio < minRatio) {
    return false;
}
```

Caller: `WindowController::SetAspectRatio` (`wmserver/src/window_controller.cpp`).

Root cause: no saturating subtract. When `min* < winFrame*`, unsigned wrap makes
`maxRatio < minRatio`, so every finite positive ratio fails.

## Trigger Conditions

1. Size limits still have mins below the decor frame (default
   `minWidth_ = minHeight_ = 1`; decor at `vpr ≥ 1` is W ≥ 10, H ≥ 53 from
   `WINDOW_FRAME_WIDTH = 5`, `WINDOW_TITLE_BAR_HEIGHT = 48`).
2. App calls `SetAspectRatio` with a normal ratio (e.g. `1.0`).
3. Bare decor subtract wraps; inverted band rejects the ratio →
   `WM_ERROR_INVALID_PARAM`.

Partial mask: once layout raises mins above the decor frame, bare subtract
stops wrapping and agrees with a saturating oracle. Bug remains on the
default / small-min window.

## Impact

- **`SetAspectRatio` rejects valid ratios** while updated limits still have mins
  below decor (default / early / small-min paths).
- After underflow the ratio band is inverted — not only exotic ratios fail.
- Medium: wrong API bool + invalid-param to app; no crash.

## Minimal Counterexample

```
limits: default { max = INT32_MAX, min = 1 }
vpr:    1.0
ratio:  1.0

winFrameW = 10, winFrameH = 53

Production:
  minWidth  = 1 - 10  → 4294967287   // wrap
  minHeight = 1 - 53  → 4294967244
  maxRatio  ≈ maxWidth / minHeight ≈ 0.5
  minRatio  ≈ minWidth / maxHeight ≈ 2.0
  // inverted band → ratio 1.0 rejected → false

Expected (saturating sub):
  content mins → 0 → maxRatio = +∞, minRatio = 0 → ratio 1.0 accepted → true
```

## Suggested Fix

Reuse `WindowLimits::Clip`'s saturating subtract; guard zero content extent
before divide:

```cpp
auto safeSub = [](uint32_t base, uint32_t dec) -> uint32_t {
    return (dec >= base) ? 0u : base - dec;
};
uint32_t maxWidth  = safeSub(sizeLimits.maxWidth_,  winFrameW);
uint32_t minWidth  = safeSub(sizeLimits.minWidth_,  winFrameW);
uint32_t maxHeight = safeSub(sizeLimits.maxHeight_, winFrameH);
uint32_t minHeight = safeSub(sizeLimits.minHeight_, winFrameH);
if (maxWidth == 0 || maxHeight == 0) {
    return false;  // no positive content box
}
float maxRatio = (minHeight == 0)
    ? std::numeric_limits<float>::infinity()
    : static_cast<float>(maxWidth) / static_cast<float>(minHeight);
float minRatio = static_cast<float>(minWidth) / static_cast<float>(maxHeight);
```

After fix: `DefaultLimitsAcceptsUnitRatio`, `UnderflowRejectsValidRatio`,
`MatchesOracle` → PASS; empty/zero-ratio and large-min props stay green.
