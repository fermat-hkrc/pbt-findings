## Summary

`Matrix::SetTranslate` stores translation floats correctly but tags
`operType = IDENTITY` when **either** axis is zero (`tx == 0 || ty == 0`).
Dispatch keys off `operType`, so pure-X or pure-Y pans are treated as a
**no-op** by `GetXYProc` / `IdentityXY` / `Invert`. Axis-aligned pans are the
common case. Both axes nonzero still OK. Sibling `SetScale` correctly uses
**both-axes** identity: `(sx == 1 && sy == 1)`.

High = wrong image geometry on common axis-aligned pan when this Matrix stack
is used — not process crash. Confirmed and fixed by developers
(`DTS2026073015200`).

## Vulnerable Code

`frameworks/innerkitsimpl/converter/src/matrix.cpp` — `SetTranslate` (~35):

```cpp
*this = Matrix(1, 0, tx, 0, 1, ty, 0, 1, 1,
    (tx == 0 || ty == 0) ? IDENTITY : TRANSLATE);  // || wrong — either axis 0 → IDENTITY

// sibling SetScale ~41-45 — correct connective
*this = Matrix(..., (sx == 1 && sy == 1) ? IDENTITY : SCALE);
```

`fMat_` still holds `(tx, ty)`. `TransXY` only runs when `operType == TRANSLATE`;
`IdentityXY` / `Invert` `IsIdentity()` when `operType == 0` ignore translation.

Consumers: `GetXYProc` → `IdentityXY` / `TransXY`; `Invert`; 
`BasicTransformer::SetTranslateParam` → concat / map / `GetDstDimension`;
`post_proc` translate path.

Root cause: wrong connective — “either axis zero” ≠ “no translation.”

## Trigger Conditions

1. Caller invokes `SetTranslate(tx, ty)` with exactly one of `tx`, `ty` nonzero
   (pure-X or pure-Y pan).
2. Matrix is tagged `IDENTITY` despite non-zero translation in `fMat_`.
3. Downstream map / invert / dimension paths take the identity early-out →
   pan is a no-op.

## Impact

| Path | Result |
|------|--------|
| Pure-X / pure-Y `SetTranslate` then `GetXYProc` / pixel map loop | **no-op** transform |
| `Invert` on axis translate | identity early-out → inv not `-t` |
| `GetDstDimension` TRANSLATE bit | may **skip** size expand for one-axis pan |
| `SetTranslate(tx,ty)` both nonzero | OK |
| `GetTransX/Y` | still return stored floats (latent; dispatch wrong) |

Honest limits:
- High = **wrong image geometry** on common axis-aligned pan — not SA crash.
- Skia / other `pixel_map` matrix types out of scope; this is
  `converter/matrix.cpp`.

## Minimal Counterexample

| Call | Expected | Actual |
|------|----------|--------|
| `SetTranslate(5, 0)` | TRANSLATE; `(10,20)→(15,20)`; inv `tx=-5` | **IDENTITY**; point unchanged; inv identity |
| `SetTranslate(0, 7)` | TRANSLATE | **IDENTITY** |
| `SetTranslate(5, 7)` | TRANSLATE | OK |
| `SetTranslate(0, 0)` | IDENTITY | OK |

cmake -S pbt-native -B pbt-native/build -DCMAKE_BUILD_TYPE=Release
cmake --build pbt-native/build -j --target matrix_axis_translate_bugs_pbt_test

## Suggested Fix

Match `SetScale` both-axes pattern:

```cpp
*this = Matrix(1, 0, tx, 0, 1, ty, 0, 1, 1,
    (tx == 0 && ty == 0) ? IDENTITY : TRANSLATE);
```

After fix: axis-translate props → PASS; `(0,0)` stays IDENTITY.
