## Summary

`CheckIpv6InNet` (PAC `isInNetEx`) has **no `prefixLen` bounds check** before
indexing `in6_addr.s6_addr`. The caller `JsIsInNetEx` feeds it raw
`atoi(slash + 1)` from untrusted PAC script text.

- **Negative** CIDR (`prefixLen < 0`) → loop skipped, bits ≤ 0 → **silent
  match-all** → wrong proxy allow/deny decision.
- **`prefixLen ≥ 129`** → `bytes ≥ 16` → **`s6_addr[16]` OOB** (ASan/debug
  visible; release = UB result).

The same file already fixed the **IPv4 twin** `CheckIpv4InNet`
(`DTS2026070856960` / OH-2026-NET-002) with `prefixLen ∈ [0,32]` + `/0`
special case; **IPv6 was left unguarded**. Confirmed and fixed by developers
(`DTS2026081135903`).

Not High: needs hostile or buggy PAC text; well-formed `/0`–`/128` works; OOB
is not a guaranteed release crash without sanitizers.

## Vulnerable Code

`services/netconnmanager/src/pac_functions.cpp` — `CheckIpv6InNet` (~940–960):

```cpp
// production CheckIpv6InNet — no bounds
int bytes = prefixLen / 8;
int bits  = prefixLen % 8;
for (int i = 0; i < bytes; i++)
    if (ipAddr.s6_addr[i] != netAddr.s6_addr[i]) return false;
if (bits > 0)
    return (ipAddr.s6_addr[bytes] & mask) == ...;  // bytes==16 → OOB
return true;  // negative: loop skipped, bits<=0 → match-all
```

Caller: `PacFunctions::JsIsInNetEx` — `atoi` of the CIDR prefix with no clamp.
Live path: `FindProxyForURL` → PAC `isInNetEx` → `JsIsInNetEx` →
`CheckIpv6InNet`.

Root cause: no `prefixLen ∈ [0,128]` guard before indexing `s6_addr`. IPv4
twin already has the guard; IPv6 was not updated in the same fix.

## Trigger Conditions

1. PAC script calls `isInNetEx(host, "net/<prefix>")` with a non-canonical
   prefix (negative string, or `≥129`).
2. `JsIsInNetEx` parses prefix via `atoi` and calls `CheckIpv6InNet`.
3. Negative → match-all `true`; `≥129` → OOB on `s6_addr[bytes]`.

Unaffected: well-formed `/0`–`/128`; IPv4 `isInNet` / `CheckIpv4InNet` (already
bounded after OH-2026-NET-002).

## Impact

| Path | Result |
|------|--------|
| PAC `isInNetEx(ip, "net/-1")` | silent **match-all** → wrong allow on proxy decision |
| PAC `isInNetEx(ip, "net/129")` | stack OOB on PAC/net process (sanitizer-visible; release = UB) |
| Valid `/0`–`/128` | works |
| What masks it | nothing on the PAC path — `atoi` is the only parse |

Honest limits:
- Medium — needs bad PAC text; not every proxy lookup.
- Match-all is the stronger product effect (silent wrong proxy decision).
- OOB is real but not a guaranteed field crash without ASan.
- Why not High / Med–High: hostile-or-buggy script required; IPv4 already fixed.

## Minimal Counterexample

| prefixLen | Expected | Actual |
|----------:|----------|--------|
| `-1` | `false` | **`true` (match-all)** |
| `129` | `false` | **`s6_addr[16]` OOB** (then UB result) |
| `0..128` | compare | OK |

```text
CheckIpv6InNet("2001:db8::1", "fe80::1", -1)  → true   // should false
CheckIpv6InNet("::", "::", 129)               → OOB    // should false
PAC: isInNetEx(host, "fe80::/-1")             → atoi=-1
```

## How PBT Detected This

Source-cited residual against production `pac_functions.cpp` using the fixed
IPv4 sibling as local oracle. Harness
`pbt-native/check_ipv6_in_net_pbt_test.cpp` is a placeholder (empty gtest);
defect is not a linked-SUT PBT FAIL.

Host structural probe:

| Case | Result |
|------|--------|
| `prefix=-1` | **`true` (match-all)** |
| `129` / `255` | **would OOB** |
| `0..128` | OK |

## Suggested Fix

Mirror IPv4 `CheckIpv4InNet` — one guard after `inet_pton`, before any
`s6_addr` index:

```cpp
static bool CheckIpv6InNet(const char *ip, const char *cidr, int prefixLen)
{
    const int ipv6Bits = 128;
    struct in6_addr ipAddr;
    struct in6_addr netAddr;
    if (inet_pton(AF_INET6, ip, &ipAddr) != 1 ||
        inet_pton(AF_INET6, cidr, &netAddr) != 1) {
        return false;
    }
    if (prefixLen < 0 || prefixLen > ipv6Bits) {
        return false;
    }
    // ... existing byte/bit compare ...
}
```

| After fix | Result |
|-----------|--------|
| `prefixLen < 0` or `> 128` | `false` (no match-all, no OOB) |
| `0..128` | unchanged byte/bit compare |
