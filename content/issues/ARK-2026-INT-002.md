## Summary

The container constructor of `ark::verifier::Range<Int>` computes `to_` as
`cont.size() - 1`. When the container is empty, `cont.size()` returns `0` and
the subtraction underflows in `size_t` unsigned arithmetic, producing
`SIZE_MAX`. The resulting range spans `[0, SIZE_MAX]` and `Contains` returns
`true` for every value representable by `Int`, even though the container has
zero elements. Additionally, `Length()` wraps back to `0`, leaving the object
internally contradictory: a range of length 0 that claims to contain everything.

## Contract

`static_core/verification/util/range.h:~146`:

```cpp
template <typename Container>
Range(const Container &cont) : from_ {0}, to_ {cont.size() - 1}
{
}
```

A `Range` constructed from a container of `n` elements must represent exactly
the index span `[0, n-1]`. For `n == 0` the range must be empty: `Contains`
must return `false` for every point and `Length()` must return `0`.

## Vulnerable Code

```cpp
template <typename Container>
Range(const Container &cont) : from_ {0}, to_ {cont.size() - 1}
//                                              ^^^^^^^^^^^^^^^^
//                                              BUG: 0 - 1 underflows to SIZE_MAX when cont is empty
{
}
```

`Contains` then evaluates `0 <= x && x <= SIZE_MAX`, which is unconditionally
`true` for any `size_t` value:

```cpp
bool Contains(Int point) const
{
    return point >= from_ && point <= to_;  // always true when to_ == SIZE_MAX
}
```

## Root Cause

The member initialiser computes `cont.size() - 1` without guarding against an
empty container. `size()` returns `size_t` (unsigned), so the subtraction
underflows silently rather than producing a negative sentinel that would make
the range appear empty.

## Minimal Counterexample

```cpp
std::vector<int> empty;
ark::verifier::Range<size_t> r(empty);

r.Contains(0);    // → true   (expected false)
r.Contains(5);    // → true   (expected false)
r.Contains(99);   // → true   (expected false)
r.Length();       // → 0      (contradicts Contains — internal inconsistency)
```

## When the Bug Triggers

Any `Range<Int>` constructed from an empty container. The underflow is
unconditional; there is no combination of compiler flags or optimisation levels
that avoids it.

## Why Existing Tests Missed It

No existing test constructs a `Range` from an empty container and then calls
`Contains`. Example-based tests used non-empty containers, leaving the
empty-container path unexercised.

## How PBT Detected This

A RapidCheck property generated random `std::vector<int>` values (including
empty ones) and asserted that a container-constructed `Range` must not contain
any index outside `[0, size-1]`. The empty-container case was the immediate
falsifying input; RapidCheck shrunk it to the minimal witness above.

The dedicated `BugDocs` regression test pins the requirement explicitly:

```cpp
TEST(RangePbt_BugDocs, EmptyContainerContainsNothing)
{
    std::vector<int> empty;
    ark::verifier::Range<size_t> r(empty);
    EXPECT_FALSE(r.Contains(0));
    EXPECT_FALSE(r.Contains(1));
    EXPECT_FALSE(r.Contains(100));
    EXPECT_EQ(r.Length(), 0u);
}
```

Result on an unfixed branch:

```
[ RUN      ] RangePbt_BugDocs.EmptyContainerContainsNothing
Expected: r.Contains(0) is false
  Actual: it's true
[  FAILED  ] RangePbt_BugDocs.EmptyContainerContainsNothing
```

## Impact

`Range` is used throughout the Panda verifier for index, address, and type-span
checks. A range constructed from an empty container accepting every value can
cause the verifier to pass checks that should reject all inputs for an empty
structure — a correctness bug on a verifier code path. Not a memory safety
defect, but a silent logic error with no crash or error signal.

## Suggested Fix

Guard the empty case explicitly, leaving `to_` below `from_` so `Contains`
correctly returns `false` for all points:

```cpp
template <typename Container>
Range(const Container &cont)
{
    if (cont.empty()) {
        from_ = 0;
        to_   = static_cast<Int>(-1);  // to_ < from_ → Contains always false
    } else {
        from_ = 0;
        to_   = static_cast<Int>(cont.size() - 1);
    }
}
```
