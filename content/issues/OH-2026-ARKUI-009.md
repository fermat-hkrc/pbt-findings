## Summary

`Matrix3N::SetEntry` and `MatrixN3::SetEntry` are the checked writers for
`std::vector` 3×N / N×3 matrices. Out-of-range indices must return `false`
and leave the matrix unchanged. Both guards are **upper bound only**:

```cpp
// Matrix3N
if (row >= DIMENSION || col >= columns_) return false;
Matrix3n_[row][col] = value;

// MatrixN3
if (row >= rows_ || col >= DIMENSION) return false;
Matrixn3_[row][col] = value;
```

`row < 0` / `col < 0` fall through. A negative `int32_t` becomes a huge
`size_t` subscript → OOB write. Product `-O3 -DNDEBUG`: `SetEntry(-1, 0, v)`
SIGSEGV; `SetEntry(0, -1, v)` heap abort. Same-file `Matrix3::SetEntry` and
the 4×N / N×4 siblings already reject negatives. Confirmed and fixed under
`DTS2026091012206`.

## Contract

`bool SetEntry(int32_t row, int32_t col, double value)` — signed indices,
boolean reject (not `ACE_DCHECK` / abort).

- `Matrix3N`: `(row < 0 ∨ row ≥ 3 ∨ col < 0 ∨ col ≥ columns_)` ⇒ `false`, no write
- `MatrixN3`: `(row < 0 ∨ row ≥ rows_ ∨ col < 0 ∨ col ≥ 3)` ⇒ `false`, no write

Pinned by `Matrix3::SetEntry`, `Matrix4N::SetEntry`, `MatrixN4::SetEntry`,
and `matrix4_test.cpp` (`SetEntry(INVALID_ROW_NEG, …)` must be `false`).

## Vulnerable Code

`frameworks/base/geometry/matrix3.cpp`:

```cpp
bool Matrix3N::SetEntry(int32_t row, int32_t col, double value)
{
    if (row >= DIMENSION || col >= columns_) {   // no row < 0 / col < 0
        return false;
    }
    Matrix3n_[row][col] = value;
    return true;
}

bool MatrixN3::SetEntry(int32_t row, int32_t col, double value)
{
    if (row >= rows_ || col >= DIMENSION) {
        return false;
    }
    Matrixn3_[row][col] = value;
    return true;
}
```

## Minimal Counterexample

```cpp
Matrix3N a(4);
a.SetEntry(-1, 0, 1.0);  // Expected: false, unchanged; Actual: SIGSEGV
a.SetEntry(0, -1, 1.0);  // Expected: false, unchanged; Actual: heap abort

MatrixN3 b(4);
b.SetEntry(-1, 0, 1.0);  // SIGSEGV
b.SetEntry(0, -1, 1.0);  // heap abort
```

Control: `Matrix4N(4).SetEntry(-1, 0, 1.0)` and `MatrixN4` already return
`false` with no crash.

## How PBT Detected This

Harnesses: `test/unittest/base/matrix3n_setentry_pbt_test.cpp`,
`matrixn3_setentry_pbt_test.cpp`. In-range + upper-bound properties pass;
any negative index fails.

| Property | Oracle | Result |
|----------|--------|--------|
| `InBoundsRoundTrip` / `UpperBoundRejected` | algebraic / negative_error | PASS |
| `BoundaryExact` (includes −1) | algebraic.invariant | FAIL — SIGSEGV |
| `OutOfRangeRejected` | negative_error | FAIL |
| `StateMachineVsModel` | state machine vs 3×N / N×3 model | FAIL |
| `NegativeAgreesWithMatrix4N` / `MatrixN4` | differential | FAIL |

## Why Existing Tests Missed It

`Matrix3Test001` uses `INVALID_ROW_NEG` only on `Matrix3`. Matrix3N / MatrixN3
get positive OOB `(5, 5)` only. `Matrix3Test008` is upper-bound only — the
path the incomplete guards already handle.

## Suggested Fix

Mirror `Matrix4N` / `MatrixN4`:

```cpp
if (row < 0 || row >= DIMENSION || col < 0 || col >= columns_) {
    return false;
}
```

(and the N×3 dual: `row < 0 || row >= rows_ || col < 0 || col >= DIMENSION`).
