## Summary

`ReadOneUnicodeChar` in `src/Utils/Unicode.cpp:91` calls `CJC_ASSERT(status == ConversionResult::OK)` after invoking `ConvertUTF8toUTF32`. On any invalid UTF-8 input — bare continuation bytes, truncated sequences, overlong encodings — the converter returns `SOURCE_ILLEGAL` or `SOURCE_EXHAUSTED` and the assert fires, aborting the process with SIGABRT. In Release builds (`-DNDEBUG`) the assert is a no-op and the uninitialised `UTF32` variable propagates undefined behaviour into NFC table lookups.

## Vulnerable Code

**`src/Utils/Unicode.cpp:85–93`**
```cpp
UTF32 ReadOneUnicodeChar(const UTF8** sourceStart, const UTF8* sourceEnd)
{
    CJC_ASSERT(*sourceStart != sourceEnd);
    UTF32 c;
    UTF32* p{&c};
    auto status = ConvertUTF8toUTF32(sourceStart, sourceEnd, &p, p + 1);
    CJC_ASSERT(status == ConversionResult::OK);  // ← asserts on invalid UTF-8
    return c;
}
```

`ConvertUTF8toUTF32` runs LLVM's converter in `strictConversion` mode. The assert fires instead of handling the error, and `c` is uninitialised on the error path.

## Call Chain

```
OptionAction.cpp:351 — ParseAndCheckConditionVar()
  └─ NFC(id)                             [no validation]
       └─ NfcQuickCheck(s)               [Unicode.cpp:551]
            └─ ReadOneUnicodeChar()      [Unicode.cpp:85]
                 └─ CJC_ASSERT(...)      [Unicode.cpp:91] → SIGABRT
```

`src/Option/OptionAction.cpp:351` calls `NFC(id)` directly on command-line parsed config keys with no UTF-8 validation. Users can trigger the crash by passing malformed UTF-8 in `--cfg` options.

## Evidence

```cpp
#include <string>
#include "cangjie/Utils/Unicode.h"

using namespace Cangjie;
using namespace Cangjie::Unicode;

int main() {
    std::string s = "\x80";  // bare continuation byte
    NFC(s);                   // aborts with SIGABRT
    return 0;
}
```

### Minimal Triggering Inputs

| Input (hex) | Reason |
|---|---|
| `\x80` | Bare continuation byte |
| `\xFF` | Outside UTF-8 range |
| `\xC2` | Truncated 2-byte sequence |
| `\xC0\x80` | Overlong encoding |

## Inconsistency with Existing Code

`TryConsumeIdentifierUTF8Char` in `Lexer.cpp:731` uses the same `ConvertUTF8toUTF32` function and checks the error result, emitting a graceful diagnostic. `ReadOneUnicodeChar` is the **only call site** that asserts instead of handling the error.

## Impact

- **Debug builds**: SIGABRT on any invalid UTF-8 byte in identifier text or `--cfg` command-line options
- **Release builds**: `CJC_ASSERT` expands to `static_cast<void>(f)`; uninitialised `c` propagates garbage values into NFC table lookups — undefined behaviour
- **No documented pre-condition**: `Unicode.h` docs for `NFC`/`NfcQuickCheck` do not state "input must be valid UTF-8"
- **No error channel**: `ReadOneUnicodeChar` returns `UTF32` with no sentinel value, making graceful error propagation impossible without a signature change

## Suggested Fix

Change `ReadOneUnicodeChar` to return an error indicator and handle invalid input gracefully, consistent with `TryConsumeIdentifierUTF8Char`:

```cpp
// Option A: substitute U+FFFD replacement character
UTF32 ReadOneUnicodeChar(const UTF8** sourceStart, const UTF8* sourceEnd)
{
    CJC_ASSERT(*sourceStart != sourceEnd);
    UTF32 c;
    UTF32* p{&c};
    auto status = ConvertUTF8toUTF32(sourceStart, sourceEnd, &p, p + 1);
    if (status != ConversionResult::OK) {
        ++(*sourceStart);  // advance past the invalid byte
        return 0xFFFD;     // U+FFFD REPLACEMENT CHARACTER
    }
    return c;
}

// Option B: return std::optional<UTF32> and let callers emit a diagnostic
std::optional<UTF32> ReadOneUnicodeChar(const UTF8** sourceStart, const UTF8* sourceEnd);
```

Additionally, `OptionAction.cpp:351` should validate that `id` is well-formed UTF-8 before calling `NFC(id)`.
