## Summary

`ClassicUtils::ConvertStringToUuid` tokenizes a comma-separated UUID list
with `while (index != value.length() - 1)`. That condition is wrong in two
ways:

1. **Trailing comma drops the last UUID.** `ConvertUuidToString` always emits
   a trailing comma. The loop exits as soon as the *next* comma is the last
   character, so the final token is never extracted.
2. **No trailing comma → infinite loop.** When `find(',')` returns `npos`,
   `startPos = index + 1` wraps `size_t` to `0`, and the next `find` restarts
   from the beginning. The loop never exits.

Live caller is paired-device UUID persistence
(`ClassicAdapterProperties` save via `ConvertUuidToString`, load via
`ConvertStringToUuid`). Confirmed and fixed under `DTS2026063023525`.

## Vulnerable Code

`services/bluetooth/service/src/classic/classic_utils.cpp` (~71–89):

```cpp
std::vector<Uuid> ClassicUtils::ConvertStringToUuid(const std::string &value)
{
    std::vector<Uuid> uuids;
    if (value.empty()) { return uuids; }
    size_t index = value.find(',', 0);
    int startPos = 0;
    while (index != (value.length() - 1)) {   // exits one comma early
        std::string uuidStr = value.substr(startPos, (index - startPos));
        Uuid uuid = Uuid::ConvertFromString(uuidStr);
        uuids.push_back(uuid);
        startPos = index + 1;                 // npos+1 wraps to 0
        index = value.find(',', startPos);
    }
    return uuids;
}
```

Serializer (`ConvertUuidToString`) always appends `","` after every UUID.

## Trigger Conditions

1. **Data loss (live path).** Save paired-device UUIDs → config string ends
   with `,` → load calls `ConvertStringToUuid` → last UUID missing.
2. **Hang.** Any UUID list *without* a trailing comma (`"u1,u2"`, or a single
   token with no comma) — `find` returns `npos`, `startPos` wraps to 0.

Unaffected: empty input (early return).

## Impact

| Axis | Rating |
|------|--------|
| Trailing-comma form (`ConvertUuidToString` output) | Silent drop of last service UUID on paired-device restore |
| No-trailing-comma form | Bluetooth service hang (DoS) |
| Error returned | None |
| Overall | **High** |

## Minimal Counterexample

```text
ConvertUuidToString({uuid1, uuid2})  →  "u1,u2,"
ConvertStringToUuid("u1,u2,")        →  [uuid1]          // uuid2 lost
ConvertStringToUuid("u1,u2")         →  does not return  // npos wrap
```

`pbt-native/classic_uuid_roundtrip_pbt_test.cpp` — comma-split loop extracted

copy adds an iteration cap so the hang is a failure, not a stuck worker.

## Suggested Fix

`npos`-terminated tokenizer:

```cpp
std::vector<Uuid> ClassicUtils::ConvertStringToUuid(const std::string &value)
{
    std::vector<Uuid> uuids;
    if (value.empty()) { return uuids; }
    size_t startPos = 0;
    while (startPos < value.size()) {
        size_t comma = value.find(',', startPos);
        if (comma == std::string::npos) {
            uuids.push_back(Uuid::ConvertFromString(value.substr(startPos)));
            break;
        }
        uuids.push_back(Uuid::ConvertFromString(value.substr(startPos, comma - startPos)));
        startPos = comma + 1;
    }
    return uuids;
}
```

| After fix | Result |
|---|---|
| `"u1,u2,"` | `[u1, u2]` (empty trailing token ignored or empty Uuid — last real UUID kept) |
| `"u1,u2"` | `[u1, u2]`, terminates |
| `""` | still empty |
