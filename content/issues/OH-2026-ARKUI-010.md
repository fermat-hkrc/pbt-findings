## Summary

`GridScrollWithOptionsLayoutAlgorithm::CalculateStartCachedCountByIrregular`
returns how many items to preload **above** the viewport under the documented
**full-line model**: regulars pack `crossCount` per line between irregulars;
each irregular is one whole line; the walk anchors on a line boundary.

When the last regular line under the anchor is **partial**
(`diff % crossCount != 0`), that window’s item count is
`rem + (budget - 1) * crossCount`, not `budget * crossCount`.

The first branch always returns `budget * crossCount` as soon as
`diff >= budget * crossCount` — it never subtracts the leftover on the line
immediately above the irregular (or above `childrenCount` on bottom
overscroll). Cache/preload above the viewport can request up to
`crossCount - 1` extra items. Extra work, not data loss or crash.

**Confirmed** under `DTS2609150153371` (accepted in the internal DTS system;
**not fixed yet**).

## Vulnerable Code

`grid_scroll_with_options_layout_algorithm.cpp` (~418–423):

```cpp
        int32_t budget = cachedCount - lineCount;
        if (diff >= budget * crossCount) {
            return budget * crossCount + sum;  // ignores partial last line
        }
```

`diff` is regulars between the previous irregular and the anchor.
`diff >= budget * C` only means “enough items to fill `budget` **full** lines.”
Walking `budget` lines back from a line-boundary irregular starts with the
**last** regular line of that gap. If `diff % C != 0`, that last line has
`rem` items.

## Trigger Conditions

All of:

1. Matrix miss at `startMainLineIndex_ - cachedCount` (irregular walk path).
2. No `getSizeByIndex`; anchor past the first irregular.
3. Regular gap immediately below the anchor has `diff % crossCount != 0`
   (partial last regular line).

Typical: irregular **line-first** start, or **bottom overscroll** after a
partial last content line (`GetEffectiveStartIndex() == childrenCount`).

Non-triggering: empty `irregularIndexes`, matrix hit, `getSizeByIndex` set,
`effectiveStart <= firstIrregular`, or `diff % C == 0`.

## Impact

| Setup | Expected (full-line model) | Actual |
|-------|----------------------------|--------|
| `C=3`, `cachedCount=2`, start irreg `22`, irreg `{0,2,22}` | lines `{18,19,20}`+`{21}` = **4** | **6** |
| `C=2`, `cachedCount=2`, `children=6`, bottom overscroll, irreg `{0}` | `{3,4}`+`{5}` = **3** | **4** |

Medium: up to `crossCount-1` extra preload items above the viewport. No crash
or data corruption.

## Minimal Counterexample

```cpp
// C=3, cachedCount=2, children=25, startIndex_=22 (irregular), empty matrix
// irregularIndexes = {0, 2, 22}
CalculateStartCachedCount(options, 2);
// Expected: 4   Actual: 6

// C=2, cachedCount=2, children=6, bottom overscroll
// irregularIndexes = {0}
CalculateStartCachedCount(options, 2);
// Expected: 3   Actual: 4
```

## How PBT Detected This

Harness: `test/pbt/core/pattern/grid/grid_calculate_start_cached_count_pbt_test.cpp`.
Oracle: full-line model item count of the `cachedCount` lines above the
effective start (`FullLineStartCache`).

| Property | Result |
|----------|--------|
| `FullLineModelAgreement` | **FAIL** (partial last regular line) |
| `BottomOverscrollLastLines` | **FAIL** |
| `…regression_irregular_start_partial_last_line` | **FAIL** (got 6, want 4) |
| `…regression_bottom_overscroll_partial_last_line` | **FAIL** (got 4, want 3) |

Existing UTs (`CalculateStartCachedCount001-006`) never enter this branch with
a partial last regular line.

## Suggested Fix

```diff
         if (diff >= budget * crossCount) {
-            return budget * crossCount + sum;
+            int32_t rem = diff % crossCount;
+            if (rem == 0) {
+                return budget * crossCount + sum;
+            }
+            return rem + (budget - 1) * crossCount + sum;
         }
```

Exact multiples stay `budget * C`. Host PBT with this patch: full suite
**14/14 PASS**. `CalculateEndCachedCountByIrregular` unchanged.
