## Summary

`Matrix3<T>::IsNearEqual` uses `std::equal(data_, data_ + 8, …)` — half-open
**[0, 8)** — and skips **`data_[8]`** (`PERSP_2`). Matrices that differ only at
the last slot compare near-equal → animation may settle early via
`RSRenderAnimatableProperty<Matrix3f>::IsNearEqual`. Sibling **`operator==`**
checks all 9. Not a crash. Many 2D affine mats keep `data_[8]==1`. Confirmed
and fixed by developers (`DTS2026080528903`).

## Vulnerable Code

`rosen/modules/render_service_base/include/common/rs_matrix3.h` —
`Matrix3<T>::IsNearEqual` (~404):

```cpp
auto result = std::equal(data_, data_ + 8, otherData, /* ROSEN_EQ */);
// should be data_ + MATRIX3_SIZE (9)
```

| End | Indices |
|-----|---------|
| `data_ + 8` (prod) | 0..7 |
| `data_ + 9` (fix) | 0..8 |

Caller: `RSRenderAnimatableProperty<Matrix3f>::IsNearEqual`
(`rs_render_property.cpp` ~749).

Root cause: exclusive end used last index 8 instead of one-past-end 9.
`MATRIX3_SIZE == 9`.

## Trigger Conditions

1. Two `Matrix3` values differ only at `data_[8]` (`PERSP_2`), within the
   near-equal tolerance on slots 0..7.
2. `IsNearEqual` returns true (skips last element).
3. Animation property path treats them as settled → may stop early.

## Impact

- Animation / render-property near-equal may settle while perspective (or last
  homogeneous) component still differs.
- Many 2D affine matrices keep `data_[8]==1` on both sides → field miss rate
  lower for pure affine pans/scales.
- Not crash/OOB. Medium: wrong equality on live animation settle path.

## Minimal Counterexample

```
// matrices equal on data_[0..7], differ on data_[8]
IsNearEqual → true   // production (bug)
Expected    → false  // all 9 elements must participate
```

```bash
./pbt-native/build/rs_matrix3_isnearequal_pbt_test
```

## Suggested Fix

```cpp
std::equal(data_, data_ + MATRIX3_SIZE, otherData, /* ROSEN_EQ */);
```

After fix: `LastElementMatters` → PASS; near-equality includes every element
(same as `operator==`).
