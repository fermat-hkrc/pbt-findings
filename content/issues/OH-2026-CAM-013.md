## Summary

`CameraApplistManager::GetLogicCameraScreenStatus` parses
`const.camera.support_logical_camera_screen_status` (`mode,direction` pairs,
`;`-separated) into `displayModeToNaturalDirectionMap_`. It gates each field
with `isIntegerRegex` (optional `-` plus digits, **no magnitude bound**), then
calls `std::stoi`. Callers have no `try`/`catch`.

A token the gate accepts but that does not fit in `int` (`"2147483648"`,
`"-2147483649"`) makes `std::stoi` throw `std::out_of_range`. The constructor
invokes this when `const.system.sensor_correction_enable=1`, so the throw
aborts construction instead of returning `CAMERA_INVALID_STATE`.

Same `isIntegerRegex` ⇒ `std::stoi` class as `IsUint8Regex`
(`OH-2026-CAM-012` / `DTS2026082239652`), `IsDoubleRegex`
(`OH-2026-CAM-006` / `DTS2026071303295`), and `UpdateBasicInfoForStream`
(`OH-2026-CAM-003` / `DTS2026071411883`). Same-job extra-check sibling
`SafeStoi` uses `std::from_chars` and never throws. Confirmed and fixed under
`DTS2026082567022`.

## Vulnerable Code

`camera_applist_manager.cpp` `GetLogicCameraScreenStatus` (~88–92):

```cpp
CHECK_RETURN_RET_ELOG((subElems.size() != SIZE_TWO) ||
    !(isIntegerRegex(subElems[0]) && isIntegerRegex(subElems[1])), CAMERA_INVALID_STATE,
    "GetLogicCameraScreenStatus subElems isIntegerRegex false");
int32_t logicDisplayMode = std::stoi(subElems[0]);   // throws if not in int32
int32_t systemNaturalDirection = std::stoi(subElems[1]);
```

Ctor (`:67`) when `const.system.sensor_correction_enable=1`:

```cpp
CHECK_EXECUTE(isLogicCamera, GetLogicCameraScreenStatus());
```

`isIntegerRegex` (`camera_util.cpp` ~559) is shape-only. `SafeStoi` (~550)
already exists and does not throw.

## Trigger Conditions

1. `const.system.sensor_correction_enable=1`.
2. A comma-pair in `const.camera.support_logical_camera_screen_status` has a
   digit field outside int32 (`"2147483648,0"` / `"0,-2147483649"`).
3. `isIntegerRegex` is true; uncaught `std::stoi` throws in the ctor.

Well-formed int32 pairs and non-digit / wrong-arity tokens take the existing
`CAMERA_INVALID_STATE` / skip paths.

## Impact

- Uncaught C++ exception → `std::terminate()` → camera-service abort during
  `CameraApplistManager` construction.
- Medium: real crash, but needs the logic-camera sysparam **and** a
  malformed/oversized config string. Not app-crafted input.
- Consumer `GetAppNaturalDirectionByBundleName` never sees the throw.

## Minimal Counterexample

| config | `isIntegerRegex` | `stoi` | wanted |
|---|---|---|---|
| `"1,0"` | true | 1, 0 | `CAMERA_OK` |
| `"2147483648,0"` | true | **throws `std::out_of_range`** | `CAMERA_INVALID_STATE`, no throw |
| `"0,-2147483649"` | true | **throws `std::out_of_range`** | `CAMERA_INVALID_STATE`, no throw |
| `"abc,0"` | false | not called | `CAMERA_INVALID_STATE` |

## How PBT Detected This

`pbt-native/get_logic_camera_screen_status_pbt_test.cpp` — real TUs
(`camera_applist_manager.cpp`, `camera_util.cpp`). Oracle: negative / error
contract — a token `isIntegerRegex` accepts but `SafeStoi` rejects must not
throw; follow `CAMERA_INVALID_STATE`.

| Property / regression | Result |
|---|---|
| well-formed pairs / skip / malformed | PASS |
| `Int32OverflowNoThrow` | **FAIL** (throws) |
| `Int32Overflow_BugDocs` (`"2147483648,0"`) | **FAIL** (throws) |
| `Int32Underflow_BugDocs` (`"0,-2147483649"`) | **FAIL** (throws) |

## Suggested Fix

Replace `isIntegerRegex` + `stoi` with sibling `SafeStoi` (`from_chars`, no
throw). `camera_util.h` is already included.

```cpp
int logicDisplayMode = 0;
int systemNaturalDirection = 0;
CHECK_RETURN_RET_ELOG((subElems.size() != SIZE_TWO) ||
    !(SafeStoi(subElems[0], logicDisplayMode) && SafeStoi(subElems[1], systemNaturalDirection)),
    CAMERA_INVALID_STATE,
    "GetLogicCameraScreenStatus subElems parse failed");
```

Do not tighten `isIntegerRegex` globally in this ticket — other sites have
their own reports. Host PBT after this change: **10/10 PASS**.
