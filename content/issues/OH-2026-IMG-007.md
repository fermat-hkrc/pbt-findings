## Summary

`PixelYuvUtils::IsLegalAxis` guards `size + offset` with
`if (size > INT32_MAX - offset) return false;` — an idiom that is only valid
for `offset >= 0`. For any **negative** translate the subtraction itself
wraps signed int32 (`INT32_MAX + |offset|` ≥ 2³¹), the comparison fires, and
the function returns `false` **before** the correct trailing
`[1, MAX_DIMENSION]` dimension check runs. Every legal negative YUV
translate-shrink is rejected → `ERR_IMAGE_INVALID_PARAMETER`; negative YUV
translate is effectively unimplemented despite later code
(`width + xAxis`, offset `memcpy`, UV even-align for negative `xAxis`)
being written to handle it. Not High: hard fail / no-op, not memory
corruption. Confirmed and fixed by developers (`DTS2026081421810`).

## Vulnerable Code

`frameworks/innerkitsimpl/utils/src/pixel_yuv_utils.cpp` — `IsLegalAxis`
(~1131):

```cpp
int32_t xOffset = static_cast<int32_t>(xAxis);
int32_t yOffset = static_cast<int32_t>(yAxis);
if (imageInfo_.size.width > INT32_MAX - xOffset) {   // UB / wrap when xOffset < 0
    return false;
}
if (imageInfo_.size.height > INT32_MAX - yOffset) {  // same for yOffset < 0
    return false;
}
```

Wrap trace (`INT32_MAX=2147483647`, `xOffset=-1`):

```text
INT32_MAX - xOffset = -2147483648   # signed wrap of 2^31
width(100) > rhs  →  true  →  early return false
int64 sum = 99 ∈ [1, MAX_DIMENSION]  →  should accept
```

Callers: `PixelYuvUtils::YuvTranslate` (~1157) — early gate before
NV12/NV21/P010 translate; `PixelYuv::Translate` (`pixel_yuv.cpp` ~819) —
returns `ERR_IMAGE_INVALID_PARAMETER` when the gate fails.

## Trigger Conditions

1. `xAxis` or `yAxis` is any non-zero negative float (in NDK
   `OH_PixelmapNative_Translate(-10,-20)` range).
2. The corresponding guard evaluates `INT32_MAX - (negative)`.
3. Wrap makes the comparison true → early `return false`.

Positive expands, zero, NaN/Inf, and beyond-int32 axes are unaffected.

## Impact

- `PixelYuv::Translate(-1, 0)` on a normal NV12/NV21/P010 map →
  `ERR_IMAGE_INVALID_PARAMETER`; canvas never shrinks.
- `YuvTranslate` with negative axes → transform fails.
- Medium: YUV translate-shrink dead on the live path; no crash / OOB.

## Minimal Counterexample

| Input | Expected | Actual |
|-------|----------|--------|
| `xAxis=-1`, `yAxis=0`, `width=100`, `height=100` | **true** (`newW=99 ∈ [1,MAX]`) | **false** |
| `xAxis=0`, `yAxis=-1`, `width=100`, `height=100` | **true** (`newH=99`) | **false** |
| `xAxis=-8`, `yAxis=-4`, `width=64`, `height=64` | **true** (`56×60`) | **false** |
| `xAxis=10`, `yAxis=5`, `100×100` | **true** | true (positive path OK) |

Shrunk RapidCheck witness: `IsLegalAxis(-64, 0, {65,1})` rejected although
`65 + (-64) = 1` is in range.

## Suggested Fix

Drop the wrap-prone mid-guards; form the sum in `int64` and let the trailing
`[1, MAX_DIMENSION]` check (the real contract) decide:

```diff
-    if (imageInfo_.size.width > INT32_MAX - xOffset) { return false; }
-    if (imageInfo_.size.height > INT32_MAX - yOffset) { return false; }
     if (xOffset == 0 && yOffset == 0) { return false; }
-    int32_t width = imageInfo_.size.width + xOffset;
-    int32_t height = imageInfo_.size.height + yOffset;
+    const int64_t width = static_cast<int64_t>(imageInfo_.size.width) + xOffset;
+    const int64_t height = static_cast<int64_t>(imageInfo_.size.height) + yOffset;
```

Safety not lost: grow-overflows the old guard caught correctly
(`offset >= 0`) still fail the tail (`> MAX_DIMENSION` or `< 1`); NaN/Inf and
`|axis| > INT32_MAX` stay rejected by the unchanged top guards.
