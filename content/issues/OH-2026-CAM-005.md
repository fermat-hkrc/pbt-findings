## Summary

Five copy-pasted sites walk `OHOS_CONTROL_CAPTURE_MIRROR_SUPPORTED` as
`(mode, flag)` pairs with step 2, but bound only `i < item.count` and then
always read `item.data.u8[i + 1]` (body and debug log). Odd `item.count` →
last `i` has `i + 1 == count` → heap **OOB read**.

App-facing `IsMirrorSupported` and service `SetMirrorForLivePhoto`. Not High:
needs truncated/odd HAL ability blob; well-formed even tables are fine.
In-tree siblings already use the safe bound `i + 1 < item.count`.

Confirmed and fixed by developers.

## Vulnerable Code

Same loop at 5 sites:

| File | Function |
|------|----------|
| `frameworks/native/camera/base/src/output/photo_output.cpp` | `PhotoOutput::IsMirrorSupported` |
| `…/video_output.cpp` | `VideoOutput::IsMirrorSupported` |
| `…/movie_file_output.cpp` | `MovieFileOutput::IsMirrorSupported` |
| `…/unify_movie_file_output.cpp` | `UnifyMovieFileOutput::IsMirrorSupported` |
| `services/camera_service/src/hstream_repeat.cpp` | `HStreamRepeat::SetMirrorForLivePhoto` |

```cpp
int step = 2;
for (int i = 0; i < static_cast<int>(item.count); i += step) {
    MEDIA_DEBUG_LOG(..., i, item.data.u8[i], i + 1, item.data.u8[i + 1]);
    if (currentSceneMode == static_cast<int>(item.data.u8[i])) {
        isMirrorEnabled = (/* flag checks on */ item.data.u8[i + 1]) …;
    }
}
// bound is i < count, but body always reads i+1
```

Root cause: pair walk advances by 2 without ensuring a complete pair remains.
Same missing bound as the deferred-photo pair walk; five call sites share the
copy-paste.

## Trigger Conditions

1. HAL ability / metadata supplies `OHOS_CONTROL_CAPTURE_MIRROR_SUPPORTED`
   with odd `item.count` (e.g. length 1 or 3).
2. App calls `IsMirrorSupported`, or service runs `SetMirrorForLivePhoto`.
3. Loop reaches last index `i = count - 1` (odd); `item.data.u8[i + 1]` reads
   one past the blob.

## Impact

- **Heap OOB read** on app-facing `IsMirrorSupported` and service
  `SetMirrorForLivePhoto` when the mirror-supported ability length is odd.
- **Medium:** even-length HAL tables (normal devices) unaffected; field hit
  needs truncated/odd metadata. FW bound still wrong vs in-tree safe siblings
  (`hstream_operator` picture-size, deferred video walk).
- One fix pattern covers all five sites.

## Minimal Counterexample

| blob / count | Production |
|--------------|------------|
| even `{mode,flag,…}` | OK |
| odd length 1 / 3 | **OOB** on `u8[i+1]` |
| empty | OK (loop does not run) |

## Suggested Fix

Match picture-size / safe pair walks at every site:

```cpp
for (int i = 0; i + 1 < static_cast<int>(item.count); i += step) {
    if (/* mode match */) {
        isMirrorEnabled = (/* flag on */ item.data.u8[i + 1]) …;
    }
}
```

Contract: incomplete trailing pair is skipped (orphan mode byte dropped).
After fix: odd/single-byte props PASS; even props stay PASS.
