## Summary

`Asn1Utils::CountTrailingZeros` probes `0x0F` / `0x33` / `0x55` independently
without isolating the lowest set bit. Extra higher `1`s fire extra probes, so
mixed bytes return too few trailing zeros. `Asn1AddChildAsBits` stores the
result as the BIT STRING unused-bits octet (`asn1_builder.cpp:110`).

In-tree unit test `CountTrailingZeros_001` already pins `0 → 8`, `1 → 0`,
`8 → 3`, `32 → 5`. So `CountTrailingZeros(8) == 3` implies
`CountTrailingZeros(24) == 3` (`8 | 16`). The SUT returns `0`.
Confirmed and fixed by developers (`DTS2026090526221`).

## Vulnerable Code

`utils/codec/src/asn1_utils.cpp` (242–261):

```cpp
uint32_t valueTemp = ((static_cast<uint32_t>(value)) & MAX_UINT8);
uint8_t nonZeroBitCount = static_cast<uint8_t>(NONZERO_OCCUPIED_BITS); // 7
if ((valueTemp & 0x0F) != 0) {
    nonZeroBitCount -= 4;
}
if ((valueTemp & 0x33) != 0) {
    nonZeroBitCount -= 2;
}
if ((valueTemp & 0x55) != 0) {
    nonZeroBitCount -= 1;
}
```

The value is never narrowed to the lowest set bit. A higher `1` can satisfy a
mask the lowest `1` would not.

Callers: exported `asn1_utils.h:42`; `Asn1AddChildAsBits`
(`asn1_builder.cpp:110`). eSIM `ListNotifications` /
`RetrieveNotificationList` pass `EsimEvent` into `Asn1AddChildAsBits`
(`esim_file.cpp:2263,:2487`).

## Trigger Conditions

1. Last BIT STRING data byte has more than one bit set.
2. Combined eSIM flags such as `EVENT_ENABLE | EVENT_DISABLE` (`6`) reverse
   to last byte `96` (expected 5 unused bits, actual 4).
3. Single-bit flags (`EVENT_ENABLE`) are powers of two after reverse and
   encode correctly.

Honest limit: phone-side `Asn1AsBits` ignores unused-bits, so a self-roundtrip
can look fine. The hole is the count, not a missing caller.

## Impact

- Wrong unused-bits octet on the wire. The eUICC can treat a real event bit
  as padding.
- Medium — silent wrong APDU field, not a crash.

| Witness | Input | Expected | Actual |
|---|---|---|---|
| mixed | `6` (`0b00000110`) | 1 | **0** |
| power of two | `8` | 3 | 3 |
| zero | `0` | 8 | 8 |

`6` is `00000110`. Lowest bit is 1 → probes should be yes / yes / no → `1`.
Bit 2 is in `0x55` → extra −1 → `0`.

## How PBT Detected This

`pbt-native/count_trailing_zeros_pbt_test` — links the REAL `asn1_utils.cpp`
(not a model). Oracle: CTZ depends only on the lowest set bit (unit test
`CountTrailingZeros_001`).

| Property | Result |
|---------|--------|
| `PowerOfTwoCtzEqualsExponent` / `OddBytesHaveZeroCtz` / `ZeroIsEightBits` | PASS |
| `ResultInClosedRange` | PASS |
| `LowestSetBitPreservesCtz` | **FAIL** `6` |
| `LeftShiftAddsToCtz` | **FAIL** `24` |
| `Regression_SixHasOneTrailingZero` | **FAIL** 0 vs 1 |

```bash
cmake -B pbt-native/build pbt-native
cmake --build pbt-native/build -j --target count_trailing_zeros_pbt_test
./pbt-native/build/count_trailing_zeros_pbt_test \
  --gtest_filter='*Regression_SixHasOneTrailingZero*'
```

## Suggested Fix

Isolate the lowest set bit, then keep the existing probes:

```diff
     uint32_t valueTemp = ((static_cast<uint32_t>(value)) & MAX_UINT8);
+    valueTemp &= (~valueTemp + 1);
     uint8_t nonZeroBitCount = static_cast<uint8_t>(NONZERO_OCCUPIED_BITS);
```

`v & (~v + 1)` keeps only the lowest `1`. After that, `6` becomes `2`, `24`
becomes `8`, `96` becomes `32`.

| After fix | Result |
|---|---|
| `6` / `24` / `96` | 1 / 3 / 5 |
| `0` / `1` / `8` / `32` | unchanged |
