## Summary

Static `ark::panda_file::helpers::Read<WIDTH>` is a little-endian fixed-width
reader over a byte cursor. It always indexes `WIDTH` bytes and advances with
`SubSpan(WIDTH)`, with **no** `Size()` gate. On a short/empty span under
`NDEBUG`, that is an OOB byte read and then a poisoned cursor whose `Size()`
wraps into the `SIZE_MAX` range.

Dynamic sibling `libpandafile/helpers.h` rejects short spans first via
`THROW_IF(sp->Size() < width, INVALID_SPAN_OFFSET)`. Confirmed and fixed under
`DTS2026080754676` (internal system) — `Size() < WIDTH` rejected before index /
pointer walk / `SubSpan` on the generic template and both specializations.

## Vulnerable Code

`static_core/libarkfile/helpers.h` — generic + `uint16_t` / `uint32_t`
specializations:

```cpp
template <size_t WIDTH>
inline auto Read(Span<const uint8_t> *sp)
{
    UnsignedType result = 0;
    for (size_t i = 0; i < WIDTH; i++) {
        UnsignedType tmp = static_cast<UnsignedType>((*sp)[i]) << (i * BYTE_WIDTH);
        result |= tmp;
    }
    *sp = sp->SubSpan(WIDTH);   // size_ - WIDTH underflows when Size() < WIDTH
    return result;
}
```

`Span::operator[]` / `SubSpan` only `ASSERT` bounds; under `NDEBUG` those
asserts compile out (`static_core/libarkbase/utils/span.h`).

## Contract

1. `Read<WIDTH>` requires `sp->Size() >= WIDTH` before any index or advance.
2. Short / empty span must not read past the end or poison the cursor
   (`Size()` must not wrap).
3. Dynamic `libpandafile` `Read` is the in-tree reference: reject when
   `Size() < WIDTH`.

## Minimal Counterexample

```cpp
using ark::Span;
using ark::panda_file::helpers::Read;

const uint8_t d = 0;
Span<const uint8_t> sp1(&d, 0U);
(void)Read<1>(&sp1);
// Expected: reject / Size() still 0
// Actual (NDEBUG): OOB [0] + Size() == SIZE_MAX

uint8_t buf2[1] = {0xab};
Span<const uint8_t> sp2(buf2, 1U);
(void)Read<2>(&sp2);
// Expected: Size() still <= 1
// Actual: OOB 2nd byte + size wrap (1 - 2)
```

## Impact

| Axis | Rating |
|------|--------|
| Impact when hit | High (OOB **read**; cursor `size_t` underflow → later decode on huge span) |
| Likelihood on well-formed abc | Low — layout lengths match |
| Likelihood on truncated / crafted abc or internal short slice | Medium |
| Overall | **Medium** |

Not High: needs a short span to reach `Read`. Well-formed abc is fine. Still a
real UB / corrupt-decode defect once that span arrives. Callers include field /
method / annotation / literal / proto accessors and tagged-value helpers in the
same header.

## Suggested Fix

Match libpandafile: reject when `Size() < WIDTH` **before** index / pointer
walk / `SubSpan`, on the generic template **and** both specializations
(`LOG(FATAL, …)` or local `THROW_IF` equivalent).

```cpp
if (UNLIKELY(sp->Size() < WIDTH)) {
    LOG(FATAL, PANDAFILE) << "INVALID_SPAN_OFFSET";
}
```
