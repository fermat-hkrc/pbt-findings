## Summary

`FixedSizeList::remove_at` unconditionally rewinds the write pointer (`index`) by 1 after any removal. After the internal circular buffer has wrapped, the rewound pointer lands on a slot holding a live element. The next `add` overwrites that live element, and a stale (already-removed) element reappears as if it were never consumed.

## Contract

`FixedSizeList` is a bounded circular buffer. The implicit contract is:

- `add(x)` inserts `x`, evicting the oldest element if at capacity
- `find_if(pred)` finds and removes the first matching element, returning it
- After `find_if` removes element X, all non-matching elements remain intact

The bug violates the third invariant: a non-matching element Y is silently destroyed after a `find_if` + `add` sequence post-wraparound.

## Vulnerable Code

`common/utils/fixed_size_list.h:67-74`:

```cpp
void remove_at(size_t position)
{
    if (position < currentSize) {
        for (size_t i = position; i < currentSize - 1; ++i) {
            data[i] = data[i + 1];
        }
        --currentSize;
        index = (index + maxSize - 1) % maxSize;   // BUG: always rewinds write pointer
    }
}
```

`remove_at` blindly rewinds `index`, assuming removal always frees the slot at `(index - 1) % maxSize`. After wraparound, the removed physical position has no fixed relationship to `index`, so the rewound pointer lands on a live element.

Compounding this, `find_if` iterates by physical position (`data[0]` through `data[currentSize-1]`), not logical ring order. After wraparound, physical position 0 holds the newest element, not the oldest, so the left-shift compaction moves elements across the logical age boundary.

## Minimal Counterexample

```cpp
FixedSizeList<int> list(2);
list.add(0);   // data=[0, _], currentSize=1, index=1
list.add(1);   // data=[0, 1], currentSize=2, index=0 (wrapped!)
list.add(2);   // data=[2, 1], currentSize=2, index=1 (evicts 0)
               // Logical contents: [1, 2]

auto popped = list.find_if([](const int& v) { return v == 1; });
// scans data[0]=2 (no), data[1]=1 (match) → remove_at(1)
// remove_at: no shift, --currentSize=1, index = (1+2-1)%2 = 0
// State: data=[2, 1], currentSize=1, index=0. Only data[0]=2 is live.

list.add(3);
// Writes to data[index=0]=3, index=1, currentSize=2
// BUG: overwrites live element 2. Dead slot 1 (stale value 1) is now "live" again.

// Expected: {2, 3}
// Actual:   {1, 3}  — element 2 lost, stale element 1 reappears
```

## When the Bug Triggers

The bug fires whenever:

1. The buffer has wrapped (more than `maxSize` total insertions)
2. `find_if` removes an element
3. `add` inserts a new element

This is the normal steady-state usage pattern for both production callers.

## How PBT Detected This

A RapidCheck property compared `FixedSizeList` against a simple `std::vector`-based bounded FIFO model, asserting that the two stay in sync across `add` / `find_if` sequences. RapidCheck shrunk the counterexample to `(cap=1, values=[0,0,0,1], popIndex=0, nextValue=0)`.

```cpp
RC_GTEST_PROP(FixedSizeListPBT, PopThenPushPreservesRemainingValues,
    (uint8_t rawCap, const std::vector<uint8_t>& rawValues,
     uint8_t rawPopIndex, uint8_t rawNextValue))
{
    FixedSizeList<int> list(cap);
    std::vector<int> model;
    for (auto value : values) {
        list.add(value);
        model.push_back(value);
        if (model.size() > cap) model.erase(model.begin());
    }

    const int popValue = model[popIndex];
    list.find_if([&](const int& stored) { return stored == popValue; });
    model.erase(std::find(model.begin(), model.end(), popValue));

    list.add(nextValue);
    model.push_back(nextValue);
    if (model.size() > cap) model.erase(model.begin());

    RC_ASSERT(DrainCounts(list) == CountsOf(model));
}
```

No existing unit tests for `FixedSizeList`, `MovingPhotoListener`, `MovingPhotoMetaListener`, or `MetaCacheFilter` exercise the `find_if` + `add` interaction after wraparound.

## Impact

Both production callers use `FixedSizeList` with capacity 8 as a metadata cache for camera frames. At 30fps the buffer wraps in ~0.27 seconds, after which every `find_if` + `add` cycle corrupts internal state.

- **Caller 1** — `moving_photo_listener.cpp` (`add` at line 317, `find_if` at line 197): caches metadata frames keyed by timestamp.
- **Caller 2** — `meta_cache_filter.cpp` (`add` at line 298, `find_if` at line 306): same pattern.

Real-world impact is limited because timestamps are unique (a stale entry never matches a future query) and callers handle `nullopt` gracefully (a missed frame proceeds without metadata). The observable effect is occasional missed metadata on individual frames — no crash, no wrong data returned.

## Suggested Fix

Replace the flat-array-with-rewind design with proper ring-buffer access: track a logical `head` (oldest element position) and iterate/remove in ring order.

```cpp
template <typename T>
class FixedSizeList {
public:
    FixedSizeList(size_t size) : maxSize(size), currentSize(0), head(0), index(0)
    {
        data.resize(size);
    }

    void add(T value)
    {
        std::lock_guard<std::mutex> lock(mtx);
        data[index] = value;
        if (currentSize == maxSize) {
            head = (head + 1) % maxSize;   // evict oldest
        } else {
            ++currentSize;
        }
        index = (index + 1) % maxSize;
    }

    std::optional<T> find_if(const std::function<bool(const T&)>& predicate)
    {
        std::lock_guard<std::mutex> lock(mtx);
        for (size_t i = 0; i < currentSize; ++i) {
            size_t pos = (head + i) % maxSize;   // iterate in logical age order
            if (predicate(data[pos])) {
                T result = data[pos];
                remove_at_logical(i);
                return result;
            }
        }
        return std::nullopt;
    }

private:
    void remove_at_logical(size_t logicalIndex)
    {
        for (size_t i = logicalIndex; i < currentSize - 1; ++i) {
            size_t dst = (head + i) % maxSize;
            size_t src = (head + i + 1) % maxSize;
            data[dst] = data[src];
        }
        --currentSize;
        index = (index + maxSize - 1) % maxSize;
    }

    std::vector<T> data;
    size_t maxSize;
    size_t currentSize;
    size_t head;     // tracks oldest element's physical slot
    size_t index;
    mutable std::mutex mtx;
};
```

Key changes:

- Add a `head` member tracking the oldest element's physical slot
- `add` advances `head` on eviction instead of relying on implicit overwrite
- `find_if` iterates in logical ring order (`(head + i) % maxSize`)
- `remove_at_logical` shifts within ring order, not physical order
