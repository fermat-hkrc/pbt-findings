## Summary

`ImageUtils::GetValidAlphaTypeByFormat` normalizes alpha type for RGBA-like
formats by falling through a `break` group and returning the caller’s
`dstType`. `RGBA_F16` is in that group; **`RGBA_U16` is missing** and hits
`default` → `IMAGE_ALPHA_TYPE_UNKNOWN`.

`RGBA_U16` is accepted by `IsRGBX` / `PixelMapCreateCheckFormat` for PixelMap
creation and paired with `RGBA_F16` in `GetPixelBytes`, so the switch is
inconsistent with same-file siblings. Not High: `RGBA_U16` is interim
(`image_type.h`: ffmpeg/skia conversion); most user-facing code uses
`RGBA_F16`. Confirmed and fixed by developers (`DTS2026081128460`).

## Vulnerable Code

`frameworks/innerkitsimpl/utils/src/image_utils.cpp` —
`GetValidAlphaTypeByFormat` (~493):

```cpp
switch (format) {
    case PixelFormat::RGBA_8888:
    case PixelFormat::BGRA_8888:
    case PixelFormat::ARGB_8888:
    case PixelFormat::RGBA_1010102:
    case PixelFormat::RGBA_F16: {   // ← BUG: RGBA_U16 missing from this group
        break;
    }
    // ... ALPHA_*, RGB_*, YUV cases ...
    case PixelFormat::CMYK:
    default: {
        IMAGE_LOGE("GetValidAlphaTypeByFormat unsupport the format(%{public}d).", format);
        return AlphaType::IMAGE_ALPHA_TYPE_UNKNOWN;  // ← RGBA_U16 lands here
    }
}
return dstType;
```

Callers: `PixelMap::Create`; `PostProc::HasPixelConvert`;
`ImageSource::CreatePixelMap`.

Root cause: missing case in switch — same class as fixed
`matrix_settranslate_axis_identity` (silent wrong result from missing case).

## Trigger Conditions

1. Caller uses `PixelFormat::RGBA_U16` with a valid alpha type (e.g. PREMUL).
2. `GetValidAlphaTypeByFormat` returns `IMAGE_ALPHA_TYPE_UNKNOWN`.
3. Downstream: `IsValidImageInfo` fails on UNKNOWN; conversion path selection
   and decode alpha normalization go wrong.

## Impact

1. **PixelMap creation:** normalized alpha becomes UNKNOWN →
   `IsValidImageInfo` fails when `alphaType == IMAGE_ALPHA_TYPE_UNKNOWN`.
2. **Pixel conversion:** `HasPixelConvert` gets UNKNOWN → incorrect
   conversion-path selection.
3. **Image decode:** `CreatePixelMap` destination format RGBA_U16 gets wrong
   alpha type.

Medium: silent wrong alpha classification on an accepted create path; interim
format limits field blast radius vs `RGBA_F16`.

## Minimal Counterexample

| Format | `GetValidAlphaTypeByFormat(PREMUL, format)` | Expected |
|--------|----------------------------------------------|----------|
| `RGBA_F16` | `IMAGE_ALPHA_TYPE_PREMUL` ✓ | PREMUL |
| `RGBA_U16` | **`IMAGE_ALPHA_TYPE_UNKNOWN`** ✗ | PREMUL |

Both: 8 Bpp, 4 channels, in `IsRGBX`; only F16 is in the break group.

## How PBT Detected This

`pbt-native/rgba_u16_alpha_type_missing_pbt_test` — links REAL
`image_utils.cpp` (not a model):

| Check | Result |
|-------|--------|
| `RGBA_F16` returns caller dstType | PASS |
| `RGBA_U16` returns PREMUL (or non-UNKNOWN) for PREMUL input | **FAIL** (UNKNOWN) |

```bash
cmake -S pbt-native -B pbt-native/build -DCMAKE_BUILD_TYPE=Release
cmake --build pbt-native/build -j --target rgba_u16_alpha_type_missing_pbt_test
./pbt-native/build/rgba_u16_alpha_type_missing_pbt_test
```

## Suggested Fix

Place `RGBA_U16` in the same case group as `RGBA_F16`:

```diff
         case PixelFormat::RGBA_1010102:
         case PixelFormat::RGBA_F16: {
+        case PixelFormat::RGBA_U16:
             break;
         }
```

After fix: `RGBA_U16` returns caller `dstType` like `RGBA_F16`.
