## Summary

Two copy-pasted sites walk `OHOS_ABILITY_EQUIVALENT_FOCUS` as `(mode, focus)`
pairs. Both bound only `i < item.count` then on even `i` always read
`item.data.i32[i + 1]`. Odd `item.count` → last even index has
`i + 1 == count` → heap **OOB read**.

Feeds equivalent-focus / zoom-point UI paths (`GetEquivalentFocus`,
`GetZoomPointInfos`). Not High: needs truncated/odd HAL ability blob;
well-formed even tables are fine. In-tree siblings already use
`i + 1 < item.count`.

Confirmed and fixed by developers (`DTS2026072832082`).

## Vulnerable Code

Same loop shape at 2 sites:

| File | Function |
|------|----------|
| `services/camera_service/src/hcapture_session.cpp` | `HCaptureSession::GetEquivalentFocus` |
| `frameworks/native/camera/extension/src/session/capture_session_for_sys.cpp` | `CaptureSessionForSys::GetZoomPointInfos` |

```cpp
for (uint32_t i = 0; i < item.count; i++) {
    if ((i & 1) == 0) {
        equivalentFocus = static_cast<uint32_t>(item.data.i32[i + 1]);
        // GetZoomPointInfos also reads i32[i] / i32[i+1] for mode match
    }
}
```

`GetZoomPointInfos` debug log also evaluates both `i32[i]` and `i32[i + 1]`.

## Trigger Conditions

1. HAL ability / metadata supplies `OHOS_ABILITY_EQUIVALENT_FOCUS` with odd
   `item.count` (e.g. length 1 or 3).
2. Service runs `GetEquivalentFocus`, or sys `GetZoomPointInfos`.
3. Loop reaches last even `i`; `item.data.i32[i + 1]` reads past the blob.

## Impact

- **Heap OOB read** on service `GetEquivalentFocus` and sys
  `GetZoomPointInfos` when equivalent-focus ability length is odd.
- **Medium:** even-length HAL tables (normal devices) unaffected; field hit
  needs truncated/odd metadata. FW bound still wrong vs in-tree safe siblings
  (`hstream_operator` picture-size, deferred video walk).
- Two sites share the copy-paste; one fix pattern covers both.

## Minimal Counterexample

| count / blob | Production |
|--------------|------------|
| even `{mode,focus,…}` | OK |
| odd length 1 / 3 | **OOB** on `i32[i+1]` |
| empty | OK (loop does not run) |

## How PBT Detected This

`pbt-native/eq_focus_pair_pbt_test` + `eq_focus_pair_real.cpp`:

| Test | Result |
|------|--------|
| `Odd_MustNotOob` | **FAIL** |
| Witness `Odd1` (bounds model throws) | documents OOB |
| `Even_Ok` / Witness `Even` | PASS |

```bash
cmake -S pbt-native -B pbt-native/build -DCMAKE_BUILD_TYPE=Release
cmake --build pbt-native/build -j --target eq_focus_pair_pbt_test
./pbt-native/build/eq_focus_pair_pbt_test
```

## Suggested Fix

Match video deferred / picture-size pair walks at **both** sites:

```cpp
for (uint32_t i = 0; i + 1 < item.count; i += 2) {
    equivalentFocus = static_cast<uint32_t>(item.data.i32[i + 1]);
}
```

`GetZoomPointInfos` uses the same bound, then mode-matches on `i32[i]` /
`i32[i + 1]`. Contract: incomplete trailing pair is skipped (orphan int
dropped). After fix: `Odd_MustNotOob` PASS; even props stay PASS.
