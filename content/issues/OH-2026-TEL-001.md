## Summary

`Asn1Utils::BytesToInt` guards its window with `(offset + length) > src.size()`
— adding two `uint32_t`s. `UINT32_MAX + 1` wraps to `0`, the check passes,
and `src.begin() + offset` is constructed far past `end()` → **SIGSEGV** on a
public API (exported `asn1_utils.h:41`) instead of returning `false`.
Same-family sibling `Asn1Decoder` ctor (`asn1_decoder.cpp:29`) already does
the non-wrapping form `offset > (UINT32_MAX - decodeLen)` before adding.
Confirmed and fixed by developers (`DTS2026082565627`).

## Vulnerable Code

`utils/codec/src/asn1_utils.cpp` (159–169):

```cpp
if (length > HEX_STR_MAX_LENGTH || (offset + length) > src.size()) {
    return false;
}
std::vector<uint8_t> subByteStream(src.begin() + offset, src.begin() + offset + length);
```

`HEX_STR_MAX_LENGTH` (4) does not stop a wrapping sum: `offset=UINT32_MAX`,
`length=1` → sum `0`, `0 > src.size()` false → OOB iterator.

Callers: ASN.1 decoder tag/len (`asn1_decoder.cpp:75,102`, `false` →
`nullptr`) and `Asn1Node` integer/bits (`asn1_node.cpp:291,331`); decoder
callers treat `false` as parse failure, so `false` is the contract for an
unreadable window.

## Trigger Conditions

1. `BytesToInt(src, offset, length, out)` called with `offset + length`
   wrapping `uint32_t` (e.g. `offset == UINT32_MAX`, `length >= 1`).
2. Wrapped sum ≤ `src.size()` passes the guard.
3. `src.begin() + offset` is OOB → SIGSEGV (exit 139).

Honest limit: well-formed decoder walks keep `offset` in-buffer; the hole is
the API check itself, not a proven field PDU carrying `UINT32_MAX`.

## Impact

- Public API crash (SIGSEGV) instead of a clean `false` on a wrapping window.
- High: crash of the hosting process on an exported utility path; not a wrong
  integer on a valid window.

| Witness | Input | Expected | Actual |
|---|---|---|---|
| wrap | `src={1,2}`, `offset=UINT32_MAX`, `length=1` | `false` | **SIGSEGV** |
| in-range | `offset=0`, `length=2` | `true` | `true` |
| plain OOB | `offset=3`, `length=1`, size 2 | `false` | `false` |

## How PBT Detected This

`pbt-native/bytes_to_int_pbt_test` — links the REAL `asn1_utils.cpp` (not a
model). Oracle: 64-bit `offset + length` vs `src.size()`.

| Property | Result |
|---------|--------|
| `IntToBytesThenBytesToIntRecovers` / `AgreesWithIndependentBigEndian` | PASS |
| `RejectsUnreadableWindow` (non-wrap OOB / `length>4`) | PASS |
| `OffsetPlusLengthOverflowRejects` | **FAIL** (SIGSEGV, exit 139) |
| `EmptyWindowDecodesToZero` / embedded window | PASS |

```bash
cmake -B pbt-native/build pbt-native
cmake --build pbt-native/build -j --target bytes_to_int_pbt_test
./pbt-native/build/bytes_to_int_pbt_test --gtest_filter='*OffsetPlusLengthOverflow*'
```

## Suggested Fix

Subtract, don't add — same shape as `asn1_decoder.cpp:29`:

```diff
-    if (length > HEX_STR_MAX_LENGTH || (offset + length) > src.size()) {
+    if (length > HEX_STR_MAX_LENGTH || offset > src.size() ||
+        length > src.size() - offset) {
         TELEPHONY_LOGE("length(%{public}d) or offset(%{public}d) is invalid.", length, offset);
         return false;
     }
```

After fix: `offset=UINT32_MAX, length=1` → `false`, no OOB; in-range /
`length>4` / plain-OOB behavior unchanged.
