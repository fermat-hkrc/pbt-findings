## Summary

Six camera-session call sites convert a HAL exposure-time rational
`(numerator, denominator)` to microseconds with:

```cpp
CHECK_RETURN*_ELOG(denominator == 0, ...);
constexpr int32_t timeUnit = 1000000;
uint32_t value = static_cast<uint32_t>(numerator / (denominator / timeUnit));
```

The guard only rejects `denominator == 0`. The inner divisor
`denominator / timeUnit` is zero for every `|denominator| < 1_000_000`
(e.g. `1`, `1000`, `999999`, `-1`) — values that pass the guard — so the
outer integer division is **divide-by-zero → SIGFPE**.

Well-formed HAL tables that use nanosecond scale (`num / 1e9`) are safe
(`1e9 / 1e6 = 1000`), but dens on the ms scale, unit scale, or truncated
metadata hit the trap. The formula is on default session/status paths
(`GetSensorExposureTimeRange`, `ProcessSensorExposureTimeChange`, time-lapse,
profession, AR) — not hook-gated.

Confirmed and fixed by developers (same P1 divisor class as the beauty
`range.size()-1` SIGFPE, OH-2026-CAM-002).

## Vulnerable Code

Same formula at 6 sites:

| File | Function |
|------|----------|
| `frameworks/native/camera/base/src/session/capture_session.cpp` | `ProcessSensorExposureTimeChange`, `GetSensorExposureTimeRange`, AR exposure block |
| `frameworks/native/camera/extension/src/session/profession_session.cpp` | `ProcessSensorExposureTimeChange` |
| `frameworks/native/camera/extension/src/session/time_lapse_photo_session.cpp` | `ProcessExposureChange`, `GetSupportedExposureRange` |

```cpp
CHECK_RETURN*_ELOG(denominator == 0, ...);
constexpr int32_t timeUnit = 1000000;
uint32_t value = static_cast<uint32_t>(numerator / (denominator / timeUnit));
//                                                    ^^^^^^^^^^^^^^^^^^^^
//                                                    0 when |den| < 1e6
```

Root cause: the reject set `{0}` and the safe set for the formula
`{ d | d / 1e6 != 0 }` (i.e. `|d| >= 1e6`) disagree. Any accepted
`denominator` with `|denominator| < timeUnit` yields a zero inner divisor.

## Trigger Conditions

1. A HAL ability table, status callback, or SystemApi exposure-range query
   supplies a rational with `denominator != 0` and `|denominator| < 1_000_000`
   (e.g. `1`, `1000`, `999999`, `-1`).
2. Any of the 6 call sites runs the conversion (app-callable via
   `GetSensorExposureTimeRange` / SystemApi exposure range, or HAL status
   callbacks on profession / time-lapse / AR / base session paths).
3. Inner `denominator / 1000000` is `0`; outer integer division faults with
   SIGFPE and aborts the process.

## Impact

- **Crash (SIGFPE)** on GetSensorExposureTimeRange / status
  ProcessSensorExposureTimeChange / time-lapse / profession / AR paths when
  the HAL rational uses a scale other than exact-µs denominator `1_000_000`
  (or a larger multiple such as ns).
- **Medium:** default-build, app-callable session paths; field likelihood
  low–moderate because well-formed HAL tables often use ns scale, but any
  ms-scale / unit-scale / truncated metadata dens hit the trap. Same
  divisor-class as the beauty single-element SIGFPE already fixed.

## Minimal Counterexample

| numerator | denominator | production guard | `den/1e6` | result |
|-----------|-------------|------------------|-----------|--------|
| any | `0` | reject | — | early return |
| `10000000` | `1000000000` | accept | `1000` | `10000` µs (OK) |
| `1000` | `1` | **accept** | `0` | **SIGFPE** |
| `500` | `1000` | **accept** | `0` | **SIGFPE** |
| `1` | `999999` | **accept** | `0` | **SIGFPE** |
| `1` | `-1` | **accept** | `0` | **SIGFPE** |

Standalone confirmation of the production arithmetic
(`capture_session.cpp:3445`):

```c
int32_t numerator = 1000, denominator = 1;  // passes denominator == 0 guard
const int timeUnit = 1000000;
uint32_t value = (uint32_t)(numerator / (denominator / timeUnit));
// → Floating point exception (core dumped)  exit=136 (SIGFPE)
```

## How PBT Detected This

`pbt-native/sensor_exposure_time_pbt_test` — properties that assert the inner
divisor is non-zero for every accepted denominator:

| Property | Result |
|----------|--------|
| `MultipleOfTimeUnit_InnerDivisorNonZero` | PASS |
| `DenZero_Rejected` / `NanoScale_TenMs` | PASS |
| `AcceptedDen_InnerDivisorMustBeNonZero` | **FAIL** |
| `SmallPositiveDen_MustNotHaveZeroDivisor` | **FAIL** |
| `SmallNegativeDen_MustNotHaveZeroDivisor` | **FAIL** |
| BugDocs `DenOne` / `DenThousand` `EXPECT_DEATH` | documents SIGFPE |

## Suggested Fix

Prefer a 64-bit multiply form that is correct for any non-zero `denominator`
and removes the inner zero trap; apply once in a shared helper and replace all
6 sites:

```cpp
CHECK_RETURN_ELOG(denominator == 0, ...);
constexpr int32_t timeUnit = 1000000;
uint32_t value = static_cast<uint32_t>(
    static_cast<int64_t>(numerator) * timeUnit / denominator);
```

Minimal alternative: also reject `|denominator| < timeUnit` (or
`denominator / timeUnit == 0`) before the existing formula.
