## Summary

`Ip4RuleMap::GetNetworkAddress` computed the IPv4 CIDR network id with
`addr & (0xFFFFFFFF << (32 - mask))`. Prefix `0` is `0xFFFFFFFF << 32` —
**undefined behavior** (shift count == width, C++ [expr.shift]).

At product opt on x86 a runtime prefix of 0 wraps to `<< 0` and returns
`addr` itself. A compile-time constant `mask = 0` is poison/garbage under
clang `-O2`/`-O3`. Two distinct hosts then look like distinct `/0` networks.
Caller `OrInsert` treats equal network ids as the same firewall rule, so
bitmap OR-propagation does not fire for `0.0.0.0/0`.

Confirmed and fixed under `DTS2026071727288` (OpenHarmony !4598 / `880bee1c1`,
2026-07-31). Same special-case as sibling `GetMaskByLength(0)`.

IPv6 twin OOB is `OH-2026-NET-006` / `DTS2026081136698`. PAC `/0` shift UB is
`OH-2026-NET-002` / `DTS2026070856960`.

## Vulnerable Code

Pre-fix body (after the `mask > 32` clamp, before !4598):

```cpp
inline uint32_t GetNetworkAddress(uint32_t addr, uint32_t mask)
{
    if (mask > IPV4_MAX_PREFIXLEN) {
        mask = IPV4_MAX_PREFIXLEN;
    }
    return addr & (0xFFFFFFFF << (IPV4_MAX_PREFIXLEN - mask));  // UB when mask == 0
}
```

The clamp (`3b1b99db2`) did not cover the `/0` shift-count boundary.

## Trigger Conditions

`NetFirewallIpParam.mask` is a `uint8_t` prefix. `GetIp4AndMask` can emit
`mask == 0` for a full-range block (`IPV4_BIT_COUNT - cidrBits`).
`OrInsert(item.mask)` passes that runtime prefix into `GetNetworkAddress`.

## Impact

High — C++ UB, plus a `0.0.0.0/0` (match-any) firewall rule does not collapse
to one network id. Distinct hosts stay distinct `/0` keys; `OrInsert` bitmap
OR-propagation does not fire.

## Minimal Counterexample

```
GetNetworkAddress(1, 0)            // runtime prefix: 1; expected 0
GetNetworkAddress(0xC0A80101, 0)   // runtime prefix: 0xC0A80101; expected 0
compile-time mask = 0u             // clang -O2/-O3: poison (e.g. 32767)
```

## How PBT Detected This

`pbt-native/get_network_address_pbt_test.cpp`

Differential vs `GetMaskByLength`; algebraic `/0` unspecified
(`GetNetworkAddress(addr, 0) == 0`). Witness `addr = 1`, `mask = 0`
(runtime prefix so clang cannot constant-fold the UB).

On current master the properties **pass** — regression for !4598.

## Suggested Fix

Landed in OpenHarmony !4598:

```cpp
if (mask == 0) {
    return 0;
}
return addr & (0xFFFFFFFF << (IPV4_MAX_PREFIXLEN - mask));
```

Same special-case as `GetMaskByLength` / `vnic_manager`
(`prefix ? (0xFFFFFFFF << (32 - prefix)) : 0`).
