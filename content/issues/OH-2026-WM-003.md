## Summary

`WindowHelper::IsFloatingNumber` returns **true** for digit-less tokens
(`"."`, `"-"`, `"-."`): it filters characters (optional `-`, at most one `.`,
digits) then `return true` with **no “at least one digit” requirement**.

Config parsers treat that gate as “safe to `std::stof`” and call bare `stof`
with no `try`/`catch`:

- `WindowManagerConfig::ReadFloatNumbersConfigInfo`
- `WindowSceneConfig::ReadFloatNumbersConfigInfo`

So a digit-less float token in XML/config → gate passes →
`std::invalid_argument` uncaught on the parse path.

The same product already requires a digit in
`ScreenSettingHelper::IsNumber` (`hasDigit`). Multi-dot is already rejected
by both helpers.

Confirmed and fixed under `DTS2026072924028`.

## Vulnerable Code

`utils/include/window_helper.h` — `IsFloatingNumber` (~445–463):

```cpp
static bool IsFloatingNumber(std::string str, bool allowNeg = false)
{
    if (str.size() == 0) return false;
    int32_t i = 0;
    if (allowNeg && str.at(i) == '-') i++;
    for (; i < (int32_t)str.size(); i++) {
        if ((str.at(i) < '0' || str.at(i) > '9') &&
            (str.at(i) != '.' || std::count(str.begin(), str.end(), '.') > 1)) {
            return false;
        }
    }
    return true;  // no "at least one digit"
}
```

Call sites (`window_manager_config.cpp` / `window_scene_config.cpp`):

```cpp
if (!WindowHelper::IsFloatingNumber(num, allowNeg)) {
    return {};   // soft fail — never reached for "." / "-" / "-."
}
floatsValue.push_back(std::stof(num));  // throws std::invalid_argument
```

## Trigger Conditions

1. A float-list config / scene XML (or equivalent) contains a digit-less token
   `"."`, `"-"`, or `"-."` (with `allowNeg` where relevant).
2. `IsFloatingNumber` returns true.
3. Caller invokes bare `std::stof` → uncaught `std::invalid_argument`.

Well-formed numbers (`"1.5"`, `"42"`, `".5"`) are unaffected. Stock good
configs stay green.

## Impact

| Token | `IsFloatingNumber` | `std::stof` | Expected |
|-------|--------------------|-------------|----------|
| `"."` | **true** | throws `invalid_argument` | false / no stof |
| `"-"` (`allowNeg`) | **true** | throws | false |
| `"-."` | **true** | throws | false |
| `"1.5"`, `"42"`, `".5"` | true | ok | true |

- Soft skip (`return {}`) only runs when the validator is **false** — digit-less
  never hits it.
- **High**: live uncaught exception on a real parse path when that token
  appears. Not heap OOB; not “every device always crashes.”

## Minimal Counterexample

```text
num = "."
IsFloatingNumber(".") == true
std::stof(".") → throws std::invalid_argument (uncaught)
Expected: IsFloatingNumber(".") == false → return {}
```

## How PBT Detected This

Harness: `pbt-native/is_floating_number_pbt_test.cpp`. Contract: if
`IsFloatingNumber` is true, `stof` must not throw; digit-less tokens must be
false (sibling `ScreenSettingHelper::IsNumber`).

| Property | Result |
|----------|--------|
| `DotAloneRejected` | **FAIL** |
| `MinusAloneRejectedWhenAllowNeg` | **FAIL** |
| `MinusDotRejected` | **FAIL** |
| `DigitlessNotAccepted` | **FAIL** |
| Valid / integer / double-dot reject | PASS |

## Suggested Fix

Mirror the sibling `hasDigit` latch:

```diff
+        bool hasDigit = false;
         for (; i < static_cast<int32_t>(str.size()); i++) {
             if ((str.at(i) < '0' || str.at(i) > '9') &&
                 (str.at(i) != '.' || std::count(str.begin(), str.end(), '.') > 1)) {
                 return false;
             }
+            if (str.at(i) >= '0' && str.at(i) <= '9') {
+                hasDigit = true;
+            }
         }
-        return true;
+        return hasDigit;
```

After fix: digit-less → false; `stof` never called on those tokens; valid
floats unchanged.
