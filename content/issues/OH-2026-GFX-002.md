## Summary

`RSColor::FromBgraInt` decodes a `uint32_t` using a union whose bit-field order is reversed relative to how `AsBgraInt` encodes it. Every channel is therefore swapped on the round-trip `FromBgraInt(AsBgraInt(c))`: alpha↔blue and red↔green. Any code that serializes a color with `AsBgraInt()` and reads it back with `FromBgraInt()` gets a completely wrong color.

## Contract

The serialize-then-deserialize law must hold losslessly:

> `FromBgraInt(AsBgraInt(c)) == c` for all `RSColor` instances.

`AsBgraInt` and `FromBgraInt` are an inverse pair; both define the same BGRA bit layout.

## Vulnerable Code

`rosen/modules/render_service_base/src/common/rs_color.cpp`.

`AsBgraInt` (line 292) encodes:

```cpp
return (alpha) | (red << 8) | (green << 16) | (blue << 24);
```

Bit layout: `[0:7]=alpha, [8:15]=red, [16:23]=green, [24:31]=blue`

`FromBgraInt` (line 310) decodes with a reversed union field order:

```cpp
union {
    struct {
        uint8_t blu_ : 8;   // bits[0:7]   → reads alpha (WRONG: should be blue)
        uint8_t gre_ : 8;   // bits[8:15]  → reads red   (WRONG: should be green)
        uint8_t red_ : 8;   // bits[16:23] → reads green (WRONG: should be red)
        uint8_t alp_ : 8;   // bits[24:31] → reads blue  (WRONG: should be alpha)
    };
    uint32_t bgra_;
} color;
color.bgra_ = bgra;
return RSColor(color.red_, color.gre_, color.blu_, color.alp_);
```

## Root Cause

The union bit-fields `blu_, gre_, red_, alp_` are laid out low-to-high, so the first-declared field occupies bits `[0:7]`. `AsBgraInt` puts `alpha` in `[0:7]`, but `FromBgraInt`'s first field is `blu_`, so `blu_` reads what `AsBgraInt` wrote as `alpha`. Every channel is consequently swapped:

| Union field | Reads bits | Gets | Should get |
|---|---|---|---|
| `blu_` | [0:7] | alpha | blue |
| `gre_` | [8:15] | red | green |
| `red_` | [16:23] | green | red |
| `alp_` | [24:31] | blue | alpha |

## Minimal Counterexample

Minimal input: `R=0, G=0, B=1, A=0` (shrunk from a random 4-tuple in 8 tests).

```cpp
RC_ASSERT(decoded.GetBlue() == static_cast<int16_t>(b))
// Expands to: 0 == 1
```

| Channel | Expected | Got |
|---|---|---|
| Red | 0 | 0 (green) |
| Green | 0 | 0 (red) |
| Blue | 1 | 0 (alpha) |
| Alpha | 0 | 1 (blue) |

## How PBT Detected It

Detected via algebraic round-trip property `RSColorBgraPBT.BgraRoundTrip`: serialize-then-deserialize must be the identity. Because every channel is swapped, the property fails for any input where adjacent channels differ.

## Impact

- Silent data corruption on all BGRA color round-trips
- Alpha↔blue and red↔green swaps on every encode/decode cycle
- BGRA is commonly used in graphics buffer/pixel formats; any path that writes a color via `AsBgraInt()` then reads it back via `FromBgraInt()` produces a completely wrong color, with no crash or error signal

## Suggested Fix

Reverse the union field order to match `AsBgraInt`'s bit layout:

```cpp
RSColor RSColor::FromBgraInt(uint32_t bgra)
{
    union {
        struct {
            uint8_t alp_ : 8;   // bits[0:7]   = alpha (matches AsBgraInt)
            uint8_t red_ : 8;   // bits[8:15]  = red
            uint8_t gre_ : 8;   // bits[16:23] = green
            uint8_t blu_ : 8;   // bits[24:31] = blue
        };
        uint32_t bgra_;
    } color;
    color.bgra_ = bgra;
    return RSColor(color.red_, color.gre_, color.blu_, color.alp_);
}
```
