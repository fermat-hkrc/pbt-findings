## Summary

`PhotoOutput::IsAutoHighQualityPhotoSupported` walks
`OHOS_ABILITY_HIGH_QUALITY_SUPPORT` as `(mode, flag)` pairs and also reads
`item.data.u8[1]` as the default-mode flag. Three defects in one function:

1. Default read uses `u8[1]` with no `count >= 2`.
2. Pair walk bounds only `i < item.count`, then always reads `u8[i + 1]`.
3. Loop still runs when `FindCameraMetadataItem` fails (`item` stack-uninit).

`count == 1` or odd length → heap **OOB read**. Find miss → walk garbage
`count` / `data`. App-facing `IsAutoHighQualityPhotoSupported` /
`EnableAutoHighQualityPhoto`. Not High: well-formed even tables OK.

Same pair-walk class as deferred / mirror / eq_focus (those have their own
tickets). Confirmed and fixed by developers (`DTS2026080813420`).

## Vulnerable Code

`frameworks/native/camera/base/src/output/photo_output.cpp` —
`PhotoOutput::IsAutoHighQualityPhotoSupported` (~1159–1193):

```cpp
camera_metadata_item_t item;  // not zero-init
int32_t ret = Camera::FindCameraMetadataItem(
    metadata->get(), OHOS_ABILITY_HIGH_QUALITY_SUPPORT, &item);
if (ret == CAM_META_SUCCESS) {
    isAutoHighQualityPhotoSupported = (item.data.u8[1] == 1) ? 0 : -1;
}

int headLenPerMode = 2;
for (int i = 0; i < static_cast<int>(item.count); i += headLenPerMode) {
    if (currentSceneMode == static_cast<int>(item.data.u8[i])) {
        isAutoHighQualityPhotoSupported =
            (item.data.u8[i + 1] == 1) ? 0 : -1;  // odd count → OOB
    }
}
```

Root cause: pair walk + default `u8[1]` with no remaining-length check;
Find-fail path not gated.

## Trigger Conditions

1. HAL ability is short (`count == 1`) or odd, **or** Find fails.
2. App queries / enables auto high-quality photo.
3. Default `u8[1]` or last-pair `u8[i+1]` reads past the blob (or uninit
   `item` on Find miss).

## Impact

- Heap OOB read on app-facing high-quality support query.
- Find miss → UB on stack-uninitialized `item`.
- Medium: even-length HAL tables (normal devices) unaffected; field hit
  needs truncated/odd metadata or Find miss.
- One function / one fix covers default + pair + Find-fail.

## Minimal Counterexample

| case / blob | Production |
|-------------|------------|
| Find OK, even `{mode,flag,…}` | OK |
| Find OK, `count == 1` | **OOB** on default `u8[1]` |
| Find OK, odd length 3 | **OOB** on last-pair `u8[i+1]` |
| Find fail | loop uses **uninit** `item` |

## Suggested Fix

Gate on Find + `count >= 2`, then bound the pair walk:

```cpp
if (ret != CAM_META_SUCCESS || item.count < 2) {
    return CAMERA_OK;  // unsupported; do not touch item.data
}
isAutoHighQualityPhotoSupported = (item.data.u8[1] == 1) ? 0 : -1;
for (int i = 0; i + 1 < static_cast<int>(item.count); i += 2) {
    if (currentSceneMode == static_cast<int>(item.data.u8[i])) {
        isAutoHighQualityPhotoSupported =
            (item.data.u8[i + 1] == 1) ? 0 : -1;
    }
}
```

After fix: short/odd props PASS; even props stay PASS; Find-fail never
touches `item.data`.
