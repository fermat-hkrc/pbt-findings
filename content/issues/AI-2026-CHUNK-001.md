## Summary

`chunk_markdown_v2` drops whitespace characters (spaces and newlines) at every chunk boundary. When a long message is split, `.lstrip()` strips the split character, making the reassembled message shorter than the original. A message split into N chunks loses N-1 characters silently.

## Vulnerable Code

```python
def chunk_markdown_v2(text: str):
    safe = escape_markdown_v2_preserve_formatting(text)
    chunks = []
    s = safe

    while len(s) > MAX_LEN:
        split_at = s.rfind("\n", 0, MAX_LEN)
        if split_at == -1:
            split_at = s.rfind(" ", 0, MAX_LEN)
        if split_at == -1:
            split_at = MAX_LEN

        chunk = s[:split_at]
        chunks.append(chunk)

        s = s[split_at:].lstrip()   # ← BUG: strips the split character

    chunks.append(s)
    return chunks
```

## Root Cause

`split_at` points to the whitespace used as the split boundary. `s[:split_at]` correctly excludes it from the current chunk. But `s[split_at:]` starts at that character, and `.lstrip()` strips it — along with any additional leading whitespace — from the next chunk. The boundary character belongs to neither chunk.

**Space split:**
```
"hello world" (split_at=5, the space)
s[:5]          = "hello"
s[5:].lstrip() = "world"   ← space lost
```

**Newline split:**
```
"line1\nline2" (split_at=5, the newline)
s[:5]          = "line1"
s[5:].lstrip() = "line2"   ← newline lost
```

## Reproduction

```python
from connect.adapters.channels.platforms.telegram.workflows.handlers._execute_and_reply import chunk_markdown_v2

# Space-split: "a " * 2000 = 4000 chars
chunks = chunk_markdown_v2("a " * 2000)
reassembled = "".join(chunks)
print(f"Characters lost: {4000 - len(reassembled)}")
# Output: Characters lost: 1

# Newline-split
chunks = chunk_markdown_v2("x\n" * 2000)
reassembled = "".join(chunks)
print(f"Characters lost: {4000 - len(reassembled)}")
# Output: Characters lost: 1
```

## Impact

- **Silent data loss** — characters dropped without any error or warning
- **User-facing** — every long Telegram bot message (> ~3900 chars) is corrupted
- **Cumulative** — N chunks lose N-1 characters

## Proposed Fix

```python
while len(s) > MAX_LEN:
    split_at = s.rfind("\n", 0, MAX_LEN)
    if split_at != -1:
        # Split at newline — keep it at start of next chunk
        chunks.append(s[:split_at])
        s = s[split_at:]          # keep the \n
    else:
        split_at = s.rfind(" ", 0, MAX_LEN)
        if split_at != -1:
            # Split at space — discard the boundary space
            chunks.append(s[:split_at])
            s = s[split_at + 1:]  # skip the space, no lstrip
        else:
            # Hard split — no whitespace found
            chunks.append(s[:MAX_LEN])
            s = s[MAX_LEN:]
chunks.append(s)
```

## How This Was Found

Property-based testing with [Hypothesis](https://hypothesis.readthedocs.io/):

```python
@given(st.text(min_size=0, max_size=MAX_LEN * 3))
@example("a " * 2000)
@example("x\n" * 2000)
def test_roundtrip(text):
    chunks = chunk_markdown_v2(text)
    escaped = escape_markdown_v2_preserve_formatting(text)
    assert "".join(chunks) == escaped  # FAILS for long inputs
```
