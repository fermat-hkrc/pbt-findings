## Summary

`SetSpace` walks from `prevIndex = -1`, `prevPos = 0`. For `lanes > 1`,
`LanesFloor(-1)` is 0, so `LineCount(-1, first)` undercounts by one line.
The first cached line is written at `startPos = 0` instead of
`(index / lanes) * (H + G)`. `lanes == 1` happens to match.

**Confirmed and fixed** under `DTS2609150107715`.

## Contract

First cached item after `SetSpace` has
`startPos = (index / lanes) * (estimateItemSize_ + spaceWidth_)`.

## Vulnerable Code

```cpp
int32_t prevIndex = -1;
float prevPos = 0.0f;   // always origin of line 0
```

## Minimal Counterexample

`lanes=2`, first index 2, H=100, G=20 → `startPos=0` (expected 120).

## How PBT Detected This

`WindowNotFromZeroMatchesPackedGeometry` FAIL; `lanes==1` and first-key-0 PASS.

## Suggested Fix

Seed `prevIndex = beginIdx - 1`,
`prevPos = (beginIdx / lanes_) * (estimateItemSize_ + spaceWidth_)`.
