## Summary

`IsDoubleRegex` accepts the double grammar via `operator>>(double&)` /
`strtod`, then `HCameraService::SetParameters` calls unguarded `std::stoi` on
the same string for `META_TYPE_BYTE` (and the same pattern fans out across
`SetParameterSetting` integer/float sites). Strings the double guard accepts
but `std::stoi` rejects — e.g. `"100000000000"`, `".5"` — throw
`std::out_of_range` / `std::invalid_argument` with **no `try`/`catch`** →
`std::terminate()` → camera service abort.

Trigger is **config-dependent**, not attacker-controlled: the throwing string
comes from vendor camera config via `kvPairs`, not the caller's raw input.
Confirmed and fixed by developers (`DTS2026071303295`).

## Vulnerable Code

`services/camera_service/src/camera_util.cpp` — `IsDoubleRegex`:

```cpp
bool IsDoubleRegex(const std::string& input)
{
    std::istringstream iss(input);
    double val;
    iss >> val;
    return iss.eof() && !iss.fail();
}
```

Sole in-tree guard caller — `hcamera_service.cpp` (~1731) inside
`HCameraService::SetParameters`:

```cpp
CHECK_CONTINUE_ELOG(!IsDoubleRegex(valueStr)
    || ((tagType == META_TYPE_BYTE) && (std::stoi(valueStr) < MIN_UINT8 || std::stoi(valueStr) > MAX_UINT8)),
    "HCameraService::SetParameters invalid config, value:%{public}s", valueStr.c_str());
```

`SetParameterSetting` (~3279+) then fans the same `valueStr` to unguarded
`std::stoi` / `stof` / `stoll` / `stod` per tag type — one root cause, six
sites.

Root cause: double predicate is the wrong guard for integer/float stdlib
parses whose accepted grammar is narrower (or throws on magnitude).

## Trigger Conditions

1. Vendor camera config stores a byte-typed (or other typed) parameter value
   accepted by `IsDoubleRegex` but rejected by the actual parse
   (`"100000000000"`, `".5"`, `1e999` for `stof`, …).
2. `SetParameters` / `SetParameterSetting` reads `valueStr` from `kvPairs`
   (caller `value` is only a **key**).
3. Unguarded `std::stoi` / `stof` / … throws; no catch in `hcamera_service.cpp`
   → `std::terminate()` → service abort.

Unrecognized caller keys default-insert `""`, which `IsDoubleRegex` rejects
(skip) — not the crash path.

## Impact

- System camera service aborts on bad/stale config value; camera unavailable
  until restart.
- No data corruption; service self-recovers on restart.
- Not a security / remote-DoS vector: trigger requires misbehaving device
  config, not a crafted request.
- Medium: real ungraceful crash on live service path; config-integrity issue.
- Extra parse sites raise trip probability, not per-incident impact — fix once
  as a shared non-throwing helper.

## Minimal Counterexample

| input | IsDoubleRegex | std::stoi |
|-------|---------------|-----------|
| `"100000000000"` | **true** | throws `out_of_range` (10^11 > `INT_MAX`) |
| `".5"` | **true** | throws `invalid_argument` |
| `"inf"` / `"nan"` | false on this libstdc++ | — (not witnesses here) |

## How PBT Detected This

`is_double_regex_pbt_test` — REAL compiled `camera_util.cpp` closure (not
reimplemented). Oracle: Differential in-tree caller contract — every string
the guard accepts must keep caller `std::stoi` from throwing.

| Property | Result |
|----------|--------|
| `AcceptedKeepsStoiSafe` | **FAIL** (shrink → `"100000000000"`) |
| Robustness / determinism / `stod` agreement / canonical decimal / int⇒double | PASS |

```bash
cmake -B pbt-native/build pbt-native
cmake --build pbt-native/build --target is_double_regex_pbt_test -j"$(nproc)"
cd pbt-native/build && ctest -R is_double_regex_pbt_test --output-on-failure
```

## Suggested Fix

Prefer a single non-throwing parse helper (e.g. `std::from_chars`) used from
`SetParameterSetting`, and drop the float predicate from in front of integer
parses. Minimal framing:

```cpp
int iv = 0;
auto [ptr, ec] = std::from_chars(valueStr.data(),
                                 valueStr.data() + valueStr.size(), iv);
bool bad = (ec != std::errc{}) || (iv < MIN_UINT8) || (iv > MAX_UINT8);
CHECK_CONTINUE_ELOG(bad, ...);
```

Less preferred: wrap `std::stoi` in `try`/`catch` and treat throw as invalid
config — preserves the grammar mismatch.
