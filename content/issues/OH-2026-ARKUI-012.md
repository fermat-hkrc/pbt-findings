## Summary

`GetTargetIndexInfoWithBenchMark` seeds `scrollToIndex` when the target is
outside the cached matrix. On `isTargetBackward` it always sets:

```cpp
benchmarkIndex = lastItem + 1
mainStartIndex = lastLine + 1
```

If the last cached line is **not full**, `lastItem+1` still belongs on
`lastLine`. When `target == lastItem+1` the packing loop does not run, so the
viewport starts at `(lastLine+1, lastItem+1)` — one main line too far down.
No crash.

**Confirmed** under `DTS2609150153174` (accepted in the internal DTS system;
**not fixed yet**).

## Contract

Backward seed + packing from `lastItem+1` must yield the same
`(startMainLineIndex_, startIndex_)` as packing `[0, target]` from line 0.
For a regular grid (`irregularIndexes` empty, span 1) that is
`(T / C, (T / C) * C)`. Leftover cross slots on the last cached line stay
on that line.

Callers only take backward when `targetIndex` is past the last matrix item
(`grid_scroll_layout_algorithm.cpp:1177-1180`).

## Vulnerable Code

`grid_scroll_with_options_layout_algorithm.cpp` (~89–96):

```cpp
    int32_t benchmarkIndex = (isTargetBackward && !info_.gridMatrix_.empty())
                                 ? info_.gridMatrix_.rbegin()->second.rbegin()->second + 1
                                 : 0;
    int32_t mainStartIndex = (isTargetBackward && !info_.gridMatrix_.empty())
                                 ? info_.gridMatrix_.rbegin()->first + 1
                                 : 0;
```

Always `lastLine+1` / `lastItem+1`. The inner loop then starts every line
with a full `crossCount_` reserve. Leftover slots on the last cached line
are never offered to `lastItem+1`.

## Minimal Counterexample

```cpp
// crossCount_ = 8
// gridMatrix_ = { 0: { 0: 0 } }   // only item 0 on line 0
GetTargetIndexInfoWithBenchMark(wrapper, /*isTargetBackward=*/true, /*targetIndex=*/1);

// Expected: startMainLineIndex_ = 0, startIndex_ = 0
// Actual:   startMainLineIndex_ = 1, startIndex_ = 1
```

## How PBT Detected This

Harness: `test/pbt/core/pattern/grid/grid_get_target_index_info_pbt_test.cpp`.
Oracle: metamorphic vs packing from 0 (`BackwardRegularPrefixAgreesWithForward`).

| Property | Result |
|----------|--------|
| `BackwardRegularPrefixAgreesWithForward` | **FAIL** (partial last line) |
| `…regression_partial_last_line` (`C=8`, `{0:0}`, target `1`) | **FAIL** |

## Impact

`scrollToIndex` on a Grid with `layoutOptions` can place the target one main
line too far down when the last cached line still has leftover cross slots.
Does not trigger on `isTargetBackward=false` or when the last cached line
is full.

## Suggested Fix

If the last cached line is not full, drop the backward shortcut and pack
from 0 (same as `isTargetBackward=false`):

```cpp
if (isTargetBackward && !info_.gridMatrix_.empty() &&
    static_cast<int32_t>(info_.gridMatrix_.rbegin()->second.size()) < info_.crossCount_) {
    benchmarkIndex = 0;
    mainStartIndex = 0;
}
```
