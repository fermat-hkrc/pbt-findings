## Summary

Both `validate_kb_name` and `validate_memory_name` fail to block the DEL control character (`\x7f`, ASCII 127). The regex pattern `\x00-\x1f` blocks control characters 0-31 but misses DEL at position 127 — an unintentional gap contradicting the error message which says "控制字符" (control characters).

## Vulnerable Code

### `knowledge_base.py`

```python
INVALID_KB_NAME_CHARS = re.compile(r'[<>:"/\\|?*\x00-\x1f]')
#                                                   ^^^^^^^^
#                                                   Blocks 0x00-0x1f, misses 0x7f

def validate_kb_name(name: str) -> str:
    if not name or not name.strip():
        raise ValueError("知识库名称不能为空")
    trimmed_name = name.strip()
    if trimmed_name != name:
        raise ValueError("知识库名称不能以空格开头或结尾")
    if INVALID_KB_NAME_CHARS.search(trimmed_name):
        raise ValueError('知识库名称不能包含以下字符: < > : " / \\ | ? * 以及控制字符')
    return name
```

### `memory_base.py`

```python
INVALID_MEMORY_NAME_CHARS = re.compile(r'[<>:"/\\|?*\x00-\x1f]')
#                                                      ^^^^^^^^
#                                                      Same bug

def validate_memory_name(name: str) -> str:
    if not name or not name.strip():
        raise ValueError("记忆库名称不能为空")
    trimmed_name = name.strip()
    if trimmed_name != name:
        raise ValueError("记忆库名称不能以空格开头或结尾")
    if INVALID_MEMORY_NAME_CHARS.search(trimmed_name):
        raise ValueError('记忆库名称不能包含以下字符: < > : " / \\ | ? * 以及控制字符')
    return name
```

## Reproduction

```python
from openjiuwen_studio.schemas.kb_base import validate_kb_name
from openjiuwen_studio.schemas.memory_base import validate_memory_name

# DEL character (0x7f) passes validation
kb_name = "myproject\x7f"
memory_name = "mydata\x7f"

result_kb = validate_kb_name(kb_name)     # accepted: 'myproject\x7f'
result_mem = validate_memory_name(memory_name)  # accepted: 'mydata\x7f'
```

## Impact

- **Homograph attack:** `"admin"` vs `"admin\x7f"` look identical in UI but are different strings
- **Duplicate bypass:** Names like `"kb_name"` and `"kb_name\x7f"` pass duplicate checks but appear identical to users
- **Log injection:** DEL can interfere with log parsing and monitoring
- **Windows filesystem:** DEL is invalid in filenames — causes errors if names are used as directory names
- **Invisible character:** Users see `"myproject"` but actual value is `"myproject\x7f"`
- **Encoding issues:** Some databases treat DEL as a special character

## Root Cause

The regex `\x00-\x1f` covers ASCII control characters 0-31, but DEL is `\x7f` (127) — outside this range. The error message says "控制字符" (control characters), showing intent to block all control characters, not just 0-31.

## Suggested Fix

Add `\x7f` to both regex patterns:

```python
INVALID_KB_NAME_CHARS = re.compile(r'[<>:"/\\|?*\x00-\x1f\x7f]')
INVALID_MEMORY_NAME_CHARS = re.compile(r'[<>:"/\\|?*\x00-\x1f\x7f]')
```

Or more comprehensively, block all C0 and C1 control characters:

```python
INVALID_KB_NAME_CHARS = re.compile(r'[<>:"/\\|?*\x00-\x1f\x7f-\x9f]')
INVALID_MEMORY_NAME_CHARS = re.compile(r'[<>:"/\\|?*\x00-\x1f\x7f-\x9f]')
```

## How This Was Found

Property-based testing with [Hypothesis](https://hypothesis.readthedocs.io/). `test_del_rejected` generates strings containing `\x7f` and asserts all raise `ValueError`:

```python
@given(st.text(alphabet=chr(0x7f), min_size=1, max_size=5))
def test_del_rejected(s):
    name = "valid" + s + "name"
    with pytest.raises(ValueError, match="控制字符"):
        validate_kb_name(name)
    with pytest.raises(ValueError, match="控制字符"):
        validate_memory_name(name)
```
