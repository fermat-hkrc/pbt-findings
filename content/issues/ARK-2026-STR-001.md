## Summary

`RemoveSlashFromBothEnds` strips leading/trailing `/` delimiters for JS-
regex-style `/pattern/` reserved lists. The guard `!empty() && front=='/' &&
back=='/'` passes for a single `"/"` (front and back are the same character),
so `erase()` empties the string and `pop_back()` runs on **empty** — UB.
libstdc++ often underflows `size()` to ~7.2e16, corrupting the string state.
The guard should require `size() >= 2` for a true delimiter pair. Not High:
panda_guard tooling path, not device runtime; reserved-list entry must be
exactly `"/"`. Confirmed and fixed by developers (`DTS2026073112258`).

## Vulnerable Code

`panda_guard/util/string_util.cpp` — `RemoveSlashFromBothEnds` (~159):

```cpp
void RemoveSlashFromBothEnds(std::string &str)
{
    // BUG: single "/" passes front==back=='; erase empties → pop_back UB
    if (!str.empty() && str.front() == '/' && str.back() == '/') {
        str.erase(str.begin());
        str.pop_back();  // UB on "/"
    }
}
```

For `s == "/"`: `front() == back() == '/'` is true (same char). Both calls
run on one character.

Callers: `guard_options.cpp` — strip `/…/` delimiters on
`universalReservedList` / `universalReservedFileNames` (~83, ~110).

## Trigger Conditions

1. Reserved list contains exactly a single `"/"` entry.
2. `RemoveSlashFromBothEnds` runs to strip JS-regex delimiters.
3. Guard passes (same char is both front and back).
4. `erase()` makes string empty; `pop_back()` triggers UB.

Normal `/pattern/` strings have `size() >= 2` and are unaffected.

## Impact

| Path | Result |
|------|--------|
| Reserved list contains exactly `"/"` | UB at strip; `size()` underflows to ~7.2e16; corrupted string state |
| Normal `/pattern/` strings | Unaffected |
| Downstream use of corrupted string | Possible SIGSEGV / OOB read if iterated or sized |

- Medium: real UB, but panda_guard tooling path + uncommon `"/"` token.
- Honest limits: not “all apps leak env on device”; this is obfuscation config.

## Minimal Counterexample

| Input | Expected size/content | Actual (libstdc++ release) |
|-------|----------------------|----------------------------|
| `"/"` | size 1, `"/"` (no-op) | size **72057594037927935**; data corrupted |
| `"//"` | `""` | OK |
| `"/a/"` | `"a"` | OK |
| `"a"` / `"/a"` / `"a/"` | unchanged | OK |

## Suggested Fix

Require `size() >= 2` for a true delimiter pair:

```diff
 void RemoveSlashFromBothEnds(std::string &str)
 {
-    if (!str.empty() && str.front() == '/' && str.back() == '/') {
+    if (str.size() >= 2U && str.front() == REGEX_DELIMITER && str.back() == REGEX_DELIMITER) {
         str.erase(str.begin());
         str.pop_back();
     }
 }
```

Where `REGEX_DELIMITER = '/'` and `constexpr size_t SLASH_PAIR_LEN = 2U`. After
fix: `"/"` is a no-op (size stays 1); `"//"` / `/a/` stripped correctly.
