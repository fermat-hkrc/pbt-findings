## Summary

`CaptureSession::UpdateDeviceDeferredability` walks
`OHOS_ABILITY_DEFERRED_IMAGE_DELIVERY` as `(mode, type)` pairs. The **photo**
loop bounds only `i < item.count` then reads `item.data.u8[i + 1]` on every
even `i`. Odd `item.count` → last even index has `i + 1 == count` → heap
**OOB read** while filling `modeDeferredType_`.

The **video** walk in the same function already uses `i + 1 < item.count`.
Not High: needs truncated/odd HAL ability blob; well-formed even tables are
fine.

Confirmed and fixed by developers (`DTS2026072716582`).

## Vulnerable Code

`frameworks/native/camera/base/src/session/capture_session.cpp` —
`CaptureSession::UpdateDeviceDeferredability` (~942–976):

```cpp
// PHOTO — buggy
for (uint32_t i = 0; i < item.count; i++) {
    if (i % DEFERRED_MODE_DATA_SIZE == 0) { // 2
        deviceInfo->modeDeferredType_[item.data.u8[i]] =
            static_cast<DeferredDeliveryImageType>(item.data.u8[i + 1]);
    }
}

// VIDEO — same function, already safe
for (uint32_t i = 0; i + 1 < item.count; i++) {
    if (i % DEFERRED_MODE_DATA_SIZE == 0) {
        deviceInfo->InsertModeVideoDeferredType(item.data.u8[i], item.data.u8[i + 1]);
    }
}
```

## Trigger Conditions

1. HAL ability / metadata supplies `OHOS_ABILITY_DEFERRED_IMAGE_DELIVERY`
   with odd `item.count` (e.g. length 1 or 3).
2. Session setup runs `UpdateDeviceDeferredability` after `BeginConfig`.
3. Photo loop reaches last even `i`; `item.data.u8[i + 1]` reads past the blob.

## Impact

- **Heap OOB read** while filling `modeDeferredType_` during session setup.
- **Medium:** even-length HAL tables (normal devices) unaffected; field hit
  needs truncated/odd metadata. FW bound still wrong vs the video twin in the
  same function.
- Same class as other ability pair walks already fixed with
  `i + offset < count`.

## Minimal Counterexample

| `item.count` / blob | Photo | Video |
|---------------------|-------|-------|
| 0 / empty | OK | OK |
| 2, 4 (even) | OK | OK |
| 1 (`{mode}`) | **OOB** `u8[1]` | OK (no pair) |
| 3 (`{m0,t0,m1}`) | **OOB** `u8[3]` | OK (one pair; orphan skipped) |

## Suggested Fix

Match the video loop in the same function:

```diff
-    for (uint32_t i = 0; i < item.count; i++) {
+    for (uint32_t i = 0; i + 1 < item.count; i++) {
         if (i % DEFERRED_MODE_DATA_SIZE == 0) {
             deviceInfo->modeDeferredType_[item.data.u8[i]] =
                 static_cast<DeferredDeliveryImageType>(item.data.u8[i + 1]);
         }
     }
```

Contract: incomplete trailing pair is skipped (orphan mode byte dropped).
After fix: `Photo_OddCount_MustNotOob` PASS; even/empty props stay PASS.
