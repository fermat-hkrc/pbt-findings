## Summary

`GridLayoutInfo::GetContentHeightOfRegularGrid()` returns a negative content height when the grid has zero items and `mainGap` is positive. The empty-grid case falls through the modulo branch and subtracts `mainGap` from zero, violating the invariant that layout dimensions must be non-negative.

## Vulnerable Code

```cpp
float GridLayoutInfo::GetContentHeightOfRegularGrid(float mainGap) const
{
    float res = 0.0f;
    if (crossCount_ == 0 || lineHeightMap_.empty()) {
        return res;
    }
    auto childrenCount = childrenCount_ + repeatDifference_;
    float lineHeight = GetTotalLineHeight(0.0f) / static_cast<float>(lineHeightMap_.size());
    auto lines = (childrenCount) / crossCount_;
    for (int i = 0; i < lines; ++i) {
        auto it = lineHeightMap_.find(i);
        res += (it != lineHeightMap_.end() ? it->second : lineHeight) + mainGap;
    }
    if (childrenCount % crossCount_ == 0) {
        return res - mainGap;
    }
    auto lastLine = lineHeightMap_.find(lines);
    return res + (lastLine != lineHeightMap_.end() ? lastLine->second : lineHeight);
}
```

## Root Cause

When `childrenCount_ == 0` and `repeatDifference_ == 0`:

- `childrenCount = 0`
- `lines = 0 / crossCount_ = 0`
- the loop does not execute
- `res` stays `0.0f`
- `childrenCount % crossCount_ == 0` is true
- the function returns `0.0f - mainGap`

So the function produces `-mainGap` for an empty grid whenever `mainGap > 0`.

## Reproduction

```cpp
GridLayoutInfo info;
info.crossCount_ = 2;
info.childrenCount_ = 0;
info.repeatDifference_ = 0;
info.lineHeightMap_[0] = 100.0f;

float height = info.GetContentHeight(10.0f);
// buggy version: -10.0f
// expected: 0.0f
```

## Impact

- Negative layout height for empty grids
- Incorrect parent layout and scroll calculations
- Visual glitches during empty-to-populated transitions
- Potential assertion failures in layout validation code

## How This Was Detected

The bug was found by property-based testing with the invariant:

> layout height must never be negative

A minimal property looks like this:

```cpp
HWTEST_F(GridLayoutInfoPbtTest, ContentHeight_AlwaysNonNegative, TestSize.Level1)
{
    PBT_RUN(1000) {
        GridLayoutInfo info;
        info.crossCount_ = PBT_CHOOSE(1, 10);
        info.childrenCount_ = PBT_CHOOSE(0, 100);
        float mainGap = static_cast<float>(PBT_CHOOSE(0, 100));

        float height = info.GetContentHeight(mainGap);
        EXPECT_GE(height, 0.0f);
    }
}
```

The empty-grid boundary case (`childrenCount = 0`, `mainGap > 0`) violates the property immediately.

## Why Unit Tests Missed It

Existing example-based tests exercised non-empty grids and normal line calculations, but not the empty-grid + positive-gap combination. This bug is easy to overlook in hand-written tests because the bad path only appears when the count is exactly zero and the modulo branch subtracts a gap from an empty accumulator.

PBT is effective here because it systematically samples the boundary values that are easy to miss by inspection.

## Suggested Fix

Return zero explicitly for empty grids before the modulo branch:

```cpp
float GridLayoutInfo::GetContentHeightOfRegularGrid(float mainGap) const
{
    float res = 0.0f;
    if (crossCount_ == 0 || lineHeightMap_.empty()) {
        return res;
    }
    auto childrenCount = childrenCount_ + repeatDifference_;
    if (childrenCount == 0) {
        return 0.0f;
    }
    float lineHeight = GetTotalLineHeight(0.0f) / static_cast<float>(lineHeightMap_.size());
    auto lines = (childrenCount) / crossCount_;
    for (int i = 0; i < lines; ++i) {
        auto it = lineHeightMap_.find(i);
        res += (it != lineHeightMap_.end() ? it->second : lineHeight) + mainGap;
    }
    if (childrenCount % crossCount_ == 0) {
        return res - mainGap;
    }
    auto lastLine = lineHeightMap_.find(lines);
    return res + (lastLine != lineHeightMap_.end() ? lastLine->second : lineHeight);
}
```

## Verification

After the fix, the PBT properties should pass:

- non-negativity
- monotonicity
- zero-gap consistency
- empty-grid returns zero
