## Summary

`GridLayoutInfo::FindInMatrix(0)` unconditionally returns `gridMatrix_.begin()` instead of searching for item `0`. When the matrix is non-empty but starts at a row index greater than `0`, `begin()` points to a row that does not contain item `0`. This violates the documented contract that `FindInMatrix(index)` must return `map::end()` when the item is absent.

Fix landed in PR: `https://gitcode.com/openharmony/arkui_ace_engine/pull/86261`.

## Contract

From `frameworks/core/components_ng/pattern/grid/grid_layout_info.h`:

```cpp
/**
 * @brief Perform a binary search to find item with [index] in the gridMatrix_.
 *
 * @param index target item index
 * @return iterator to that item, or map::end if not found.
 */
std::map<int32_t, std::map<int32_t, int32_t>>::const_iterator FindInMatrix(int32_t index) const;
```

Required behavior:
- return iterator to row containing `index` when present
- return `gridMatrix_.end()` when absent

## Vulnerable Code

```cpp
MatIter GridLayoutInfo::FindInMatrix(int32_t index) const
{
    if (crossCount_ == 0) {
        return gridMatrix_.end();
    }
    if (index == 0) {
        return gridMatrix_.begin();   // BUG: skips search, assumes begin() contains item 0
    }
    // binary search follows...
}
```

## Root Cause

The `index == 0` fast path assumes item `0` is always located in the first row of `gridMatrix_`. That assumption is false when:
- `gridMatrix_` is non-empty
- visible/cached rows start at row index `> 0`
- item `0` is not in the current matrix window

In that case, `begin()` is a valid iterator to the wrong row, so callers receive a non-`end()` result that does not contain the requested item.

## Minimal Counterexample

```cpp
GridLayoutInfo info;
info.crossCount_ = 1;
info.gridMatrix_[5][0] = 10;  // only row 5, only item 10 — item 0 absent

auto it = info.FindInMatrix(0);

// Expected: gridMatrix_.end()
// Actual:   gridMatrix_.begin() -> row 5
```

## Existing Oracle in Unit Tests

`test/unittest/core/pattern/grid/layout_info_test.cpp` already contains an oracle that the returned row must actually contain the requested item:

```cpp
void CheckEachIndex(const GridLayoutInfo& info, int32_t maxIdx)
{
    for (int i = 0; i <= maxIdx; ++i) {
        auto it = info.FindInMatrix(i);
        EXPECT_NE(it, info.gridMatrix_.end());
        bool foundFlag = false;
        for (auto [_, item] : it->second) {
            if (item == i) { foundFlag = true; break; }
        }
        EXPECT_TRUE(foundFlag);
    }
}
```

The bug violates this oracle whenever `FindInMatrix(0)` returns `begin()` for a row that does not contain item `0`.

## Why Existing Tests Missed It

Existing example-based tests only exercised:
- matrices that actually contain item `0` in the first row
- the empty-matrix absent case

The empty-matrix test accidentally masks the bug because `begin() == end()` when the map is empty.

Untested case:
- `index == 0`
- `gridMatrix_` is non-empty
- first row index `> 0`
- item `0` absent

This is the real failing configuration.

## How PBT Detected It

Property-based test in `test/unittest/core/pattern/grid/find_in_matrix_pbt_test.cpp` encoded the contract directly:

```cpp
bool present = ExistsInMatrix(info.gridMatrix_, x);
auto it = info.FindInMatrix(x);
EXPECT_EQ(it != info.gridMatrix_.end(), present);
```

Boundary-biased generation allowed row numbering to start above zero:

```cpp
int startRow = PBT_CHOOSE(0, 10);
int nextItem = PBT_CHOOSE(0, 5);
```

Once `startRow > 0` and `FindInMatrix(0)` is exercised, the bug appears immediately.

Example counterexample from the report:

```cpp
gridMatrix_ = {{5, {{0, 10}}}}, crossCount_ = 1
FindInMatrix(0) should return end()
Bug: returns begin() = row 5, which contains item 10 instead of 0
```

## Impact

- Wrong iterator returned for absent item `0`
- Callers may skip rebuild/fill logic because result is non-`end()`
- Incorrect row/position calculations for scroll-to-index and update paths
- Silent wrong behavior, not a crash

Concrete affected paths called out in the report:
- `FindJumpLineIdx(jumpIdx)` when `jumpIdx == 0`
- `GetChildrenUpdated()` paths when `updateIdx == 0`
- `GetItemPos(0)` returning wrong coordinates instead of `{-1, -1}`

## Suggested Fix

Remove the unsafe shortcut and let the normal search handle `index == 0`:

```cpp
MatIter GridLayoutInfo::FindInMatrix(int32_t index) const
{
    if (crossCount_ == 0) {
        return gridMatrix_.end();
    }
    // removed: if (index == 0) return gridMatrix_.begin();

    size_t count = gridMatrix_.size();
    // ... rest unchanged
}
```

If a fast path is required, it must first verify that `begin()` actually contains item `0`.
