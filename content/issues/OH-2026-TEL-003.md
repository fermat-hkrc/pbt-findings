## Summary

`Asn1Decoder::BuildAsn1Node` guards incomplete contents with
`offset + dataLen > end_` — adding two `uint32_t`s. `5 + 0xFFFFFFFF` wraps
to `4`, the check passes, and
`vector(begin()+offset, begin()+offset+dataLen)` requests a ~4GiB range →
**`std::bad_alloc`** instead of `nullptr`. Same-file sibling ctor
(`asn1_decoder.cpp:29`) already does `offset > (UINT32_MAX - decodeLen)`
before adding. Confirmed and fixed by developers (`DTS2026090326272`).

Callers treat `nullptr` as parse failure (`Asn1NextNode` /
`EsimFile::Asn1ParseResponse`).

## Vulnerable Code

`utils/codec/src/asn1_decoder.cpp` (106–109):

```cpp
if (offset + dataLen > end_) {
    return nullptr;
}
std::vector<uint8_t> byteStream(srcData_.begin() + offset, srcData_.begin() + offset + dataLen);
```

`offset` and `dataLen` are `uint32_t`. The add wraps at 2³².

Witness: `src={0x84,0xFF,0xFF,0xFF,0xFF}` — long-form length `0xFFFFFFFF`,
then `offset = 5`. `5 + 0xFFFFFFFF == 4`; `4 > end_` (`5`) is false.

Public path: `Asn1NextNode` on `{0x04, 0x84, 0xFF, 0xFF, 0xFF, 0xFF}`.

## Trigger Conditions

1. Untrusted eUICC/ASN.1 bytes with a 4-byte contents length of
   `0xFFFFFFFF` (long-form `0x84 FF FF FF FF`).
2. Wrapped `offset + dataLen` ≤ `end_` passes the guard.
3. `vector` over ~4GiB → `std::bad_alloc` (not `nullptr`).

Honest limit: well-formed decoder walks usually keep declared length
in-window. The hole is the guard, not a proven field PDU that already
carries `0xFFFFFFFF`.

## Impact

- `std::bad_alloc` or a ~4GiB allocation on a public parse path.
- High — process crash/DoS; not a wrong node on a valid TLV.

| Witness | Input | Expected | Actual |
|---|---|---|---|
| wrap | `src={0x84,0xFF,0xFF,0xFF,0xFF}`, `offset=0`, `tag=0x04` | `nullptr` | **`std::bad_alloc`** |
| in-range | short-form length that fits the window | node | node |
| incomplete, no wrap | claimed 10, have 3 | `nullptr` | `nullptr` |

## How PBT Detected This

`pbt-native/build_asn1_node_pbt_test` — links the REAL `asn1_decoder.cpp`
(not a model). Oracle: incomplete definite-length contents → `nullptr`.

| `PositionAdvancesPastPayload` / `TrailingBytesDoNotAffectPayload` | PASS |

| `FourByteAllFfLengthReturnsNull` | **FAIL** `std::bad_alloc` |

```bash
cmake -B pbt-native/build pbt-native
cmake --build pbt-native/build -j --target build_asn1_node_pbt_test
./pbt-native/build/build_asn1_node_pbt_test \
  --gtest_filter='*FourByteAllFfLengthReturnsNull*'
```

## Suggested Fix

Subtract, don't add — same shape as `asn1_decoder.cpp:29`:

```diff
-    if (offset + dataLen > end_) {
+    if (offset > end_ || dataLen > end_ - offset) {
         TELEPHONY_LOGE("Incomplete data at position: offset=%{public}u, dataLen=%{public}u, leftLength=%{public}u.",
             offset, dataLen, (end_ - offset));
         return nullptr;
     }
```

After fix: `{0x84,0xFF,0xFF,0xFF,0xFF}` → `nullptr`, no alloc; in-range /
incomplete no-wrap unchanged.
