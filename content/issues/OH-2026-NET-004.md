## Summary

`IpParamParser::RfindIp6` scans IPv6 bytes downward with
`for (uint32_t i = endBytes; i >= startBytes; --i)`. On a **miss** with
`startBit < 8` (`startBytes == 0`), `--i` past 0 wraps to `UINT_MAX` →
**infinite loop** and `s6_addr[UINT_MAX]` **OOB**.

Call chain: `BitmapManager::InsertIp6SegBitmap` (`MULTIPLE_IP`) →
`GetIp6AndMask` → `RfindIp6(startBit = prefixlen, …)`. Can hang/crash netsys
while expanding a wide IPv6 netfirewall range. Not every rule: needs
`prefixlen < 8` **and** a miss for the sought bit value. Same file already uses
**signed** downward indices elsewhere. Confirmed and fixed by developers
(`DTS2026072750511`).

## Vulnerable Code

`services/netmanagernative/bpf/src/bitmap_manager.cpp` — `RfindIp6` (~566):

```cpp
uint32_t startBytes = startBit / BIT_PER_BYTE;
// …
for (uint32_t i = endBytes; i >= startBytes; --i) {
    // scan s6_addr[i] for bit == value
}
// miss with startBytes == 0: after i==0 body, --i → UINT_MAX
// i >= 0 forever → hang; s6_addr[UINT_MAX] → OOB
```

`GetIp6AndMask` sets `prefixlen = GetIp6Prefixlen(start, end)` then calls e.g.:

```cpp
off = RfindIp6(addr6Start, prefixlen, IPV6_BIT_COUNT - 1, 1);
// and later RfindIp6(..., prefixlen, off, 0) / off-1
```

Ranges whose first differing bit is in **byte 0** have `prefixlen < 8` →
`startBytes == 0`. A full miss on that call hits the underflow.

Root cause: unsigned countdown never makes `i < startBytes` when
`startBytes == 0`.

## Trigger Conditions

1. `MULTIPLE_IP` IPv6 path expands a range with `prefixlen < 8` (first differ
   in byte 0).
2. `RfindIp6` is called with `startBit < 8` and the sought bit value is
   **absent** in `[startBit, endBit]`.
3. After scanning `i == 0`, `--i` → `UINT_MAX`; loop never exits; OOB index.

Unaffected: `prefixlen ≥ 8`; hit before underflow; `SINGLE_IP` path (does not
call `GetIp6AndMask`).

## Impact

| Path | Result |
|------|--------|
| `MULTIPLE_IP` IPv6 + `prefixlen < 8` + Rfind **miss** | Hang / OOB during `GetIp6AndMask` → rule install fails or stalls netsys |
| `prefixlen ≥ 8` | Loop stops when `i` drops below `startBytes` — OK |
| Hit before underflow | Returns early — OK |
| `SINGLE_IP` path | Unaffected |

Honest limits:
- Not every IPv6 firewall rule; needs range expand + early prefix + miss.
- Privilege to install netfirewall rules is typically not untrusted-app open;
  still a real service hang on bad/wide ranges.
- Medium: hang/OOB on netsys path, not unauthenticated RCE.

## Minimal Counterexample

| Case | Input | Expected | Actual |
|------|-------|----------|--------|
| all-zero, search 1 from bit 0 | `::`, start=0, end=127, value=1 | return 128 | **hang/OOB** |
| all-ones, search 0 from bit 0 | `ffff…`, start=0, end=127, value=0 | return 128 | **hang/OOB** |
| single-byte miss | `::`, start=0, end=0, value=1 | return 128 | **hang/OOB** |
| miss with `startBit ≥ 8` | `::`, start=8, end=15, value=1 | return 128 | **OK** |
| hit in byte 0 | has a 1-bit in range from 0 | bit index | **OK** |

## Suggested Fix

Match signed downward loops already in-file (`FindIp6` / `GetIp6Prefixlen`):

```cpp
for (int32_t i = static_cast<int32_t>(endBytes);
     i >= static_cast<int32_t>(startBytes); --i) {
    // same body; use s6_addr[static_cast<size_t>(i)]
}
```

Or, unsigned-safe: after the inner scan, `if (i == startBytes) break;` before
`--i`. After fix: hang props → PASS; startBit≥8 / hit props stay PASS.
