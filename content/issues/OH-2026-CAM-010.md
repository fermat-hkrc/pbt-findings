## Summary

`HCaptureSession::QueryZoomPerformance` walks
`OHOS_STATUS_CAMERA_ZOOM_PERFORMANCE` as variable-length TLV
`(sceneMode, zoomPointsNum, point×3…)*`. It reads `ui32[i+1]` as `num` then
`ui32[i+2 … i+1+3*num]` with **no** remaining-length check → heap **OOB** /
over-advance on a short or lying-`num` blob. Downstream
`GetCrossZoomAndTime` also OOB-reads if the filled vector length is not a
multiple of 3.

Not High: well-formed TLV OK. Orthogonal to fixed step-3 zoom triples and
moon FOV look-ahead. Confirmed and fixed by developers (`DTS2026080813827`).

## Vulnerable Code

`services/camera_service/src/hcapture_session.cpp` —
`QueryZoomPerformance` (~2008–2022) and `GetCrossZoomAndTime` (~2062–2068):

```cpp
for (int i = 0; i < static_cast<int>(zoomItem.count);) {
    int sceneMode = static_cast<int>(zoomItem.data.ui32[i]);
    int zoomPointsNum = static_cast<int>(zoomItem.data.ui32[i + 1]); // need i+1 < count
    if (operationMode == sceneMode) {
        for (int j = 0; j < dataLenPerPoint * zoomPointsNum; j++) {
            crossZoomAndTime.push_back(
                zoomItem.data.ui32[i + headLenPerMode + j]); // need i+2+j < count
        }
        break;
    } else {
        i = i + 1 + zoomPointsNum * dataLenPerPoint + 1; // unchecked num
    }
}

// GetCrossZoomAndTime — stride 3, no tail guard
for (int i = 0; i < (int)crossZoomAndTime.size(); i = i + 3) {
    crossTime.push_back({crossZoomAndTime[i + 1], crossZoomAndTime[i + 2]});
}
```

Three walk defects: header look-ahead, payload trust of `num`, skip
arithmetic (and `uint32→int` `num` can be negative / huge). Downstream
repeats the pattern on the output vector.

## Trigger Conditions

1. HAL / status `OHOS_STATUS_CAMERA_ZOOM_PERFORMANCE` is short vs claimed
   `3*num`, or `num` has the high bit set.
2. Smooth-zoom path calls `QueryFpsAndZoomRatio` → `QueryZoomPerformance`.
3. Header `ui32[i+1]`, payload, or skip advance reads / jumps past `count`;
   or filled vector `% 3 != 0` into `GetCrossZoomAndTime`.

## Impact

- Heap OOB while building cross-zoom performance points for live-session
  smooth zoom.
- Medium: well-formed tables unaffected; field hit needs bad HAL/status
  metadata. Not app-crafted input.
- One validation helper hardens both functions.

## Minimal Counterexample

| blob / state | Production |
|--------------|------------|
| well-formed matching mode | OK |
| `count == 1` (`{mode}`) | **OOB** on `ui32[i+1]` |
| `count == 2`, `num = 1` | **OOB** on first payload word |
| lying `3*num` vs remaining | **OOB** in inner `j` loop |
| `num` high bit set → negative `int` | backward `i` / **OOB** |
| filled size `% 3 != 0` | **OOB** in `GetCrossZoomAndTime` |

## Suggested Fix

Bound every stage and keep `num` unsigned vs remaining length:

```cpp
if (i + 1 >= static_cast<int>(zoomItem.count)) break;
uint32_t zoomPointsNumU = zoomItem.data.ui32[i + 1];
if (zoomPointsNumU > static_cast<uint32_t>((zoomItem.count - i - 2) / 3)) {
    break;  // truncated / lying num
}
int groupSpan = 2 + 3 * static_cast<int>(zoomPointsNumU);
// match → copy groupSpan-2 payload words; else i += groupSpan
```

`GetCrossZoomAndTime`: `for (i = 0; i + 2 < size; i += 3)`.

After fix: short/lying-`num` props PASS; well-formed stay PASS.
