## Summary

`InterfaceManager::GetMtu` `read()`s `/sys/class/net/<if>/mtu` and passes the
buffer to `StrToInt`. Kernel sysfs attributes are text lines (`"1500\n"`).
After `21584d87f` (`DTS20260717048` / `OH-2026-NET-009`), `StrToInt` is
full-consume `from_chars`, so leftover `\n` → `defaultErr` (`-1`) on every
healthy iface. Same sentinel as open/read fail.

Old `strtol` did not check `*pEnd`, so leftover `\n` happened to work. Helper
change made the missing strip in `GetMtu` visible. Do **not** weaken
`StrToInt`; the caller owns “sysfs line → int.”

Confirmed and fixed under `DTS2026083109843` (internal system: strip `\n`/`\r`
in `GetMtu` before `StrToInt`). Distinct from the octal helper tickets
(`OH-2026-NET-008` / `OH-2026-NET-009`).

## Vulnerable Code

`interface_manager.cpp` `GetMtu`:

```cpp
char originMtuValue[MAX_MTU_LEN] = {0};
int nread = read(fd, originMtuValue, (sizeof(char) * (MAX_MTU_LEN - 1)));
// ...
mtu = StrToInt(originMtuValue);  // buffer is "1500\n"
```

Call chain: `NetsysController::GetInterfaceMtu` → IPC `NETSYS_INTERFACE_GET_MTU`
→ `NetsysNativeService::GetInterfaceMtu` → `NetManagerNative::GetInterfaceMtu`
→ `GetMtu`.

Sibling `TrafficManager::GetInterfaceTrafficByType` reads the same sysfs tree
but uses `atol` (stops at `\n`). `SetMtu` is ioctl, not this path.

## Trigger Conditions

Any live `/sys/class/net/<if>/mtu` (always `"<digits>\n"`). No special
configuration. Pre-`21584d87f` devices looked OK.

## Impact

Medium — entire success path of shipped IPC `GetInterfaceMtu` returns `-1`.
Callers cannot tell “no iface” from “parse choked on newline.” Not High: no
crash / UB / security.

Official `GetMtuTest002` accepts `ret == -1 || ret == 1500`, so CI without
`eth0` hides the bug; after this defect, success is also `-1`.

## Minimal Counterexample

```
StrToInt("1500\n")   // -1; GetMtu should return 1500
StrToInt("1500")     // 1500
StrToInt("0\n")      // -1; GetMtu should return 0
GetMtu("wlan0")      // -1 on a box with mtu 1500
```

## How PBT Detected This

`pbt-native/str_to_int_pbt_test.cpp` `SysfsTrailingNewlineKeepsValue`:

```
∀ n ∈ [0, 65535].  StrToInt(to_string(n) + "\n") == n
```

FAIL is on the **helper leftover** (`StrToInt("0\n") == -1`). Product defect
is `GetMtu` not stripping. That leftover-reject on `StrToInt` must stay.

## Suggested Fix

Strip line endings in `GetMtu`. Leave `StrToInt` strict.

```cpp
originMtuValue[nread] = '\0';
while (nread > 0 && (originMtuValue[nread - 1] == '\n' || originMtuValue[nread - 1] == '\r')) {
    originMtuValue[--nread] = '\0';
}
mtu = StrToInt(originMtuValue);
```

`StrToInt(Trim(originMtuValue))` is equivalent (`CommonUtils::Trim` already
handles ` \t\n\r`).
