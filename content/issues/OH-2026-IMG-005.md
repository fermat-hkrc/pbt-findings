## Summary

`Matrix::SetConcat` scale/translate fast path (no rotate/skew) composes
translation as `tx1*tx2+tx1` instead of `sx1*tx2+tx1`. Full rotate path in the
same function uses correct `MulAddMul`. Wrong composed geometry (e.g. scale
then translate drops/mis-scales pan). Not High: wrong geometry, not crash;
needs TAS-only concat. Same class as fixed `Matrix::SetTranslate` axis-
identity (OH-2026-IMG-003). Confirmed and fixed by developers
(`DTS2026081126994`).

## Vulnerable Code

`frameworks/innerkitsimpl/converter/src/matrix.cpp` — `SetConcat` (~73):

```cpp
} else if (((static_cast<uint8_t>(aOperType) | static_cast<uint8_t>(bOperType)) & ROTATEORSKEW) == 0) {
    SetTranslateAndScale(fMat_[IMAGE_TRANSX] * m.fMat_[IMAGE_TRANSX] + fMat_[IMAGE_TRANSX],  // BUG
                         fMat_[IMAGE_TRANSY] * m.fMat_[IMAGE_TRANSY] + fMat_[IMAGE_TRANSY],  // BUG
                         fMat_[IMAGE_SCALEX] * m.fMat_[IMAGE_SCALEX],
                         fMat_[IMAGE_SCALEY] * m.fMat_[IMAGE_SCALEY]);
}

// Sibling (correct) — full path in same function ~92–94
fMat_[IMAGE_TRANSX] = static_cast<float>(
    MulAddMul(src.fMat_[IMAGE_SCALEX], m.fMat_[IMAGE_TRANSX],
              src.fMat_[IMAGE_SKEWX],  m.fMat_[IMAGE_TRANSY]) +
    src.fMat_[IMAGE_TRANSX]);
// skew=0 → SCALEX * peer TRANSX + TRANSX
```

Callers: `BasicTransformer::SetScaleParam` / `SetTranslateParam` /
`SetRotateParam` → `matrix_.SetConcat`; `PostProc::TranslatePixelMap` /
transform paths.

Root cause: TAS fast path multiplies translations by each other instead of
left scale × peer translation.

## Trigger Conditions

1. Both operands are scale/translate only (no rotate/skew) — TAS fast path.
2. `SetConcat` runs the product formula for translation.
3. Composed `(sx, tx)` is self-consistent under `ScaleXY` but geometrically
   wrong vs intended \(A \circ B\).

Identity-scale then translate may dodge via IDENTITY early-out; pure scale
then translate and double-translate hit the bug.

## Impact

- `BasicTransformer` scale(≠1) then translate: pan is **dropped or wrong**.
- Double translate: product instead of sum.
- Downstream `ScaleXY` / invert use stored `(sx,tx)` consistently → maps are
  self-consistent but **geometrically wrong** vs intended composition.
- Medium: wrong image geometry on common TAS concat; not crash.

## Minimal Counterexample

Compose scale+translate \(A \circ B\) (apply \(B\) then \(A\)):
\(t_x' = s_{xA}\,t_{xB} + t_{xA}\).

| Setup | Production `tx` | Expected |
|-------|-----------------|----------|
| `translate(2) ∘ translate(3)` | **8** (`2*3+2`) | **5** (add) |
| `scale(2) ∘ translate(5)` | **0** | **10** (`2*5`) |
| TAS(sx=2,tx=10) ∘ translate(5) | **60** | **20** (`2*5+10`) |
| Same affine via full path (rotate-tagged) | **20** | **20** |

Fast path ≠ full path on equivalent skew-free inputs.

## Suggested Fix

```diff
     } else if (((static_cast<uint8_t>(aOperType) | static_cast<uint8_t>(bOperType)) & ROTATEORSKEW) == 0) {
-        SetTranslateAndScale(fMat_[IMAGE_TRANSX] * m.fMat_[IMAGE_TRANSX] + fMat_[IMAGE_TRANSX],
-                             fMat_[IMAGE_TRANSY] * m.fMat_[IMAGE_TRANSY] + fMat_[IMAGE_TRANSY],
+        SetTranslateAndScale(fMat_[IMAGE_SCALEX] * m.fMat_[IMAGE_TRANSX] + fMat_[IMAGE_TRANSX],
+                             fMat_[IMAGE_SCALEY] * m.fMat_[IMAGE_TRANSY] + fMat_[IMAGE_TRANSY],
                              fMat_[IMAGE_SCALEX] * m.fMat_[IMAGE_SCALEX], fMat_[IMAGE_SCALEY] * m.fMat_[IMAGE_SCALEY]);
```

After fix: TAS concat matches full-path skew=0 reduction and point-map oracle.
