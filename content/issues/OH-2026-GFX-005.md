## Summary

`OHOS::Rosen::IsUtf8` encodes intent to reject UTF-8 surrogate halves via
`c == 0xED && (next & 0xA0) == 0xA0 → false`. On signed-`char` hosts (typical
OH/Linux ARM/x86), `uint32_t c = text[i]` sign-extends `0xED` to `0xFFFFFFED`,
so `c == 0xED` is never true. The sequence falls through to
`(c & 0xF0) == 0xE0` and is **accepted**. Encoded U+D800..U+DFFF passes the
“UTF-8” gate.

Wrong validation gate, not crash/OOB. Field impact is accept-then-convert
(replacement / odd glyphs). Confirmed and fixed by developers
(`DTS2026072513315`).

## Vulnerable Code

`rosen/modules/2d_graphics/src/drawing/utils/string_util.cpp` — `IsUtf8` (~28):

```cpp
uint32_t c = text[i];   // char may be signed → 0xED promotes to 0xFFFFFFED
if (c <= 0x7F) {
    n = 0;
} else if ((c & 0xE0) == 0xC0) {
    n = 1;
} else if (c == 0xED && i < (len - 1) && (text[i + 1] & 0xA0) == 0xA0) {
    return false;       // NEVER true when c is sign-extended (0xFFFFFFED != 0xED)
} else if ((c & 0xF0) == 0xE0) {
    n = 2;              // ED A0 80 still matches 3-byte lead via mask → accepted
}
```

Sibling copy (same bug): static `Drawing::IsUtf8` in
`rosen/modules/2d_graphics/include/text/common_utils.h`.

Callers of `string_util` `IsUtf8`: NDK typography pre-API18
(`drawing_text_typography.cpp`); NAPI paragraph builder
(`js_paragraph_builder.cpp`); font mgr (`skia_font_mgr.cpp`). API18+ NDK uses
`Str8ToStr16ByIcu` and skips this gate.

Root cause: signed `char` load into `uint32_t` kills the equality-based
surrogate guard. Need `static_cast<uint8_t>(text[i])`.

## Trigger Conditions

1. Host has signed `char` (typical OH/Linux ARM/x86).
2. Byte string contains UTF-8-encoded surrogate half, e.g. `ED A0 80` (U+D800).
3. Caller runs `IsUtf8` as pre-layout / pre-convert gate → returns **true**
   (fail-open for this class) → convert/append proceeds.

## Impact

| Path | Behavior with `ED A0 80` |
|------|--------------------------|
| NAPI `JsParagraphBuilder` | `IsUtf8` → true → convert/append proceeds |
| NDK typography **pre-API18** | same reject gate skipped → convert via `codecvt` |
| NDK typography **API18+** | does not call `IsUtf8`; `Str8ToStr16ByIcu` (illegal → U+FFFD) |
| Font mgr | may accept bad-labeled “UTF-8” font name bytes |

Honest limits:
- Not a crash / OOB / memory-safety bug.
- Not “all invalid UTF-8 accepted” — only this **equality-based** surrogate
  guard is dead; other rejects still work.
- SUT is already a loose structural acceptor (not full RFC 3629).
- Downstream often replaces or degrades glyphs; do not claim a specific ICU
  crash without a separate witness.
- Medium: wrong validation gate on live text paths.

## Minimal Counterexample

```
bytes: ED A0 80   // UTF-8 encoding of U+D800

Production (signed char): IsUtf8 → true
Expected (own guard live): IsUtf8 → false

// Host: char is signed; uint32_t c = (char)0xED → 0xFFFFFFED; c == 0xED is false
```

## How PBT Detected This

`pbt-native/is_utf8_pbt_test`:

| Test | Result |
|------|--------|
| `IsUtf8PBT.SurrogateEdA0Rejected` | **FAIL** (assert `!IsUtf8` expands to false) |
| Empty / ASCII / well-formed scalars / truncation rejects | PASS |

```bash
cmake -S pbt-native -B pbt-native/build -DCMAKE_BUILD_TYPE=Release
cmake --build pbt-native/build -j --target is_utf8_pbt_test
./pbt-native/build/is_utf8_pbt_test --gtest_filter='*Surrogate*'
```

## Suggested Fix

Cast through `uint8_t` on all byte loads used in class tests:

```cpp
uint32_t c = static_cast<uint8_t>(text[i]);
// …
} else if (c == 0xED && i < (len - 1) &&
           (static_cast<uint8_t>(text[i + 1]) & 0xA0) == 0xA0) {
    return false;
}
```

Apply the same `uint8_t` cast in the sibling `common_utils.h` copy (one ticket,
both sites). After fix: `SurrogateEdA0Rejected` → PASS; other props stay PASS.
