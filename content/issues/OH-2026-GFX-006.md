## Summary

`DrawingConfig::UpdateDrawingProperties` compares
`DrawingDisableFlag::COUNT` (42) to `gDrawingDisableFlagStr.size()` (41) and
early-returns on mismatch — so **no** `drawing.disable*` param is ever applied
and all flags stay `false`. The enum grew (`DISABLE_PARTICLE`) without a
matching string key (`"disableParticle"`).

Entire kill-switch surface is inert when `DRAWING_DISABLE_API` is compiled in.
Not a crash. Default product builds that omit the define strip
`UpdateDrawingProperties` / `IsDisabled` entirely. Confirmed and fixed by
developers (`DTS2026073129863`).

## Vulnerable Code

`rosen/modules/2d_graphics/src/drawing/config/DrawingConfig.cpp`:

```cpp
int flagCount = static_cast<int>(DrawingDisableFlag::COUNT);  // 42

std::vector<std::string> gDrawingDisableFlagStr = {
    "disablePoint", …, "disablePathEffect"
    // 41 entries — missing trailing enum DISABLE_PARTICLE
};

void UpdateDrawingProperties()
{
    if (flagCount != static_cast<int>(gDrawingDisableFlagStr.size())) { // 42 != 41
        LOGE("… inconsistent");
        return;  // always — never reads parameters
    }
    for (int i = 0; i < flagCount; i++) {
        gDrawingDisableFlags[i] = GetBoolParameter("drawing." + gDrawingDisableFlagStr[i], false);
    }
}
```

| Side | Count |
|------|--------|
| Enum values before `COUNT` | **42** (`DISABLE_POINT` … `DISABLE_PATH_EFFECT`, `DISABLE_PARTICLE`) |
| `gDrawingDisableFlagStr` | **41** (ends at `"disablePathEffect"`; **no** `"disableParticle"`) |

Consumers: `core_canvas.cpp` / `brush.cpp` / … gate draw ops with
`IsDisabled(...)` under `DRAWING_DISABLE_API`.

Root cause: enum grew without a matching string → `COUNT > str.size()`; guard
treats any mismatch as fatal for the whole update.

## Trigger Conditions

1. Build with `DRAWING_DISABLE_API` so `UpdateDrawingProperties` / `IsDisabled`
   exist.
2. Set any `drawing.disable*` syspara (e.g. `drawing.disablePoint=true`).
3. `UpdateDrawingProperties()` early-returns (42 ≠ 41); `IsDisabled(*)` stays
   false.

## Impact

| Path | Result |
|------|--------|
| Any `drawing.disable*` / intended runtime kill-switch | **Ignored** — flags stay default false |
| `IsDisabled(*)` at draw sites | Always “not disabled” via this update path |
| Only LOGE | Easy to miss |

Honest limits:
- Medium (Low–Medium): 100% no-op of a **debug/diagnostic** param surface when
  the API is built; not crash, not default draw path if `#ifdef` off.
- With the size bug even init never loads flags.
- Counts verified: enum before `COUNT` = **42**; string table = **41** (missing
  only `disableParticle`).

## Minimal Counterexample

| Step | Result |
|------|--------|
| Set `drawing.disablePoint=true` | param store true |
| `UpdateDrawingProperties()` | early `return` (42 ≠ 41) |
| `IsDisabled(DISABLE_POINT)` | **false** (expected true) |

```bash
cmake -S pbt-native -B pbt-native/build -DCMAKE_BUILD_TYPE=Release
cmake --build pbt-native/build -j --target drawingconfig_isdisabled_pbt_test
./pbt-native/build/drawingconfig_isdisabled_pbt_test --gtest_filter='*ParamSet*'
```

## Suggested Fix

Append the missing key in enum order (after path effect):

```cpp
    "disableBlender",
    "disablePathEffect",
    "disableParticle",   // DISABLE_PARTICLE — was missing
};
```

Verify `gDrawingDisableFlagStr.size() == 42`. After fix:
`ParamSetTrueThenUpdateDisablesFlag` → PASS for all `i`.

Optional harden: `static_assert` on sizes, or update only
`min(flagCount, str.size())` instead of aborting all flags.
