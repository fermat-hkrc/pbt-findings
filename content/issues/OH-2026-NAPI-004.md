## Summary

`napi_get_value_string_latin1` copies a JS string as Latin-1 into `buf`.
`bufsize` is the destination size **including** the NUL. Utf8 and utf16 in the
same file pass `bufsize - 1` into the writer, then store `'\0'` at
`buf[copied]`. Latin1 passes the **full** `bufsize`, so when the string is at
least `bufsize` bytes it writes `bufsize` payload bytes and then
`buf[bufsize] = '\0'` — one past the caller buffer. `*result` is also one too
large (the NUL is counted as payload). Confirmed and fixed under
`DTS2026082238400`.

## Vulnerable Code

`native_engine/native_api.cpp` `napi_get_value_string_latin1` (~805–810):

```cpp
} else if (LIKELY(bufsize != 0)) {
    uint32_t copied = stringVal->WriteLatin1WithoutSwitchState(vm, buf, bufsize);
    buf[copied] = '\0';
    if (result != nullptr) {
        *result = copied;
    }
}
```

`WriteLatin1WithoutSwitchState` writes `min(|s|, bufsize)` payload bytes and
does not add a NUL. Then `buf[copied] = '\0'` with `copied == bufsize` is out
of range.

Same-job siblings reserve the NUL (`native_api.cpp` utf8 ~838–841, utf16
~874–875):

```cpp
uint32_t copied = stringVal->WriteUtf8(vm, buf, bufsize - 1, true) - 1;
buf[copied] = '\0';

uint32_t copied = stringVal->WriteUtf16(vm, buf, bufsize - 1); // reserve "\0"
buf[copied] = '\0';
```

## Contract

Node-API: `bufsize` includes the terminator. On truncation, copy at most
`bufsize - 1` payload bytes. `*result` is bytes copied **excluding** the NUL.

`copied = min(|s|, bufsize - 1)`, `buf[copied] == '\0'`, and `buf[bufsize]` is
never written. Does not fire when `buf == nullptr` (length query) or when
`|s| < bufsize`.

## Minimal Counterexample

```cpp
char buf[1];
size_t n = 99;
// JS string "A" (or longer)
napi_get_value_string_latin1(env, js, buf, 1, &n);
// Expected: n == 0, buf[0] == '\0'
// Actual:   n == 1, buf[0] == 'A', buf[1] == '\0'  // OOB
```

`"hi"` / `bufsize == 2`: expected `{'h','\0'}` and `n == 1`; actual payload
fills both bytes and the NUL lands at index 2.

## How PBT Detected This

Harness: `pbt-native/get_value_string_latin1_pbt_test.cpp`. Canary byte at
`buf[bufsize]`. Oracle: `copied == min(|s|, bufsize - 1)` and canary unchanged.

| Property / regression | Result |
|---|---|
| Truncation + canary | FAIL |
| `BufsizeOneHoldsOnlyNul` (`"A"` / 1) | FAIL |
| `ExactFitBufsizeLeavesRoomForNul` | FAIL |

In-tree unit tests copy with `bufferSize + 1`, so they never pass
`bufsize == 1` or `bufsize == strlen` on a non-empty string.

## Impact

One-byte write past the caller buffer on the public Latin-1 truncation path,
whenever the Latin-1 length is **≥ `bufsize`**. That includes a fixed
`char buf[N]` with a longer JS string, and `malloc(len)` + `bufsize == len`
(query-then-copy without `+1`). Not a guaranteed crash: the extra byte lands
immediately after the caller's buffer.

## Suggested Fix

Match utf8/utf16: reserve one byte for the NUL.

```cpp
uint32_t copied = stringVal->WriteLatin1WithoutSwitchState(vm, buf, bufsize - 1);
buf[copied] = '\0';
```

Witness `"A"` / `bufsize = 1`: `copied == 0`, `buf[0] == '\0'`, no write at
index 1.
